ルーティングとデータ取得

  • ⏱ 所要時間: 45分
  • 📊 難易度: 中級
  • 📋 前提知識: Lesson 1〜2, React の基礎

🎯 このレッスンで学ぶこと

  • App Router のファイルベースルーティングの仕組みを理解する
  • サーバーコンポーネントでのデータ取得パターンを実装する
  • ローディング UI とエラーハンドリングを適切に配置する

概要

このレッスンでは Next.js の App Router を使ったルーティングと、サーバーコンポーネントでの データ取得の基本パターンを学びます。app/ ディレクトリ配下のファイル構成が そのまま URL 構造に対応する点を確認しながら進めます。

ℹ️

Note

このレッスンは Node.js 20 以降がインストールされている前提で進めます。バージョンは node -v で確認してください。

手順

1

プロジェクトを作成する

まず新しい Next.js プロジェクトを作成します。ターミナルで以下のコマンドを実行してください。

Terminal 
$ npx create-next-app@latest my-app --typescript✔ Would you like to use ESLint?  … Yes✔ Would you like to use App Router?  … YesSuccess! Created my-app at ./my-app

✅ 確認ポイント

my-app ディレクトリが作成され、app/page.tsx が存在していることを確認してください。

2

一覧ページを実装する

app/posts/page.tsx を作成し、サーバーコンポーネントでデータを取得します。

TypeScript app/posts/page.tsx 
export default async function PostsPage() {
  const res = await fetch("https://api.example.com/posts", {
    next: { revalidate: 60 },
  });
  const posts: Post[] = await res.json();

  return (
    <ul>
      {posts.map((post) => (
        <li key={post.id}>{post.title}</li>
      ))}
    </ul>
  );
}

次に、変更前のコードとの差分を確認しておきましょう。

Diff app/posts/page.tsx 
- const posts = await getStaticPosts();+ const res = await fetch("https://api.example.com/posts", {+   next: { revalidate: 60 },+ });+ const posts: Post[] = await res.json();
💡

Tip

revalidate を指定すると ISR（Incremental Static Regeneration）としてキャッシュされ、指定秒数ごとに再生成されます。

✅ 確認ポイント

npm run dev を実行し、/posts にアクセスして一覧が表示されることを確認してください。

3

ローディングとエラーの状態を扱う

App Router では loading.tsx と error.tsx を同じディレクトリに置くだけで、状態ごとの UI を自動的に切り替えられます。

⚠️

Warning

error.tsx は Client Component である必要があります。ファイルの先頭に "use client" を忘れずに記述してください。

🚫

Danger

本番環境で fetch の cache: "no-store" を多用すると、意図せず全ページが動的レンダリングになりサーバー負荷が急増します。挙動を必ず確認してください。

解答例を見る
TypeScript app/posts/error.tsx 
"use client";

export default function Error({ error, reset }: {
  error: Error;
  reset: () => void;
}) {
  return (
    <div>
      <p>読み込みに失敗しました: {error.message}</p>
      <button onClick={() => reset()}>再試行</button>
    </div>
  );
}

✅ 確認ポイント

意図的に API URL を間違えて、エラー画面と「再試行」ボタンが表示されることを確認してください。
