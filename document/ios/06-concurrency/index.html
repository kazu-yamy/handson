async/await と @MainActor

  • ⏱ 所要時間: 45分
  • 📊 難易度: 初級
  • 👤 対象: SwiftUI で一覧と詳細画面のアプリを作れ、次にデータの読み込みのような時間のかかる処理を画面を止めずに書きたい人
  • 📋 前提: 05 で List と NavigationStack を使った HandsonApp プロジェクトが手元にあること。@Observable の TodoStore を @Environment で注入する構成と、Swift Testing の @Test・#expect を知っていること
  • 🔗 前提となる項目: 05 List と NavigationStack

🎯 このレッスンで学ぶこと

  • async 関数を await で呼び、画面の表示と同時に .task で読み込みを始める
  • 同期のクロージャ（Button の action）から Task { } で非同期処理を始め、.refreshable を付ける
  • @MainActor の既定のもとで、@concurrent を使って処理をメインアクターの外で動かす。Sendable な値だけがアクターの境界を越えられることを知る
  • async let で 2 つの処理を並行に待ち、直列との所要時間の違いをテストで測る
  • タスクのキャンセルとエラーを区別して扱う
  • actor で、複数のタスクから安全に読み書きできるキャッシュを作る

概要

05 までの ToDo アプリは、起動時に決まったデータを持っていました。この項目では、データを「ネットワークから取ってくる」形に変えます。 通信の代わりに Task.sleep で 1 秒待ってから固定のデータを返す TodoRepository を作り、TodoStore がそこから読み込みます。 完成すると、起動直後に「読み込み中…」が表示されたあとで一覧が現れます。左上の「再読み込み」ボタンで読み込み直すことができ、一覧の下に「1 / 3 件完了」のような集計が表示されます。

async / await と .task → Task { } と .refreshable → @MainActor と @concurrent → async let → キャンセルとエラー → actor、の順に進めます。1 ステップで扱う概念は 1 つです。 途中で、つまずきやすい誤りを意図的に起こして、コンパイラのエラーを確かめます。 05 と同じく、Xcode の画面での操作と、同じ結果をターミナルで確かめるコマンドの両方を載せています。

ℹ️

使用バージョンと並行処理の設定

macOS 26.6.2 / Xcode 27.0 / Swift 6.4 / iPhone 17（iOS 27.0）のシミュレータは 05 と同じです。バージョンは執筆時点（2026年10月）のものです。

この項目の動作は、01 で確認したアプリターゲットの 2 つの設定に依存します。1 つは SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor で、アプリの型や関数は何も書かなければメインアクターに分離されます。 もう 1 つは SWIFT_APPROACHABLE_CONCURRENCY = YES です。この設定により、コンパイラに NonisolatedNonsendingByDefault などの機能が渡されます（ビルド時のコンパイルコマンドで確認）。その効果はステップ 4 で確かめます。

2

async 関数を await で呼び、.task で読み込む

まず、データを取ってくる役の TodoRepository を作ります。Models フォルダに Swift ファイル TodoRepository.swift を追加します。Xcode では Models を右クリックし、New File from Template… で iOS > Swift File を選びます（Targets は HandsonApp）。 中身を次の内容にします。

Swift HandsonApp/Models/TodoRepository.swift 
import Foundation

struct TodoRepository {
    // ネットワークの代わりに 1 秒待って固定のデータを返す
    func fetchAll() async throws -> [TodoItem] {
        try await Task.sleep(for: .seconds(1))
        return [
            TodoItem(title: "牛乳を買う", priority: .high),
            TodoItem(title: "メールを返す", priority: .low, status: .done(Date())),
            TodoItem(title: "SwiftUI を勉強する"),
        ]
    }
}
  • func fetchAll() async throws: async は「途中で一時停止することがある関数」の印です。throws と並べて書きます。
  • try await Task.sleep(for: .seconds(1)): 1 秒待ちます。ネットワーク通信の代わりで、07 で URLSession に置き換えます。Task.sleep(for:) 自体が async throws なので、呼ぶ側に try await が要ります。
  • 待っている間、スレッドは止まりません。await の地点で処理が一時停止し、その間メインスレッドは画面の更新などの別の仕事をします。

@MainActor と @concurrent で、集計をメインアクターの外で動かす

このプロジェクトでは、アプリの型や関数は既定で @MainActor（メインアクターに分離）です。TodoRepository と TodoStore は、何も書かなくてもメインスレッドで動きます。 async 関数にしただけでは、別のスレッドでは動きません。Task.sleep で一時停止している間はメインアクターが空くので、画面は止まりません。しかし、待ち時間ではなく重い計算をメインアクターで行うと、その間は画面が止まります。

そこで、一覧の完了件数を数える「集計」を、メインアクターの外で動かしてみます。Models フォルダに TodoSummary.swift を追加します。

Swift HandsonApp/Models/TodoSummary.swift 
import Foundation

// async の中では Thread.isMainThread を直接呼べないので、同期関数に切り出す
nonisolated func runningOnMainThread() -> Bool {
    Thread.isMainThread
}

nonisolated struct TodoSummary {
    let doneCount: Int
    let totalCount: Int
    let ranOnMainThread: Bool

    var text: String {
        "\(doneCount) / \(totalCount) 件完了"
    }
}

struct TodoSummarizer {
    // @concurrent: メインアクターの外（グローバルな並行プール）で実行する
    @concurrent
    func summarize(_ items: [TodoItem]) async -> TodoSummary {
        try? await Task.sleep(for: .milliseconds(300))  // 重い計算の代わり
        let done = items.filter { $0.isDone }.count
        return TodoSummary(
            doneCount: done,
            totalCount: items.count,
            ranOnMainThread: runningOnMainThread()
        )
    }
}
  • @concurrent: この async 関数を、メインアクターの外（グローバルな並行の実行環境）で動かします。@concurrent は async 関数にだけ付けられます。
  • try? await Task.sleep(for: .milliseconds(300)): 重い計算の代わりに 0.3 秒待ちます。
  • ranOnMainThread: 集計がメインスレッドで動いたかどうかを記録し、テストで確かめるためのプロパティです。
  • nonisolated func runningOnMainThread(): Thread.isMainThread を async 関数の中で直接呼ぶと、error: class property 'isMainThread' is unavailable from asynchronous contexts で始まるエラーになります。そのため、同期関数に切り出しています。
  • nonisolated struct TodoSummary: nonisolated は「メインアクターに分離しない」指定です。@concurrent の関数の中で作るので付けています。

cancel() はキャンセルを「依頼する」だけ

実際に止まるのは、Task.sleep のようにキャンセルに対応した await の地点です。キャンセルを確かめない計算のループは、cancel() しても最後まで走ります。そうした処理では、途中に try Task.checkCancellation() を挟みます。

.task で始めた処理は、View が画面から消えると自動でキャンセルされます。執筆時に、.task の中で 10 秒の Task.sleep を待つ View を表示してから取り除き、Task.sleep が CancellationError を投げることを確かめました。 自分で Task { } を作った場合とは違い、cancel() を呼ぶ必要はありません。

actor で読み込み結果をキャッシュする

一度取得した ToDo を覚えておき、次の取得ではすぐに返すキャッシュを作ります。キャッシュは複数のタスクから同時に読み書きされる可能性があるので、actor にします。Models フォルダに TodoCache.swift を追加します。

Swift HandsonApp/Models/TodoCache.swift 
import Foundation

actor TodoCache {
    private var storage: [String: [TodoItem]] = [:]

    func value(for key: String) -> [TodoItem]? {
        storage[key]
    }

    func store(_ items: [TodoItem], for key: String) {
        storage[key] = items
    }
}

actor は、中の状態に同時に 1 つの処理しか触れない参照型です。storage への読み書きは自動で順番に並べられるので、クラスに自前のロックを書く必要はありません。 TodoItem は Sendable なので、アクターに出し入れできます。

TodoRepository の fetchAll から使います。useCache が true でキャッシュがあれば、待たずにそれを返します。

つまずきポイント

💡

Thread.isMainThread が使えない

async 関数の中で Thread.isMainThread を呼ぶと、error: class property 'isMainThread' is unavailable from asynchronous contexts で始まるエラーになります。TodoSummary.swift の runningOnMainThread() のように、同期関数に切り出してください。メインアクターであることを確かめるだけなら、MainActor.assertIsolated() を使います。

💡

@concurrent を付けたら、メインアクターのプロパティに触れなくなった

@concurrent の関数はメインアクターの外で動くので、メインアクターに分離された型（既定ではアプリの全ての型）のプロパティに触れません。渡す値の型に nonisolated を付けるか、ストアではなく値を引数で渡してください。

💡

テストの実行に時間がかかる

この項目のテストは、Task.sleep で実際に待つので、全体で約 6 秒かかります。テストが失敗すると、05 と同じく xcodebuild の終了まで長く待たされることがあります。

まとめ

async 関数と await でデータの読み込みを書き、.task で画面の表示時に始めました。同期の Button の action からは Task { } で非同期の処理を始め、.refreshable も付けました。 アプリの型が既定で @MainActor のプロジェクトでは、nonisolated だけではメインアクターの外に出ず、@concurrent が必要なことを確かめました。境界を越える値は Sendable でなければならないことも確かめました。 さらに、async let で 2 つの取得を並行に待ち、キャンセルとエラーを区別し、actor でキャッシュを作りました。 次の項目では、TodoRepository の Task.sleep を URLSession による実際の通信に置き換え、Codable で JSON を読み込みます。
