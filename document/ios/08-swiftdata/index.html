SwiftData

  • ⏱ 所要時間: 60分
  • 📊 難易度: 初級
  • 👤 対象: Web API から読み込むアプリを作れ、次にデータを端末に保存してアプリを閉じても残るようにしたい人
  • 📋 前提: 07 で API と通信する HandsonApp プロジェクトが手元にあること。@Observable・@Bindable・@Environment・Swift Testing の @Test / #expect を使ったことがあること
  • 🔗 前提となる項目: 07 URLSession と Codable

🎯 このレッスンで学ぶこと

  • @Model で保存するクラスを定義し、.modelContainer でアプリに保存先を用意する
  • @Query で保存したデータを一覧に表示する
  • modelContext で追加・更新・削除し、save() を明示的に呼んで確実に保存する
  • #Predicate と @Query(filter:sort:) で絞り込みと並び替えをする
  • メモリ上だけのコンテナで、ファイルを作らないテストを書く
  • （発展）API から取り込み、@Attribute(.unique) で重複を防ぐ
  • .modelContainer の付け忘れと、保存できない型のプロパティで何が起きるかを確かめる

概要

07 の ToDo アプリは、一覧をメモリ上の TodoStore に持っていました。そのため、アプリを終了すると追加したタスクは消えます。この項目では、一覧を SwiftData で端末に保存し、アプリを終了しても残るようにします。 完成すると、追加・完了の切り替え・削除がそのまま保存され、再起動しても同じ一覧が表示されます。「完了も表示」をオフにすると、保存されたデータを未完了だけに絞って表示します。

@Model でモデルを作る → @Query で表示 → modelContext で追加・更新・削除 → #Predicate で絞り込み → メモリ上のコンテナでテスト、の順に進めます。1 ステップで扱う概念は 1 つです。 ステップ 7 は 07 の API と組み合わせる発展の内容なので、時間が足りなければ飛ばしても、ステップ 8 はそのまま進められます。07 と同じく、Xcode の画面での操作と、同じ結果をターミナルで確かめるコマンドの両方を載せています。

ℹ️

使用バージョンと並行処理の設定

macOS 26.6.2 / Xcode 27.0 / Swift 6.4 / iPhone 17（iOS 27.0）のシミュレータは 07 と同じです。バージョンは執筆時点（2026年10月）のものです。

2

@Model で保存するクラスを作り、.modelContainer を付ける

SwiftData で保存する ToDo の型を作ります。Models フォルダに Swift ファイル TodoRecord.swift を追加します（Xcode では Models を右クリックし、New File from Template… で iOS > Swift File、Targets は HandsonApp）。 中身を次の内容にします。

Swift HandsonApp/Models/TodoRecord.swift 
import Foundation
import SwiftData

@Model
final class TodoRecord {
    var title: String
    var priority: Priority
    var isDone: Bool
    var completedAt: Date?
    var createdAt: Date

    init(title: String, priority: Priority = .medium, createdAt: Date = .now) {
        self.title = title
        self.priority = priority
        self.isDone = false
        self.completedAt = nil
        self.createdAt = createdAt
    }

    // 完了と未完了を切り替える。完了にした時刻も一緒に記録する
    func toggle() {
        isDone.toggle()
        completedAt = isDone ? .now : nil
    }
}
  • import SwiftData: SwiftData のフレームワークを読み込みます。忘れると error: unknown attribute 'Model' になります。
  • @Model: このクラスを SwiftData で保存できるモデルにするマクロです。付けるだけで PersistentModel と Observable に準拠します。@Observable を別に書かなくても、プロパティを変えると SwiftUI の画面が更新されます。
  • @Model は クラスにしか付けられません。struct に付けると error: '@Model' cannot be applied to struct type 'TodoRecord' (from macro 'Model') になります。継承しないので final にします。
  • 保存するプロパティは、String・Bool・Date・Date? のような Codable な型にします。Priority は 02 で作った enum です（このあと Codable を付けます）。
  • id は書きません。保存した 1 件は SwiftData が識別子（persistentModelID）を持つからです。
  • toggle(): 完了と未完了を切り替え、完了にした時刻を completedAt に記録します。

⚠️

Codable でない型は保存できない

Codable を付けずにビルドすると、次のエラーになります。

Terminal 
macro expansion @_PersistedProperty:4:23: error: no exact matches in call to instance method 'setValue'macro expansion @_PersistedProperty:9:21: error: no exact matches in call to instance method 'getValue'macro expansion @_PersistedProperty:13:18: error: no exact matches in call to instance method 'setValue'…** BUILD FAILED **

@Model は、各プロパティに @_PersistedProperty というマクロを展開します。保存できない型のプロパティがあると、その展開されたコードの中で getValue / setValue の不一致としてエラーが出ます。エラーの位置がマクロの中なので、どのプロパティが原因かは分かりにくくなります。

ℹ️

完了状態を Status ではなく isDone と completedAt で持つ理由

02 で作った Status（.todo / .done(Date) の関連値付き enum）も、Codable を付ければ保存して読み戻せました。 ただし、ステップ 5 で使う #Predicate の中では enum の case と比べられません。#Predicate { $0.status == Status.todo } と書くと error: key path cannot refer to enum case 'todo' になります。 そこで、絞り込みに使う完了状態は Bool の isDone と Date? の completedAt で持ちます。

3

@Query で一覧を表示する

画面の一覧を、TodoStore（メモリ）から SwiftData に切り替えます。まず、行と詳細の View を TodoItem ではなく TodoRecord を受け取る形にします。Views/TodoRow.swift を次の内容に置き換えます。

Swift HandsonApp/Views/TodoRow.swift 
import SwiftData
import SwiftUI

struct TodoRow: View {
    // @Model のオブジェクトはクラスなので、@Binding ではなく @Bindable で受け取る
    @Bindable var record: TodoRecord

    var body: some View {
        HStack(spacing: 12) {
            // 完了の切り替えはアイコンのボタンだけに任せる（行のタップは NavigationLink に譲る）
            Button {
                record.toggle()
            } label: {
                if record.isDone {
                    Image(systemName: "checkmark.circle.fill")
                        .foregroundStyle(.green)
                } else {
                    Image(systemName: "circle")
                        .foregroundStyle(.secondary)
                }
            }
            .buttonStyle(.borderless)
            .accessibilityLabel(record.isDone ? "未完了に戻す" : "完了にする")

            Text(record.title)
                .strikethrough(record.isDone)

            Spacer()

            Text(record.priority.label)
                .font(.caption)
                .padding(.horizontal, 8)
                .padding(.vertical, 2)
                .background(.quaternary, in: Capsule())
        }
    }
}
  • @Bindable var record: TodoRecord: 07 までは struct の TodoItem を @Binding で受け取っていました。@Model のオブジェクトはクラスで Observable なので、04 の TodoStore と同じく @Bindable で受け取ります。
  • record.toggle() はオブジェクトのプロパティを直接変えます。@Model のオブジェクトは変更を SwiftData が追跡します。
  • Preview は TodoItem を使っていたので削除しました。

ContentView.swift を次の内容に置き換えます。この時点では、保存されたデータを表示するだけです。

Swift HandsonApp/ContentView.swift 
//
//  ContentView.swift
//  HandsonApp
//

import SwiftData
import SwiftUI

struct ContentView: View {
    // SwiftData から createdAt の古い順に読む。データが変わると画面が自動で更新される
    @Query(sort: \TodoRecord.createdAt) private var items: [TodoRecord]

    @State private var tapCount = 0
    @State private var showsDone = true

    var body: some View {
        NavigationStack {
            List {
                Section {
                    Button("タップ回数: \(tapCount)") {
                        tapCount += 1
                    }
                    .buttonStyle(.borderless)

                    Toggle("完了も表示", isOn: $showsDone)
                }

                Section("Todo") {
                    if items.isEmpty {
                        ContentUnavailableView("ToDo はまだありません", systemImage: "checklist")
                    }
                    ForEach(items) { item in
                        if showsDone || !item.isDone {
                            NavigationLink(value: item) {
                                TodoRow(record: item)
                            }
                        }
                    }
                }
            }
            .navigationDestination(for: TodoRecord.self) { item in
                TodoDetailView(record: item)
            }
            .navigationTitle("ToDo")
        }
    }
}
  • @Query: SwiftData から @Model のオブジェクトの配列を読むプロパティラッパーです。データが追加・変更・削除されると、View が自動で再描画されます。sort: に KeyPath を渡すと、その値の昇順に並びます。
  • @Query は、環境の modelContext（ステップ 2 の .modelContainer が入れたもの）から読みます。
  • NavigationLink(value: item) と .navigationDestination(for: TodoRecord.self): @Model のクラスは Hashable を満たすので、追加の準拠なしにそのまま値として渡せます。
  • ContentUnavailableView: データが無いときの表示です。アイコンと文言を中央に並べます。

⚠️

save() を呼ばないと、直後の終了で消える（実測）

ModelContext には自動保存（autosaveEnabled）があり、.modelContainer の引数 isAutosaveEnabled の既定値は true です。公式ドキュメントでは「特定のイベントが起きたときに、保存していない変更を自動で保存する」と説明されています。つまり、変更した瞬間に保存されるわけではありません。

執筆時に UI テストで確かめました。「牛乳を買う」「メールを返す」を追加し、1 件目を完了にしたら、待たずにアプリを終了して再起動します。 3 か所の save() をコメントアウトした状態では、再起動後に、追加した 2 件とも残りませんでした。save() を呼ぶ状態では、2 件とも残り、完了も 1 件のままでした。 そのため、完成コードでは追加・完了の切り替え・削除のたびに try? modelContext.save() を呼んでいます。

#Predicate と @Query(filter:sort:) で絞り込む

「完了も表示」をオフにしたときの絞り込みを、View の if ではなく SwiftData の読み込みの条件で行います。 @Query の条件はプロパティの初期値として書くので、同じ View の @State（showsDone）を参照できません。そこで、一覧のブロックを子 View に切り出し、init の引数で条件を受け取ります。 Views フォルダに TodoSection.swift を追加し、次の内容にします（Targets は HandsonApp）。

Swift HandsonApp/Views/TodoSection.swift 
import SwiftData
import SwiftUI

// Todo の一覧セクション。@Query の条件は init で組み立てる
// （@Query の filter は View の State を直接参照できないため、子 View に引数として渡す）
struct TodoSection: View {
    @Query private var items: [TodoRecord]
    @Environment(\.modelContext) private var modelContext

    init(showsDone: Bool) {
        // 「完了も表示」がオフなら未完了だけに絞る。どちらも作成日時の古い順
        let predicate = #Predicate<TodoRecord> { showsDone || !$0.isDone }
        _items = Query(filter: predicate, sort: \.createdAt)
    }

    var body: some View {
        Section("Todo") {
            if items.isEmpty {
                ContentUnavailableView("ToDo はまだありません", systemImage: "checklist")
            }
            ForEach(items) { item in
                NavigationLink(value: item) {
                    TodoRow(record: item)
                }
            }
            .onDelete { offsets in
                for index in offsets {
                    modelContext.delete(items[index])
                }
                // 自動保存を待たず、削除の直後に保存する
                try? modelContext.save()
            }
        }
    }
}
  • #Predicate<TodoRecord> { showsDone || !$0.isDone }: 読み込む条件を書くマクロです。$0 が 1 件の TodoRecord で、true になるものだけを読みます。showsDone が true なら全件、false なら isDone が false のものだけです。
  • _items = Query(filter: predicate, sort: \.createdAt): _items は @Query のプロパティラッパーそのものです。init で条件付きの Query を作って入れ替えます。
  • 親の showsDone が変わると TodoSection が新しい引数で作り直され、新しい条件で読み直します。
  • 削除の .onDelete も、items を持つこの View に移します。

SwiftData を使うコードもユニットテストで確かめます。テストでは、ファイルに保存しない「メモリ上だけ」のコンテナを使います。HandsonAppTests フォルダに TodoRecordTests.swift を追加し、次の内容にします（Targets は HandsonAppTests）。

Swift HandsonAppTests/TodoRecordTests.swift 
import Foundation
import SwiftData
import Testing
@testable import HandsonApp

@MainActor
struct TodoRecordTests {
    // テストごとにメモリ上だけのコンテナを作る。ファイルを作らないので互いに影響しない
    // ModelContext はコンテナを強参照しない。コンテナも返して、テストの間は呼び出し側が保持する
    private func makeContainer() throws -> ModelContainer {
        let configuration = ModelConfiguration(isStoredInMemoryOnly: true)
        return try ModelContainer(for: TodoRecord.self, configurations: configuration)
    }

    @Test func insertして取得できる() throws {
        let container = try makeContainer()
        let context = container.mainContext
        context.insert(TodoRecord(title: "牛乳を買う"))
        try context.save()

        let records = try context.fetch(FetchDescriptor<TodoRecord>())
        #expect(records.count == 1)
        #expect(records.first?.title == "牛乳を買う")
    }

    @Test func deleteすると取得できなくなる() throws {
        let container = try makeContainer()
        let context = container.mainContext
        let record = TodoRecord(title: "メールを返す")
        context.insert(record)
        try context.save()

        context.delete(record)
        try context.save()

        #expect(try context.fetch(FetchDescriptor<TodoRecord>()).isEmpty)
    }

    @Test func Predicateで未完了だけに絞れる() throws {
        let container = try makeContainer()
        let context = container.mainContext
        let done = TodoRecord(title: "完了済み")
        done.toggle()
        context.insert(done)
        context.insert(TodoRecord(title: "未完了"))

        let descriptor = FetchDescriptor<TodoRecord>(predicate: #Predicate { !$0.isDone })
        let records = try context.fetch(descriptor)
        #expect(records.map(\.title) == ["未完了"])
    }

    @Test func sortByで作成日時の古い順に並ぶ() throws {
        let container = try makeContainer()
        let context = container.mainContext
        let now = Date.now
        context.insert(TodoRecord(title: "新しい", createdAt: now))
        context.insert(TodoRecord(title: "古い", createdAt: now.addingTimeInterval(-60)))

        let descriptor = FetchDescriptor<TodoRecord>(sortBy: [SortDescriptor(\.createdAt)])
        let records = try context.fetch(descriptor)

    }

        let record = TodoRecord(title: "x")

        #expect(record.isDone)
        #expect(record.completedAt != nil)
        record.toggle()
        #expect(record.completedAt == nil)

import Foundation
import SwiftData

// API から取ってきた 1 件ずつを TodoRecord として保存する。
// メインアクター上の modelContext で行う（件数が少なく、@ModelActor で別スレッドに逃がす必要がないため）
func importTodos(_ dtos: [TodoDTO], into context: ModelContext) throws {
    for dto in dtos {
        let record = TodoRecord(title: dto.title, remoteID: dto.id)
        if dto.completed {
            record.toggle()
        }
        // remoteID が同じ行が既にあれば、insert は新規追加ではなく上書きになる（.unique の挙動）
        context.insert(record)
    }
    try context.save()
}

つまずきポイント

💡

unknown attribute 'Model' が出る

@Model を使うファイルに import SwiftData があるかを確かめてください。@Query や modelContext を使う View のファイルにも必要です。

💡

再起動するとデータが消えている

追加・完了の切り替え・削除の後に try? modelContext.save() を呼んでいるかを確かめてください。自動保存だけでは、操作の直後に終了したときに保存されないことがあります（ステップ 4）。

💡

一覧がいつも空で、エラーも出ない

HandsonAppApp.swift の WindowGroup に .modelContainer(for: TodoRecord.self) が付いているかを確かめてください（ステップ 8）。

まとめ

@Model で保存するクラスを作り、.modelContainer でアプリに保存先を用意しました。@Query で一覧を表示し、modelContext で追加・更新・削除しました。自動保存は変更の直後に行われるとは限らないので、操作のたびに save() を呼びます。 #Predicate と @Query(filter:sort:) を子 View の init で組み立てて絞り込み、メモリ上だけのコンテナでテストを書きました。発展として、API から取り込んだデータを @Attribute(.unique) で重複させずに保存しました。 次の項目では、Swift Testing を使ったユニットテストを詳しく学びます。
