URLSession と Codable

  • ⏱ 所要時間: 60分
  • 📊 難易度: 初級
  • 👤 対象: async / await でデータを読み込むアプリを作れ、次に本物の Web API と通信したい人
  • 📋 前提: 06 で TodoRepository から読み込む HandsonApp プロジェクトが手元にあること。@concurrent・nonisolated・async let の意味と、HTTP（メソッド・ステータスコード）と JSON の基本を知っていること
  • 🔗 前提となる項目: 06 async/await と @MainActor

🎯 このレッスンで学ぶこと

  • Codable と JSONDecoder で JSON を型に変換する。キー名が違うときは CodingKeys や keyDecodingStrategy を使い、失敗は DecodingError で受ける
  • URLSession の data(from:) で GET し、HTTPURLResponse のステータスコードを自分で確かめる
  • URLProtocol のスタブで、ネットワークに出ないテストを書く
  • 固定データを返していた TodoRepository を、本物の通信に差し替える
  • URLRequest と JSONEncoder で POST する
  • 404・App Transport Security・ホスト不明のエラーを起こし、画面のエラー表示で受ける

概要

06 の ToDo アプリは、Task.sleep で 1 秒待ってから固定のデータを返す TodoRepository から読み込んでいました。この項目では、そこを本物の Web API との通信に置き換えます。 完成すると、起動時にインターネット上の API から 5 件の ToDo を取得して一覧に表示します。「追加」でタスクを足すと、API に POST して返ってきた 1 件を一覧の末尾に加えます。

Codable で JSON を型にする → URLSession で GET → URLProtocol のスタブでテスト → TodoRepository の差し替え → POST → エラー処理、の順に進めます。1 ステップで扱う概念は 1 つです。 Swift 6 の言語モードでつまずく箇所は、実際のエラーの文言とともに対処を示します。06 と同じく、Xcode の画面での操作と、同じ結果をターミナルで確かめるコマンドの両方を載せています。

ℹ️

使用バージョンと並行処理の設定

macOS 26.6.2 / Xcode 27.0 / Swift 6.4 / iPhone 17（iOS 27.0）のシミュレータは 06 と同じです。バージョンは執筆時点（2026年10月）のものです。

アプリターゲットの SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor と SWIFT_APPROACHABLE_CONCURRENCY = YES も 06 のままです。アプリの型は、何も書かなければメインアクターに分離されます。この前提は、この項目でも何度も出てきます。

ℹ️

インターネット接続と、使用する API

この項目のアプリと curl の実行には、インターネット接続が必要です。API には、公開されている学習用の模擬 API JSONPlaceholder を使います。登録や API キーは不要です。

JSONPlaceholder は、POST などの書き込みを受け付けて結果を返しますが、サーバーには保存しません。この点はステップ 6 で確かめます。なお、ユニットテストはスタブを使うので、ネットワークに出ません（ステップ 4）。

2

Codable と JSONDecoder で JSON を型にする

まず、API の 1 件分の JSON に対応する型を作ります。Models フォルダに Swift ファイル TodoDTO.swift を追加します（Xcode では Models を右クリックし、New File from Template… で iOS > Swift File、Targets は HandsonApp）。 中身を次の内容にします。

Swift HandsonApp/Models/TodoDTO.swift 
import Foundation

// JSONPlaceholder の /todos が返す 1 件分の JSON に対応する型
nonisolated struct TodoDTO: Codable {
    let userId: Int
    let id: Int
    let title: String
    let completed: Bool
}

nonisolated extension TodoItem {
    // API の 1 件から画面用のモデルを作る。優先度は API に無いので既定値（中）
    init(dto: TodoDTO) {
        self.init(title: dto.title, status: dto.completed ? .done(Date()) : .todo)
    }
}
  • DTO（Data Transfer Object）は、通信でやり取りする形をそのまま写した型です。画面で使う TodoItem とは分けます。id が Int か UUID か、優先度があるかどうかが違うからです。
  • Codable は Encodable & Decodable の別名です。プロパティ名と JSON のキー名が一致していれば、準拠を書くだけで、JSON との変換（init(from:) と encode(to:)）が自動で作られます。
  • nonisolated struct TodoDTO: 06 で TodoItem に付けたのと同じ指定です。理由は下の警告で確かめます。
  • init(dto:): API の 1 件を画面用の TodoItem に変換します。API には優先度が無いので既定値（中）になります。完了日時も無いので、completed が true なら変換した時刻で .done(Date()) にします。

デコードとエンコードを確かめるテストを書きます。HandsonAppTests フォルダに TodoDTOTests.swift を追加します（Targets は HandsonAppTests）。

Swift HandsonAppTests/TodoDTOTests.swift 
import Foundation
import Testing
@testable import HandsonApp

struct TodoDTOTests {

    // 実際の API のレスポンス（先頭 2 件。2 件目の completed だけ true に変えてある）
    static let json = """

        #expect(todos.count == 2)
        #expect(todos[0].title == "delectus aut autem")
        #expect(todos[1].completed)
    }

    @Test func encodesToJSON() throws {
        let dto = TodoDTO(userId: 1, id: 0, title: "牛乳を買う", completed: false)
        let data = try JSONEncoder().encode(dto)
        let object = try #require(try JSONSerialization.jsonObject(with: data) as? [String: Any])
        #expect(object["title"] as? String == "牛乳を買う")
        #expect(object["completed"] as? Bool == false)
        #expect(object.count == 4)
    }

    @Test func convertsToTodoItem() {
        let done = TodoItem(dto: TodoDTO(userId: 1, id: 2, title: "A", completed: true))
        #expect(done.title == "A")
        #expect(done.isDone)
        #expect(done.priority == .medium)

        let open = TodoItem(dto: TodoDTO(userId: 1, id: 3, title: "B", completed: false))
        #expect(!open.isDone)
    }

    // キー名が違う場合 1: CodingKeys で対応づける
    struct Renamed: Codable {
        let title: String
        let isCompleted: Bool

        enum CodingKeys: String, CodingKey {
            case title
            case isCompleted = "completed"
        }
    }

    @Test func codingKeysMapsDifferentKeyNames() throws {
        let json = #"{ "title": "A", "completed": true }"#
        let value = try JSONDecoder().decode(Renamed.self, from: Data(json.utf8))
        #expect(value.isCompleted)
    }

    // キー名が違う場合 2: snake_case を camelCase に自動変換する
    struct SnakeCase: Decodable {
        let userId: Int
        let dueDate: String
    }

    @Test func convertFromSnakeCase() throws {
        let json = #"{ "user_id": 7, "due_date": "2026-10-03" }"#
        let decoder = JSONDecoder()
        decoder.keyDecodingStrategy = .convertFromSnakeCase
        let value = try decoder.decode(SnakeCase.self, from: Data(json.utf8))
        #expect(value.userId == 7)
        #expect(value.dueDate == "2026-10-03")
    }

    @Test func typeMismatchThrowsDecodingError() {
        let json = #"{ "userId": 1, "id": 1, "title": "A", "completed": "yes" }"#
        do {
            _ = try JSONDecoder().decode(TodoDTO.self, from: Data(json.utf8))
            Issue.record("デコードが成功してしまった")
        } catch DecodingError.typeMismatch(let type, let context) {
            print("DEBUG typeMismatch:", type, context.codingPath.map(\.stringValue), context.debugDescription)
            #expect("\(type)" == "Bool")
        } catch {
            Issue.record("想定外のエラー: \(error)")
        }
    }

    @Test func missingKeyThrowsDecodingError() {
        let json = #"{ "userId": 1, "id": 1, "title": "A" }"#
        do {
            _ = try JSONDecoder().decode(TodoDTO.self, from: Data(json.utf8))
            Issue.record("デコードが成功してしまった")
        } catch DecodingError.keyNotFound(let key, let context) {
            print("DEBUG keyNotFound:", key.stringValue, context.debugDescription)
            #expect(key.stringValue == "completed")
        } catch {
            Issue.record("想定外のエラー: \(error)")
        }
    }
}
  • JSONDecoder().decode([TodoDTO].self, from:): JSON の Data を、指定した型に変換します。配列なら [TodoDTO].self を渡します。逆向きは JSONEncoder().encode(_:) です。
  • CodingKeys: JSON のキー名とプロパティ名が違うときに、対応表を書きます。Renamed では JSON の completed を isCompleted として読みます。
  • keyDecodingStrategy = .convertFromSnakeCase: user_id のような snake_case のキーを、userId のような camelCase のプロパティに自動で対応づけます。JSONPlaceholder のキーは camelCase なので、テスト用の JSON で試しています。
  • デコードに失敗すると DecodingError が投げられます。型が合わなければ .typeMismatch、キーが無ければ .keyNotFound です。中身を見るために print しています。

3

URLSession で GET し、ステータスコードを確かめる

API と通信する役の TodoAPIClient を作ります。Models フォルダに TodoAPIClient.swift を追加し、次の内容にします（Targets は HandsonApp）。

Swift HandsonApp/Models/TodoAPIClient.swift 
import Foundation

nonisolated enum APIError: Error, Equatable {
    case invalidResponse
    case badStatus(Int)
}

nonisolated struct TodoAPIClient {
    var session: URLSession = .shared
    var baseURL = URL(string: "https://jsonplaceholder.typicode.com")!

    @concurrent func fetchTodos(limit: Int) async throws -> [TodoDTO] {
        // https://jsonplaceholder.typicode.com/todos?_limit=5
        var components = URLComponents(url: baseURL.appending(path: "todos"), resolvingAgainstBaseURL: false)!
        components.queryItems = [URLQueryItem(name: "_limit", value: String(limit))]

        let (data, response) = try await session.data(from: components.url!)
        guard let http = response as? HTTPURLResponse else {
            throw APIError.invalidResponse
        }
        guard (200..<300).contains(http.statusCode) else {
            throw APIError.badStatus(http.statusCode)
        }
        return try JSONDecoder().decode([TodoDTO].self, from: data)
    }
}
  • URLComponents と URLQueryItem: ?_limit=5 のようなクエリを組み立てます。文字列の連結で URL を作ると、日本語や & を含む値がエスケープされません。baseURL.appending(path:) は iOS 16 以降で使えます。
  • session.data(from:): async throws の関数で、(Data, URLResponse) の組を返します。
  • response as? HTTPURLResponse: URLResponse を HTTP の応答として扱うためにキャストし、statusCode を見ます。
  • session と baseURL は var にして既定値を持たせています。アプリは既定値のまま使い、テストでは外から差し替えます（ステップ 4）。
  • nonisolated: TodoDTO と同じ理由で、APIError と TodoAPIClient にも付けます。APIError を Equatable にしたのは、テストで .badStatus(404) と比べるためです。
⚠️

URLSession は 404 や 500 でもエラーを投げない

data(from:) がエラーを投げるのは、通信そのものが失敗したとき（ホストが見つからない、接続できないなど）です。サーバーが 404 や 500 を返した場合は、通信としては成功なので、そのまま Data と応答が返ります。 ステータスコードの確認は自分で書きます。ここでは 200 番台以外で APIError.badStatus を投げています。確認を書き忘れると、エラー画面の HTML などを JSON のつもりでデコードしてしまい、分かりにくい DecodingError になります。

@concurrent: デコードをメインアクターの外で行う
fetchTodos には、06 の TodoSummarizer と同じく @concurrent を付けています。 執筆時に、@MainActor のテストから実際のネットワークで fetchTodos(limit: 3) を呼び、デコードの直前に runningOnMainThread() を print して比べました（確認後に削除）。

fetchTodos の宣言デコード時にメインスレッドか
@concurrent なし（nonisolated な型の async 関数）true
@concurrent func fetchTodosfalse

どちらの場合も、await session.data(from:) で応答を待っている間はメインスレッドを止めません。違うのは、受け取ったあとの JSON のデコードをどこで行うかです。 06 で確かめたとおり、nonisolated な async 関数は呼び出し元のアクター（ここではメインアクター）で動きます。件数の多い JSON をメインアクターでデコードすると画面が引っかかるので、@concurrent でメインアクターの外に出します。

4

URLProtocol のスタブで、ネットワークに依存しないテストを書く

テストから本物の API を呼ぶと、ネットワークの状態や API の都合で結果が変わります。そこで、URLSession の通信を横取りして決めた応答を返す URLProtocol のサブクラス（スタブ）を作ります。 まず、素朴に static var で応答を持たせると、Swift 6 の言語モードでは次のエラーになります。

⚠️

可変の static var はコンパイルエラーになる

次のように、static var でハンドラを持たせた最初の版を考えます。

Swift HandsonAppTests/StubURLProtocol.swift 
import Foundation

final class StubURLProtocol: URLProtocol {
    static var handler: ((URLRequest) throws -> (HTTPURLResponse, Data))?
}

この版でテストを実行すると、4 行目（static var handler）の 16 文字目で次のエラーになります。

Terminal 
$ perl -e 'alarm 600; exec @ARGV' xcodebuild -project HandsonApp.xcodeproj -scheme HandsonApp -destination 'platform=iOS Simulator,name=iPhone 17' -derivedDataPath $DD -parallel-testing-enabled NO -only-testing:HandsonAppTests test 2>&1 | grep -E "^Test |✔|✘|\*\* |error:"……/StubURLProtocol.swift:4:16: error: static property 'handler' is not concurrency-safe because it is nonisolated global shared mutable state [#MutableGlobalVariable]** TEST FAILED **

テストターゲットの既定の分離は nonisolated です（メインアクターになるのはアプリターゲットだけ）。可変の static var は、どのスレッドからも読み書きできる共有の状態なので、データ競合の恐れがあるとしてエラーになります。

  • nonisolated(unsafe) static var にするとコンパイラの検査を切れます。しかし Swift Testing は既定でテストを並列に実行するので、テスト同士でハンドラを上書きし合う恐れがあり、採りません。
  • actor で守る方法は、URLProtocol の startLoading() が同期のメソッドで await できないので向きません。
  • そこで、Synchronization の Mutex（iOS 18 以降）で守ります。withLock の中でだけ値を読み書きできる、ロック付きの入れ物です。

HandsonAppTests フォルダに StubURLProtocol.swift を追加し、次の内容にします（Targets は HandsonAppTests）。

Swift HandsonAppTests/StubURLProtocol.swift 
import Foundation
import Synchronization
@testable import HandsonApp

// 送信されたリクエストの記録。POST のテストで「何を送ったか」を確かめるために使う
struct RecordedRequest: Sendable {
    let method: String
    let url: URL
    let contentType: String?
    let body: Data
}

// ネットワークに出ずに、決めた応答を返す URLProtocol。
// テストごとに別のホスト名（stub-<UUID>.test）を使い、ホスト名をキーにして
// 応答と記録を保持するので、テストを並列実行しても互いに干渉しない。
final class StubURLProtocol: URLProtocol {
    typealias Handler = @Sendable (URLRequest) throws -> (statusCode: Int, body: Data)

    // 可変な static は Mutex で守る（`static var` のままだと Swift 6 のコンパイルエラー）
    private static let handlers = Mutex<[String: Handler]>([:])
    private static let recorded = Mutex<[String: [RecordedRequest]]>([:])

    // このスタブ専用のセッションとクライアントを作る
    static func makeClient(statusCode: Int = 200, json: String) -> TodoAPIClient {
        makeClient { _ in (statusCode, Data(json.utf8)) }
    }

    static func makeClient(handler: @escaping Handler) -> TodoAPIClient {
        let host = "stub-\(UUID().uuidString.lowercased()).test"
        handlers.withLock { $0[host] = handler }
        let configuration = URLSessionConfiguration.ephemeral
        configuration.protocolClasses = [StubURLProtocol.self]
        return TodoAPIClient(
            session: URLSession(configuration: configuration),
            baseURL: URL(string: "https://\(host)")!
        )
    }

    static func requests(for client: TodoAPIClient) -> [RecordedRequest] {
        recorded.withLock { $0[client.baseURL.host()!] ?? [] }
    }

    override class func canInit(with request: URLRequest) -> Bool { true }
    override class func canonicalRequest(for request: URLRequest) -> URLRequest { request }

    override func startLoading() {
        guard let url = request.url, let host = url.host(),
              let handler = Self.handlers.withLock({ $0[host] }) else {
            client?.urlProtocol(self, didFailWithError: URLError(.badURL))
            return
        }
        let record = RecordedRequest(
            method: request.httpMethod ?? "GET",
            url: url,
            contentType: request.value(forHTTPHeaderField: "Content-Type"),
            body: Self.bodyData(of: request)
        )
        Self.recorded.withLock { $0[host, default: []].append(record) }
        do {
            let (statusCode, body) = try handler(request)
            let response = HTTPURLResponse(url: url, statusCode: statusCode, httpVersion: "HTTP/1.1", headerFields: ["Content-Type": "application/json"])!
            client?.urlProtocol(self, didReceive: response, cacheStoragePolicy: .notAllowed)
            client?.urlProtocol(self, didLoad: body)
            client?.urlProtocolDidFinishLoading(self)
        } catch {
            client?.urlProtocol(self, didFailWithError: error)
        }
    }

    override func stopLoading() {}

    // URLSession は httpBody を httpBodyStream に変換して URLProtocol に渡すので、ストリームから読む
    private static func bodyData(of request: URLRequest) -> Data {
        if let body = request.httpBody { return body }
        guard let stream = request.httpBodyStream else { return Data() }
        stream.open()
        defer { stream.close() }
        var data = Data()
        var buffer = [UInt8](repeating: 0, count: 1024)
        while stream.hasBytesAvailable {
            let count = stream.read(&buffer, maxLength: buffer.count)
            if count <= 0 { break }
            data.append(buffer, count: count)
        }
        return data
    }
}
  • Mutex<[String: Handler]>: 応答を作るハンドラを、ホスト名をキーにして持ちます。static let なので、それ自体は書き換わりません。
  • makeClient: テストごとに stub-<UUID>.test という別のホスト名を割り当てて、ハンドラを登録します。テストが並列に動いても、互いの応答を取り違えません。
  • URLSessionConfiguration.ephemeral の protocolClasses にスタブを入れ、そのセッションと baseURL を TodoAPIClient(session:baseURL:) に渡します。TodoAPIClient 側には、テスト用の分岐を一切書かずに済みます。
  • canInit(with:) で全てのリクエストを引き受け、startLoading() で client?.urlProtocol(...) を通じて応答・本文・完了を返します。
  • RecordedRequest と bodyData(of:): 送られたリクエストを記録します。POST の本文を確かめるためにステップ 6 で使います。URLSession は httpBody をストリーム（httpBodyStream）に変えて渡すので、ストリームから読み出しています。

7

通信のエラーを起こして、画面で受ける

通信が失敗する場面を、わざと起こして確かめます。コードは変えず、baseURL を一時的に差し替えます。 まず、存在しないパスで 404 を起こします。HandsonAppApp.swift の TodoAPIClient() を、一時的に次のように書き換えます。

Swift HandsonApp/HandsonAppApp.swift（一時的な変更） 
    @State private var store = TodoStore(repository: TodoRepository(client: TodoAPIClient(baseURL: URL(string: "https://jsonplaceholder.typicode.com/x")!)))

リクエスト先は /x/todos になり、存在しないので 404 が返ります。ビルドしてシミュレータで起動します。

Terminal 
$ xcodebuild -project HandsonApp.xcodeproj -scheme HandsonApp -destination 'platform=iOS Simulator,name=iPhone 17' -derivedDataPath $DD build…** BUILD SUCCEEDED **$ xcrun simctl install booted $DD/Build/Products/Debug-iphonesimulator/HandsonApp.app$ xcrun simctl launch booted com.example.HandsonAppcom.example.HandsonApp: <プロセス ID>

画面では、「Todo」の一覧が空で、その上に赤い文字で「読み込みに失敗しました」と表示されます。プロフィールのカードも表示されません。 load() は async let で一覧とプロフィールを同時に取得し、どちらかが失敗した時点で catch へ進みます。そのため、items と profile はどちらも更新されません。

同じ書き換え箇所で、ほかの URL も試します。http://jsonplaceholder.typicode.com（HTTPS ではない）と https://no-such-host.invalid（存在しないホスト）です。どちらも、画面は 404 のときと同じになります。赤い文字の「読み込みに失敗しました」が表示され、Todo の一覧は空で、プロフィールのカードも表示されません。

画面では区別できないので、投げられたエラーの中身を一時的なテストで確かめます。baseURL を差し替えた TodoAPIClient で fetchTodos(limit: 1) を実際のネットワークで呼び、エラーを print します。次のファイルを作ります。

Swift HandsonAppTests/NetworkErrorProbeTests.swift（一時的なファイル） 
import Foundation
import Testing
@testable import HandsonApp

struct NetworkErrorProbeTests {   // 一時的。確認後に削除
    @Test(arguments: [
        ("badpath", "https://jsonplaceholder.typicode.com/x"),
        ("http", "http://jsonplaceholder.typicode.com"),
        ("nohost", "https://no-such-host.invalid"),
    ])
    func probe(label: String, url: String) async {
        do {
            _ = try await TodoAPIClient(baseURL: URL(string: url)!).fetchTodos(limit: 1)
        } catch let error as URLError {
            print("DEBUG \(label): URLError code=\(error.code.rawValue) \(error.code) desc=\(error.localizedDescription)")
        } catch {
            print("DEBUG \(label): APIError \(error) | \(error.localizedDescription)")
        }
    }
}

このテストだけを実行し、DEBUG で始まる行を取り出します。

⚠️

存在しないパス: APIError.badStatus(404)

Terminal 
DEBUG badpath: APIError badStatus(404) | The operation couldn’t be completed. (HandsonApp.APIError error 0.)

ステップ 3 のステータスの確認が投げた badStatus(404) です。| の後ろは localizedDescription ですが、APIError は利用者向けの文言を持たないので、読んでも意味の分からない文になります。そのため画面には、固定の文言「読み込みに失敗しました」を出しています。

⚠️

http:// で接続: App Transport Security（-1022）

baseURL を http://jsonplaceholder.typicode.com（HTTPS ではない）にした結果です。

Terminal 
DEBUG http: URLError code=-1022 Code(rawValue: -1022) desc=The resource could not be loaded because the App Transport Security policy requires the use of a secure connection.

URLError のコード -1022（appTransportSecurityRequiresSecureConnection）です。iOS の App Transport Security（ATS）は、暗号化されていない http:// の通信を既定で拒否します。リクエストは、サーバーへ届く前に OS が止めます。 対処はサーバー側を HTTPS にすることです。ATS の例外の設定は、この項目では扱いません。

⚠️

存在しないホスト（-1003）

baseURL を https://no-such-host.invalid にした結果です。.invalid は予約されたトップレベルドメインで、名前解決は必ず失敗します。

Terminal 
DEBUG nohost: URLError code=-1003 Code(rawValue: -1003) desc=A server with the specified hostname could not be found.

URLError のコード -1003（cannotFindHost）です。404 と違い、こちらは通信そのものの失敗なので、data(from:) が URLError を投げます。

3 つのエラーは、どれも TodoStore.load() の最後の catch 1 か所で受けられ、「読み込みに失敗しました」になります。 エラーの種類で文言を出し分けたい場合は、catch let error as URLError や catch APIError.badStatus(let code) を、汎用の catch より前に足します。06 で CancellationError を先に catch したのと同じ考え方です。

確かめたら、HandsonAppApp.swift を元の TodoAPIClient() に戻してください。

✅ 確認ポイント

404 の baseURL で起動すると、赤い文字の「読み込みに失敗しました」が表示され、一覧とプロフィールが空になることを確かめます。HandsonAppApp.swift を元に戻したら、次のステップに進みます。

つまずきポイント

💡

main actor-isolated ... can not be referenced from a nonisolated context が出る

アプリターゲットでは、型も extension のメンバーも既定でメインアクターに分離されます。通信や JSON に使う型（TodoDTO・TodoAPIClient・APIError・NewTodo）と、TodoItem の extension に nonisolated が付いているかを確かめてください。

💡

#expect で型どうしを == で比べられない

DecodingError.typeMismatch の型を #expect(type == Bool.self) で比べると、error: cannot convert value of type 'Bool.Type' to expected argument type '_OptionalNilComparisonType' になりました。TodoDTOTests では "\(type)" == "Bool" と文字列にして比べています。

💡

一覧の内容が教材と違う

一覧の項目は API の応答そのままです（_limit=5 で先頭の 5 件）。completed が true の項目は .done(Date()) に変換するので、完了日は API から取得して変換した日時になります。

まとめ

Codable の DTO と JSONDecoder で JSON を型にし、CodingKeys・keyDecodingStrategy・DecodingError をテストで確かめました。 URLSession の data(from:) で GET し、404 でもエラーにならないのでステータスコードを自分で確かめました。デコードは @concurrent でメインアクターの外で行います。 URLProtocol のスタブを Mutex で作ってネットワークに出ないテストを書き、TodoRepository を本物の通信に差し替えました。さらに URLRequest で POST し、404・ATS・ホスト不明のエラーを画面で受けました。 次の項目では、SwiftData を使ってデータを端末に保存（永続化）します。
