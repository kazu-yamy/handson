環境構築（Xcode 27・Swift 6 言語モード）

  • ⏱ 所要時間: 45分
  • 📊 難易度: 入門
  • 👤 対象: iOS アプリ開発が初めてで、Xcode でプロジェクトを作るところから始めたい人
  • 📋 前提: macOS 26.6 以上の Mac に Xcode 27 をインストール済みであること（App Store または developer.apple.com から入手）。シミュレータだけを使うため Apple ID は不要です。ターミナルでの基本的なコマンド操作ができること。Swift の文法は 02 で扱うため、この項目では知らなくても進められます
  • 🔗 前提となる項目: なし（トラック最初の項目）

🎯 このレッスンで学ぶこと

  • Xcode とシミュレータのバージョンをターミナルから確認する
  • Xcode の App テンプレートから SwiftUI のプロジェクトを作り、生成されたファイルの役割を知る
  • Swift Language Version を Swift 6 に切り替え、iOS Deployment Target を 18.0 に下げる
  • シミュレータでアプリを起動し、ContentView の変更を反映させる
  • Swift Testing でテストを書き、既定の MainActor 分離によるエラーを直す
  • Swift 6 言語モードのデータ競合チェックがエラーになることを確かめ、xcodebuild でビルドとテストを実行する

概要

iOS トラックの最初の項目です。Xcode でアプリのプロジェクトを作り、Swift 6 言語モードに切り替えて、シミュレータでの実行とテストまでを通します。 以降の項目は、ここで作るプロジェクト HandsonApp を出発点にして機能を足していきます。

操作は Xcode の画面で行います。スクリーンショットは載せず、メニュー名や画面上の項目名（英語表示）を コード書式 で示します。 あわせて、同じ結果をターミナルから確かめるコマンドとその出力を載せています。

ℹ️

使用バージョン

macOS 26.6.2 / Xcode 27.0（27A266a）/ Swift 6.4 / iOS Simulator SDK 27.0 で動作を確認しています。シミュレータは iPhone 17（iOS 26.5）を使います。 バージョンは執筆時点（2026年10月）のものです。

この教材の出力は、iOS 26.5 のシミュレータランタイムだけが入った環境で採取しました。iOS 27 のランタイムがある環境では、出力中の 26.5 が 27.0 になります。 iOS 27 のランタイムが無い環境では、Xcode 27 の SDK（27.0）とシミュレータの iOS（26.5）がずれるため、ステップ 4 で説明するエラーが起きます。

手順

1

Xcode とシミュレータを確認する

最初に、Xcode と Swift のバージョンを確認します。ターミナルで次のコマンドを実行してください。

💡

ランタイムが 1 つも表示されない場合

== Runtimes == の下に何も表示されない場合は、Xcode の Xcode > Settings > Components から iOS のランタイムをダウンロードしてください。 iOS 27 のランタイムが入っている場合は、デバイス名が上の出力と異なることがあります。その場合は、以降のコマンドの name=iPhone 17 を、一覧に表示された iPhone の名前に置き換えてください。

✅ 確認ポイント

Xcode 27.0 と Apple Swift version 6.4 が表示され、iOS のランタイムが 1 つ以上、iPhone のシミュレータが 1 台以上あれば準備完了です。

2

新しいプロジェクトを作る

Xcode を起動し、App テンプレートからプロジェクトを作ります。次の順に操作してください。

  1. メニューの File > New > Project… を選びます。
  2. 上部のタブで iOS を選び、App を選んで Next を押します。
  3. プロジェクトの設定を次のとおり入力し、Next を押します。
    • Product Name: HandsonApp
    • Team: None
    • Organization Identifier: com.example（Bundle Identifier に com.example.HandsonApp と表示されます）
    • Interface: SwiftUI
    • Language: Swift
    • Testing System: Swift Testing with XCTest UI Tests
    • Storage: None（Host in CloudKit はオフ）
  4. 保存先のフォルダを選びます。Create Git repository on my Mac はオフにして Create を押します。

保存先に HandsonApp フォルダが作られ、その中に HandsonApp.xcodeproj ができます。 左側のナビゲータには、HandsonApp・HandsonAppTests・HandsonAppUITests の 3 つのフォルダが並びます。

ℹ️

入力値について

HandsonApp はトラックを通して使う名前です。プロジェクト名やターゲット名はテストの @testable import やスキーム名にも使われるため、項目ごとには変えません。 com.example はシミュレータで動かすための仮の値です。シミュレータで動かすだけなら、署名用の Team は不要です。 Storage は SwiftData を扱う 08 まで使わないため None にします。

ターミナルでも、ターゲットとスキームを確認しておきます。HandsonApp.xcodeproj があるフォルダ（保存先の HandsonApp フォルダ）に移動してから実行してください。以降のコマンドも全てこのフォルダで実行します。

Terminal 
$ xcodebuild -list -project HandsonApp.xcodeprojInformation about project "HandsonApp":    Targets:        HandsonApp        HandsonAppTests        HandsonAppUITests    Build Configurations:        Debug        Release    If no build configuration is specified and -scheme is not passed then "Release" is used.    Schemes:        HandsonApp

✅ 確認ポイント

ナビゲータに 3 つのフォルダがあり、xcodebuild -list の Targets に HandsonApp・HandsonAppTests・HandsonAppUITests、Schemes に HandsonApp が表示されれば OK です。

3

生成されたファイルを読む

テンプレートが生成したファイルを順に見ていきます。プロジェクトのフォルダ構成は次のとおりです。

Text HandsonApp/ 
HandsonApp/
  HandsonApp.xcodeproj/          # プロジェクトの設定（ターゲット・ビルド設定）
  HandsonApp/                    # アプリ本体
    HandsonAppApp.swift
    ContentView.swift
    Assets.xcassets/             # 画像や色などのアセット
  HandsonAppTests/               # ユニットテスト（Swift Testing）
    HandsonAppTests.swift
  HandsonAppUITests/             # UI テスト（XCTest）
    HandsonAppUITests.swift

以降のコードでは、ファイル先頭のヘッダーコメント（作成者・日付）と説明用コメントを省略しています。HandsonAppApp.swift はアプリのエントリポイントです。

Swift HandsonApp/HandsonAppApp.swift 
//
//  HandsonAppApp.swift
//  HandsonApp
//

import SwiftUI

@main
struct HandsonAppApp: App {
    var body: some Scene {
        WindowGroup {
            ContentView()
        }
    }
}
  • @main: アプリの実行がここから始まることを示します。
  • App プロトコル: アプリ全体を表す型が適合するプロトコルです。body でアプリが持つ画面（Scene）を返します。
  • WindowGroup: ウィンドウを表す Scene で、中に ContentView を表示します。

ContentView.swift は最初に表示される画面です。

Swift HandsonApp/ContentView.swift 
//
//  ContentView.swift
//  HandsonApp
//

import SwiftUI

struct ContentView: View {
    var body: some View {
        VStack {
            Image(systemName: "globe")
                .imageScale(.large)
                .foregroundStyle(.tint)
            Text("Hello, world!")
        }
        .padding()
    }
}

#Preview {
    ContentView()
}
  • View プロトコル: 画面の部品が適合するプロトコルです。body が表示する UI を返します。
  • VStack: 中の要素を縦に並べます。地球のアイコン（Image(systemName: "globe")）と文字列（Text）が並びます。
  • #Preview: Xcode の Canvas（エディタ右側のプレビュー）に表示する内容です。

Assets.xcassets は、アクセントカラー（AccentColor）とアプリアイコン（AppIcon）の置き場所です。この項目では中身を変更しません。

テストは 2 種類あります。HandsonAppTests.swift は Swift Testing のユニットテストです。

Swift HandsonAppTests/HandsonAppTests.swift 
//
//  HandsonAppTests.swift
//  HandsonAppTests
//

import Testing
@testable import HandsonApp

struct HandsonAppTests {

    @Test func example() async throws {
        // Write your test here and use APIs like `#expect(...)` to check expected conditions.
    }

}

HandsonAppUITests.swift は XCTest の UI テストで、アプリを起動して画面を操作する処理を自動化するためのものです。テンプレートが生成するコメントと一部のメソッド（tearDownWithError、testLaunchPerformance）は省略しています。

Swift HandsonAppUITests/HandsonAppUITests.swift 
//
//  HandsonAppUITests.swift
//  HandsonAppUITests
//

import XCTest

final class HandsonAppUITests: XCTestCase {

    override func setUpWithError() throws {
        continueAfterFailure = false
    }

    @MainActor
    func testExample() throws {
        let app = XCUIApplication()
        app.launch()
    }
}
ℹ️

UI テストはこの項目では実行しない

UI テストはシミュレータでアプリを起動して操作するため、実行に時間がかかります。この項目ではユニットテスト（HandsonAppTests）だけを実行し、UI テストは実行しません。

💡

3 つのフォルダは「同期フォルダ」

HandsonApp・HandsonAppTests・HandsonAppUITests の 3 つのフォルダは、Xcode の同期フォルダ（project.pbxproj では PBXFileSystemSynchronizedRootGroup）として登録されています。 Finder やエディタでフォルダにファイルを追加すると、project.pbxproj を編集しなくてもターゲットに取り込まれます。ステップ 6 で Greeting.swift を追加するときに、この仕組みを使います。

最後に、ビルド設定の初期値を確認します。プロジェクトの設定は HandsonApp.xcodeproj/project.pbxproj に保存されていますが、直接編集する必要はありません。 ここではターミナルから、この項目で扱う 4 つの設定値を表示します。

Terminal 
$ xcodebuild -project HandsonApp.xcodeproj -target HandsonApp -showBuildSettings | grep -E " (SWIFT_VERSION|IPHONEOS_DEPLOYMENT_TARGET|SWIFT_DEFAULT_ACTOR_ISOLATION|SWIFT_APPROACHABLE_CONCURRENCY) ="    IPHONEOS_DEPLOYMENT_TARGET = 27.0    SWIFT_APPROACHABLE_CONCURRENCY = YES    SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor    SWIFT_VERSION = 5.0
  • IPHONEOS_DEPLOYMENT_TARGET = 27.0: アプリが動く最小の iOS バージョンです。テンプレートの既定は最新の iOS（27.0）です。
  • SWIFT_VERSION = 5.0: Swift の言語モードです。テンプレートの既定は Swift 5 言語モードで、コンパイラー自体は Swift 6.4 でも、Swift 6 言語モードのチェックは有効になっていません。
  • SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor: アプリのコードを既定でメインアクター（UI を扱うメインスレッド）に分離する設定です。アプリターゲットにだけ付き、テストターゲットには付きません。
  • SWIFT_APPROACHABLE_CONCURRENCY = YES: Swift Concurrency を扱いやすくする一連の機能を有効にする設定です。

このほか、全ターゲットに共通して SWIFT_UPCOMING_FEATURE_MEMBER_IMPORT_VISIBILITY = YES、GENERATE_INFOPLIST_FILE = YES、TARGETED_DEVICE_FAMILY = "1,2"（iPhone と iPad）、MARKETING_VERSION = 1.0、CURRENT_PROJECT_VERSION = 1 が設定されています。

✅ 確認ポイント

ContentView.swift を開くと、Canvas に地球のアイコンと Hello, world! が表示されます。また、ターミナルの出力が IPHONEOS_DEPLOYMENT_TARGET = 27.0 と SWIFT_VERSION = 5.0 になっていることを確認してください。次のステップでこの 2 つを変更します。

4

Swift 6 言語モードと Deployment Target を設定する

Deployment Target を iOS 18.0 に下げ、3 つのターゲットの Swift Language Version を Swift 6 にします。 Deployment Target を下げるのは、最新の iOS 27 だけでなく、それより古い iOS 18 以降の端末もアプリの対象にするためです（このトラックの最小対象は iOS 18 です）。

⚠️

iOS 26.5 のシミュレータしか無い環境では、27.0 のままだと動かせない

iOS 27 のランタイムが無く、iOS 26.5 のシミュレータしか無い環境で起きる失敗です。既定の 27.0 のまま iPhone 17 を指定してビルドすると、次のように実行先（destination）が見つかりません。iOS 26.5 のシミュレータは、iOS 27.0 以上を要求するアプリの実行先として扱われないためです。iOS 27 のランタイムがある環境では、27.0 のままでもビルドできます。

Terminal 
$ xcodebuild -project HandsonApp.xcodeproj -scheme HandsonApp -destination 'platform=iOS Simulator,name=iPhone 17' buildxcodebuild: error: Unable to find a destination matching the provided destination specifier:		{ platform:iOS Simulator, OS:latest, name:iPhone 17 }	Destinations compatible with the "HandsonApp" scheme:		{ platform:iOS, id:dvtdevice-DVTiPhonePlaceholder-iphoneos:placeholder, name:Any iOS Device }		{ platform:iOS Simulator, id:dvtdevice-DVTiOSDeviceSimulatorPlaceholder-iphonesimulator:placeholder, name:Any iOS Simulator Device }	…		{ platform:iOS Simulator, arch:arm64, id:438136B4-…, OS:26.5, name:iPhone 17, error:iPhone 17’s iOS Simulator 26.5 doesn’t match HandsonApp.app’s iOS Simulator 27.0  deployment target. Upgrade iPhone 17’s iOS Simulator version or lower HandsonApp.app’s deployment target. }

実行先を特定のシミュレータに限定しない -destination 'generic/platform=iOS Simulator' を指定すれば、ビルドは ** BUILD SUCCEEDED ** で終わります。 ただし、そうしてビルドした .app を xcrun simctl install でシミュレータに入れようとすると、次のように失敗します。

Terminal 
App installation failed: “HandsonApp” Requires a Newer Version of iOS … You need to update this iPhone to iOS 27.0 to install this app. … Have 26.5; need 27.0

Xcode の画面でも、同じ理由で実行先に iPhone 17 を選べません。

Xcode で次の順に設定します。

  1. 左のナビゲータの一番上にある青い HandsonApp（プロジェクト）を選びます。
  2. 中央の PROJECT の HandsonApp を選び、Info タブの Deployment Target にある iOS Deployment Target を 18.0 にします。
  3. TARGETS の HandsonApp を選び、Build Settings タブの検索欄に Swift Language Version と入力して、値を Swift 6 にします。
  4. 同じ操作を HandsonAppTests と HandsonAppUITests でも行います。
⚠️

Deployment Target はターゲットではなくプロジェクトで変える

PROJECT の設定は全てのターゲットに引き継がれるため、プロジェクトで変えるとテストターゲットにも効きます。 アプリターゲットの設定だけを変えると、テストターゲットが 27.0 のまま残ります。

続いて、同じ Build Settings で並行処理（Concurrency）に関する設定を確認します。 アプリターゲットの Default Actor Isolation が MainActor、Approachable Concurrency が Yes になっていれば変更は不要です。 Approachable Concurrency は Swift 5 以下の言語モード向けの設定です。Swift 6 に切り替えると Build Settings に表示されなくなる場合があります。 Default Actor Isolation はアプリターゲットにだけ設定されています。

ℹ️

Strict Concurrency Checking は設定しなくてよい

Build Settings には Strict Concurrency Checking という項目もありますが、これは Swift 5 以前の言語モードでだけ効く設定です。Swift 6 言語モードでは、並行処理のチェックは常に最も厳しい complete になるため、設定は不要です。

この操作で project.pbxproj は次のように変わります（Deployment Target はプロジェクトの Debug / Release の 2 か所、Swift Language Version は 3 ターゲット × Debug / Release の 6 か所）。

Diff HandsonApp.xcodeproj/project.pbxproj（抜粋） 
-				IPHONEOS_DEPLOYMENT_TARGET = 27.0;+				IPHONEOS_DEPLOYMENT_TARGET = 18.0;-				SWIFT_VERSION = 5.0;+				SWIFT_VERSION = 6.0;

アプリターゲットのビルド設定は、変更後に次のようになります。

pbxproj HandsonApp.xcodeproj/project.pbxproj（アプリターゲット Debug の抜粋） 
				SWIFT_APPROACHABLE_CONCURRENCY = YES;
				SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor;
				SWIFT_EMIT_LOC_STRINGS = YES;
				SWIFT_UPCOMING_FEATURE_MEMBER_IMPORT_VISIBILITY = YES;
				SWIFT_VERSION = 6.0;
				TARGETED_DEVICE_FAMILY = "1,2";

ターミナルで設定値を確認し、iPhone 17 を指定してビルドします。 -derivedDataPath はビルド結果の出力先です。ステップ 5 でビルドした .app の場所を指定するため、変数 DD に出力先のパスを入れておきます。

Terminal 
$ xcodebuild -project HandsonApp.xcodeproj -target HandsonApp -showBuildSettings | grep -E " (SWIFT_VERSION|IPHONEOS_DEPLOYMENT_TARGET|SWIFT_DEFAULT_ACTOR_ISOLATION|SWIFT_APPROACHABLE_CONCURRENCY) ="    IPHONEOS_DEPLOYMENT_TARGET = 18.0    SWIFT_APPROACHABLE_CONCURRENCY = YES    SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor    SWIFT_VERSION = 6.0$ export DD=/tmp/handson-ios-dd$ xcodebuild -project HandsonApp.xcodeproj -scheme HandsonApp -destination 'platform=iOS Simulator,name=iPhone 17' -derivedDataPath $DD build…** BUILD SUCCEEDED **

ビルドのログは長いため、末尾以外を省略しています。Xcode の画面では ⌘ + B でビルドできます。

✅ 確認ポイント

設定値が IPHONEOS_DEPLOYMENT_TARGET = 18.0 と SWIFT_VERSION = 6.0 になり、iPhone 17 を指定したビルドが ** BUILD SUCCEEDED ** で終われば OK です。

5

シミュレータで実行し、ContentView を変える

Xcode のツールバーで実行先に iPhone 17 を選び、⌘ + R で実行します。 シミュレータが起動し、地球のアイコンと Hello, world! が表示されます。

ターミナルから同じことをする場合は、シミュレータを起動し、ステップ 4 でビルドした .app をインストールして起動します。Xcode の ⌘ + R でシミュレータを起動済みの場合は、すでに起動しているため simctl boot は失敗します。その場合は boot を飛ばしてください。

Terminal 
$ xcrun simctl boot 'iPhone 17'$ xcrun simctl install booted $DD/Build/Products/Debug-iphonesimulator/HandsonApp.app$ xcrun simctl launch booted com.example.HandsonAppcom.example.HandsonApp: 74544

launch の出力の末尾の数字はプロセス ID で、実行するたびに変わります。

次に、画面の文字を変えます。ContentView.swift の Text を次のように書き換えます。

Diff HandsonApp/ContentView.swift 
             Image(systemName: "globe")                 .imageScale(.large)                 .foregroundStyle(.tint)-            Text("Hello, world!")+            Text("Hello, SwiftUI!")+                .font(.title)         }         .padding()

.font(.title) は、文字をタイトル用の大きさにするモディファイア（View の見た目を変えるメソッド）です。変更後の全文は次のとおりです。

Swift HandsonApp/ContentView.swift 
//
//  ContentView.swift
//  HandsonApp
//

import SwiftUI

struct ContentView: View {
    var body: some View {
        VStack {
            Image(systemName: "globe")
                .imageScale(.large)
                .foregroundStyle(.tint)
            Text("Hello, SwiftUI!")
                .font(.title)
        }
        .padding()
    }
}

#Preview {
    ContentView()
}

保存したら、もう一度 ⌘ + R で実行します。ターミナルの場合は、ビルドし直してからインストールと起動をやり直します。

Terminal 
$ xcodebuild -project HandsonApp.xcodeproj -scheme HandsonApp -destination 'platform=iOS Simulator,name=iPhone 17' -derivedDataPath $DD build…** BUILD SUCCEEDED **$ xcrun simctl install booted $DD/Build/Products/Debug-iphonesimulator/HandsonApp.app$ xcrun simctl launch booted com.example.HandsonAppcom.example.HandsonApp: <PID>

✅ 確認ポイント

シミュレータに地球のアイコンと、大きな文字の Hello, SwiftUI! が表示されれば成功です。Canvas のプレビューにも同じ変更が反映されます。

6

Swift Testing でテストを書く

テスト対象の関数を追加します。HandsonApp フォルダに Greeting.swift を作り、次の内容を書きます。 Xcode では HandsonApp フォルダを右クリックして新しい Swift ファイルを作れます。 同期フォルダなので、Finder やエディタでファイルを置いても取り込まれます。

Swift HandsonApp/Greeting.swift 
func greeting(for name: String) -> String {
    "Hello, \(name)!"
}

続いて、HandsonAppTests.swift の example() を、次のテストに置き換えます。

Swift HandsonAppTests/HandsonAppTests.swift（失敗する版の抜粋） 
@Test func greetingContainsName() {
    #expect(greeting(for: "Swift") == "Hello, Swift!")
}

@Test がテスト関数の印で、#expect が条件を確かめるマクロです。 ところが、このテストはビルドの段階で失敗します。Xcode では ⌘ + U でテストを実行できますが、ここではターミナルでテストのビルドだけを行い、エラーを確認します。

Terminal

⚠️

MainActor の関数を nonisolated なテストから呼べない

ステップ 3 で見たとおり、アプリターゲットは SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor なので、greeting(for:) もメインアクターに分離されます。 一方、テストターゲットにはこの設定がなく、テスト関数はどのアクターにも属さない（nonisolated）状態です。 メインアクターの関数を外から同期的に呼ぶことはできないため、エラーになります。エラーの note が示すとおり、テスト関数に @MainActor を付けると解決します。

@MainActor の詳しい使い分けは、06（async/await と @MainActor）で扱います。

テスト関数に @MainActor を付けます。修正後の HandsonAppTests.swift の全文は次のとおりです。

Swift HandsonAppTests/HandsonAppTests.swift 
//
//  HandsonAppTests.swift
//  HandsonAppTests
//

import Testing
@testable import HandsonApp

struct HandsonAppTests {

    @Test @MainActor func greetingContainsName() {
        #expect(greeting(for: "Swift") == "Hello, Swift!")
    }

}

テストを実行します。出力が長いため、grep でテストの結果に関する行だけを表示しています。

Terminal

-only-testing:HandsonAppTests でユニットテストだけを実行し、-parallel-testing-enabled NO でテストの並列実行を止めています。 Xcode の画面では、⌘ + U、またはテストナビゲータでテストの横にある ◇ のボタンから実行できます。

7

Swift 6 のデータ競合チェックと CLI でのビルド・テスト

Swift 6 言語モードに切り替えた効果を確かめます。データ競合（複数の処理が同じ変数を同時に書き換えること）の恐れがあるコードを、確認用のファイルに書いてビルドします。 HandsonApp フォルダに RaceSample.swift を作り、次の内容を書きます。

Swift HandsonApp/RaceSample.swift（確認用。最後に削除する） 
var tapCount = 0

func countUpInBackground() {
    Task.detached {
        tapCount += 1
    }
}

Task.detached は、呼び出し元のアクターを引き継がない非同期タスクを作ります。 一方、グローバル変数 tapCount はアプリターゲットの既定の分離によりメインアクターに属します。メインアクターの外からこの変数を書き換えるコードになっています。

Terminal

Swift 6 言語モードでは、この書き換えがコンパイルエラーになります。比較のため、SWIFT_VERSION=5.0 を引数で上書きして Swift 5 言語モードでビルドしてみます。

Terminal

Swift 5 言語モードでは同じ箇所が warning にとどまり、ビルドは成功します。Swift 6 言語モードに切り替えたことで、データ競合の恐れがビルドを止めるエラーとして扱われるようになりました。

⚠️

Task.detached を Task に直す

Task { } は呼び出し元のアクター（ここではメインアクター）を引き継いで実行されるため、tapCount をメインアクター上で安全に書き換えられます。次のように直すと、Swift 6 言語モードでもビルドが通ります。

Diff HandsonApp/RaceSample.swift 
 func countUpInBackground() {-    Task.detached {+    Task {         tapCount += 1     } }

Task { に直してビルドが通ることを確認したら、RaceSample.swift は削除します。 最後に、完成状態でビルドとテストを実行し、シミュレータを止めます。
