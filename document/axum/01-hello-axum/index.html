Hello Axum: 最小の Web サーバーを起動する

  • ⏱ 所要時間: 30分
  • 📊 難易度: 入門
  • 👤 対象: Rust の基本文法は分かるが、Axum で Web サーバーを書くのは初めての人
  • 📋 前提: Rust の基本文法、cargo の基本操作（cargo new / cargo run）、ターミナルでの基本的なコマンド操作ができること。Rust ツールチェーンがインストール済みであること
  • 🔗 前提となる項目: なし（トラック最初の項目）

🎯 このレッスンで学ぶこと

  • cargo new でプロジェクトを作り、cargo add で axum と tokio を依存に追加する
  • GET / に文字列を返す最小の Axum サーバーを書いて起動する
  • curl でレスポンスを確認し、存在しないパスが 404 になることを確かめる
  • ルートを追加し、サーバーを再起動して反映させる
  • #[tokio::main] が必要な理由を、コンパイルエラーから確かめる
  • cargo build / cargo clippy / cargo fmt で仕上げの確認をする

概要

Axum トラックの最初の項目です。Rust の Web フレームワーク Axum を使い、127.0.0.1:3000 で待ち受けて文字列を返すだけの、最小の HTTP サーバーを作ります。 以降の項目は、ここで作るプロジェクトを出発点にして機能を足していきます。

ℹ️

使用バージョン

Rust（rustc）1.98.1 / cargo 1.98.1 / axum 0.8.9 / tokio 1.53.1（Rust edition 2024）で動作を確認しています。 バージョンは執筆時点（2026年9月）のものです。cargo add はその時点の最新版を追加するため、実行する時期によっては新しいバージョンが入り、出力の内容も多少変わります。

手順

1

cargo new でプロジェクトを作成する

作業用のディレクトリに移動し、cargo new でプロジェクトを作成します。ディレクトリ名は 01-hello-axum、パッケージ名は --name で hello-axum と指定します。

Terminal 
$ cargo new --name hello-axum 01-hello-axum    Creating binary (application) `hello-axum` packagenote: see more `Cargo.toml` keys and their definitions at https://doc.rust-lang.org/cargo/reference/manifest.html
💡

なぜ --name を付けるのか

cargo new は、何も指定しないとディレクトリ名をそのままパッケージ名にします。 このトラックではディレクトリ名に番号（01-）を付けますが、先頭が数字のパッケージ名はエラーになります。そこで --name でパッケージ名を別に指定しています。

生成された Cargo.toml と src/main.rs は次のとおりです。

TOML Cargo.toml 
[package]
name = "hello-axum"
version = "0.1.0"
edition = "2024"

[dependencies]
Rust src/main.rs 
fn main() {
    println!("Hello, world!");
}

プロジェクトのディレクトリに移動し、そのまま実行してみます。

Terminal 
$ cd 01-hello-axum$ cargo run   Compiling hello-axum v0.1.0 (/path/to/01-hello-axum)    Finished `dev` profile [unoptimized + debuginfo] target(s) in 2.45s     Running `target/debug/hello-axum`Hello, world!

✅ 確認ポイント

最後に Hello, world! と表示されれば成功です。以降のコマンドは全て 01-hello-axum ディレクトリで実行します。

2

axum と tokio を依存に追加する

cargo add で依存クレートを追加します。Axum 本体の axum と、非同期ランタイムの tokio の 2 つです。 まず axum を追加します。

Terminal 
$ cargo add axum    Updating crates.io index      Adding axum v0.8.9 to dependencies             Features:             + form             + http1             + json             + matched-path             + original-uri             + query             + tokio             + tower-log             + tracing             - __private             - __private_docs             - http2             - macros             - multipart             - ws    Updating crates.io index     Locking 52 packages to latest Rust 1.98.1 compatible versions      Adding atomic-waker v1.1.2      ...

出力の後半は、一緒に追加される依存クレートの一覧が続くため省略しています。続いて tokio を、必要なフィーチャーを指定して追加します。

Terminal 
$ cargo add tokio --features macros,net,rt-multi-thread    Updating crates.io index      Adding tokio v1.53.1 to dependencies             Features:             + libc             + macros             + net             + rt             + rt-multi-thread             + socket2             + tokio-macros             - bytes             - fs             - full             - io-std             - io-uring             - io-util             - mio             - parking_lot             - process             - schedule-latency             - signal             - signal-hook-registry             - sync             - taskdump             - test-util             - time             - tracing             - windows-sys

指定した 3 つのフィーチャーは、このレッスンのコードで次のように使います。

  • macros: #[tokio::main] アトリビュートを使うため
  • net: tokio::net::TcpListener でポートを待ち受けるため
  • rt-multi-thread: #[tokio::main] が起動するランタイムのため
ℹ️

net フィーチャーを明示する理由

axum の既定フィーチャー tokio が tokio の net も有効にするため、net を指定しなくてもビルドは通ります。ただし、このレッスンのコードでは tokio::net::TcpListener を直接使うので、自分のコードが使う機能として明示しておきます。

⚠️

rt-multi-thread を忘れるとコンパイルできない

rt-multi-thread を外すと、#[tokio::main] の行で次のコンパイルエラーになります。#[tokio::main] の既定はマルチスレッドランタイムなので、このフィーチャーが必要です。

Terminal 
error: The default runtime flavor is `multi_thread`, but the `rt-multi-thread` feature is disabled. --> src/main.rs:3:1

追加後の Cargo.toml は次のようになります。

TOML Cargo.toml 
[package]
name = "hello-axum"
version = "0.1.0"
edition = "2024"

[dependencies]
axum = "0.8.9"
tokio = { version = "1.53.1", features = ["macros", "net", "rt-multi-thread"] }

cargo tree --depth 1 を実行すると、直接の依存関係を確認できます。

Terminal 
$ cargo tree --depth 1hello-axum v0.1.0 (/path/to/01-hello-axum)├── axum v0.8.9└── tokio v1.53.1

✅ 確認ポイント

Cargo.toml の [dependencies] に axum と tokio が並んでいることを確認してください。tokio の features に "macros"・"net"・"rt-multi-thread" の 3 つが入っていれば OK です。

3

最小のサーバーを書いて起動する

src/main.rs の中身を全て次の内容に置き換えます。127.0.0.1:3000 で待ち受け、GET / に Hello, Axum! という文字列を返すサーバーです。

Rust src/main.rs 
use axum::{routing::get, Router};

#[tokio::main]
async fn main() {
    let app = Router::new().route("/", get(|| async { "Hello, Axum!" }));

    let listener = tokio::net::TcpListener::bind("127.0.0.1:3000")
        .await
        .unwrap();
    println!("listening on {}", listener.local_addr().unwrap());
    axum::serve(listener, app).await.unwrap();
}

コードの流れは次のとおりです。

  • Router::new().route("/", get(...)): パス / への GET リクエストに、"Hello, Axum!" を返す非同期クロージャを割り当てます。
  • tokio::net::TcpListener::bind("127.0.0.1:3000"): ポート 3000 で接続を待ち受けます。
  • println!: 待ち受けているアドレスを表示します。
  • axum::serve(listener, app): 待ち受けたポートでリクエストを受け付け、app のルートに振り分けます。

保存したら、サーバーを起動します。

Terminal 
$ cargo run   Compiling itoa v1.0.18   ...   Compiling hyper v1.11.1   Compiling tower v0.5.3   Compiling hyper-util v0.1.21   Compiling axum v0.8.9   Compiling hello-axum v0.1.0 (/path/to/01-hello-axum)    Finished `dev` profile [unoptimized + debuginfo] target(s) in 7.60s     Running `target/debug/hello-axum`listening on 127.0.0.1:3000

初回は axum と tokio に関連する 50 個以上の依存クレートを全てコンパイルするため、完了まで数秒から十数秒かかります（出力の途中は省略しています）。 2 回目以降はコンパイル済みの結果が再利用されるので速くなります。 サーバーは起動したまま止まらないので、このターミナルは開いたままにしておいてください。

✅ 確認ポイント

ターミナルの最後に listening on 127.0.0.1:3000 と表示され、プロンプトへ戻らず待ち受けを続けていれば成功です。

4

curl でレスポンスを確認する

サーバーを動かしたまま別のターミナルを開き、curl -i でリクエストを送ります。-i を付けると、本文に加えてレスポンスヘッダーも表示されます。

Terminal（2 つ目） 
$ curl -i http://127.0.0.1:3000/HTTP/1.1 200 OKcontent-type: text/plain; charset=utf-8content-length: 12date: Fri, 25 Sep 2026 15:46:43 GMTHello, Axum!

本文はハンドラの返した文字列そのもので、content-type は text/plain; charset=utf-8 です。date の値は実行した日時によって変わります。

次に、ルートを登録していないパスにリクエストを送ってみます。

Terminal（2 つ目） 
$ curl -i http://127.0.0.1:3000/fooHTTP/1.1 404 Not Foundcontent-length: 0date: Fri, 25 Sep 2026 15:46:43 GMT
ℹ️

404 の本文は空

ルートにないパスへのリクエストには、Axum が既定で 404 Not Found を返します。このとき本文は空（content-length: 0）なので、curl にはヘッダーだけが表示されます。

✅ 確認ポイント

/ で 200 OK と Hello, Axum!、/foo で 404 Not Found が返れば OK です。

5

/health ルートを追加して再起動する

動作確認用のエンドポイント GET /health を追加し、ok を返すようにします。 まず、サーバーを起動しているターミナルで Ctrl + C を押してサーバーを止めてください。 そのうえで、src/main.rs の let app = ... の部分を次のように書き換えます。

Diff src/main.rs 
-     let app = Router::new().route("/", get(|| async { "Hello, Axum!" }));+     let app = Router::new()+         .route("/", get(|| async { "Hello, Axum!" }))+         .route("/health", get(|| async { "ok" }));

.route(...) をつなげて書くと、ルートをいくつでも追加できます。変更後の src/main.rs の全体は次のとおりです。

Rust src/main.rs 
use axum::{routing::get, Router};

#[tokio::main]
async fn main() {
    let app = Router::new()
        .route("/", get(|| async { "Hello, Axum!" }))
        .route("/health", get(|| async { "ok" }));

    let listener = tokio::net::TcpListener::bind("127.0.0.1:3000")
        .await
        .unwrap();
    println!("listening on {}", listener.local_addr().unwrap());
    axum::serve(listener, app).await.unwrap();
}

保存したら、もう一度サーバーを起動します。今回は hello-axum だけがコンパイルされるので、すぐに起動します。

Terminal 
$ cargo run   Compiling hello-axum v0.1.0 (/path/to/01-hello-axum)    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.43s     Running `target/debug/hello-axum`listening on 127.0.0.1:3000

2 つ目のターミナルから、/ と /health にリクエストを送ります。

Terminal（2 つ目） 
$ curl -i http://127.0.0.1:3000/HTTP/1.1 200 OKcontent-type: text/plain; charset=utf-8content-length: 12date: Fri, 25 Sep 2026 15:47:08 GMTHello, Axum!$ curl -i http://127.0.0.1:3000/healthHTTP/1.1 200 OKcontent-type: text/plain; charset=utf-8content-length: 2date: Fri, 25 Sep 2026 15:47:08 GMTok
⚠️

コードを変えたら再起動が必要

cargo run で起動したサーバーは、ソースコードを保存しても自動では変更を反映しません。ルートを追加したら、サーバーを止めて cargo run し直してください。

✅ 確認ポイント

/health で 200 OK と ok が返り、/ も引き続き Hello, Axum! を返せば成功です。確認できたら、サーバーを Ctrl + C で止めておきます。

6

#[tokio::main] を外してエラーを確かめる

main 関数に付けた #[tokio::main] の役割を、あえて外してみることで確かめます。 サーバーを止めた状態で、src/main.rs から次の 1 行を一時的に削除してください。

Diff src/main.rs 
  use axum::{routing::get, Router}; - #[tokio::main]  async fn main() {

この状態でビルドします。

Terminal 
$ cargo build   Compiling hello-axum v0.1.0 (/path/to/01-hello-axum)error[E0752]: `main` function is not allowed to be `async` --> src/main.rs:3:1  |3 | async fn main() {  | ^^^^^^^^^^^^^^^ `main` function is not allowed to be `async`For more information about this error, try `rustc --explain E0752`.error: could not compile `hello-axum` (bin "hello-axum") due to 1 previous error
⚠️

main 関数は標準では async にできない

エラー E0752 は、Axum や tokio ではなく Rust 言語自体が出すエラーです。Rust の main 関数は、そのままでは async fn にできません。 #[tokio::main] は、async fn main を通常の main 関数で包み、tokio の非同期ランタイムを起動してから中身を実行するコードに展開するマクロです。 これにより、main の中で .await を使えるようになります。

確認できたら、削除した #[tokio::main] を元に戻してください。

✅ 確認ポイント

#[tokio::main] を外すと error[E0752] になり、戻すとビルドが通ることを確認してください。

7

ビルド・Lint・フォーマットを確認する

仕上げに、ビルドと静的解析（Clippy）がエラーや警告なく通ることを確認します。

Terminal 
$ cargo build   Compiling hello-axum v0.1.0 (/path/to/01-hello-axum)    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.28s$ cargo clippy   ...    Checking hello-axum v0.1.0 (/path/to/01-hello-axum)    Finished `dev` profile [unoptimized + debuginfo] target(s) in 3.03s

続いて、cargo fmt --check でコードの書式を確認します。--check を付けると、ファイルを書き換えずに差分だけを表示します。

Terminal 
$ cargo fmt --checkDiff in /path/to/01-hello-axum/src/main.rs:1:-use axum::{routing::get, Router};+use axum::{Router, routing::get}; #[tokio::main] async fn main() {

use 文の中の並び順に差分が出ました。 この並び順は cargo fmt の既定ルールで決まるので、手で直す必要はありません。cargo fmt を実行すると自動で整形されます。 整形後にもう一度 cargo fmt --check を実行し、何も表示されなければ OK です。

Terminal 
$ cargo fmt$ cargo fmt --check

完成した src/main.rs は次のとおりです。

Rust src/main.rs 
use axum::{Router, routing::get};

#[tokio::main]
async fn main() {
    let app = Router::new()
        .route("/", get(|| async { "Hello, Axum!" }))
        .route("/health", get(|| async { "ok" }));

    let listener = tokio::net::TcpListener::bind("127.0.0.1:3000")
        .await
        .unwrap();
    println!("listening on {}", listener.local_addr().unwrap());
    axum::serve(listener, app).await.unwrap();
}
ℹ️

target/ と .gitignore について

ビルド結果は target/ に出力されます。target/ は Git にコミットしません。 このリポジトリでは、ルートの .gitignore に **/target/ を書いて除外しています。既存の Git リポジトリの中で実行した cargo new は、プロジェクト内に .gitignore を作りません。 Git 管理外のディレクトリで単独のプロジェクトとして作った場合は、cargo new が target/ を除外する .gitignore を生成します。

✅ 確認ポイント

cargo build と cargo clippy がエラーや警告を出さずに終わり、cargo fmt --check が何も表示しなければ完成です。

演習

以下のチェックリストを使って、このレッスンの内容を振り返りましょう。

つまずきポイント

💡

ポート 3000 が使用中の場合

別の開発サーバーなどがポート 3000 を使っていると、TcpListener::bind が失敗し、unwrap() によって次のように panic します（macOS での出力例です）。

Terminal 
thread 'main' (12345) panicked at src/main.rs:9:10:called `Result::unwrap()` on an `Err` value: Os { code: 48, kind: AddrInUse, message: "Address already in use" }

lsof -nP -i :3000 で使用中のプロセスを確認して止めるか、src/main.rs の "127.0.0.1:3000" を空いているポート番号に変えてください。

💡

前回のサーバーが残っている

サーバーを止め忘れたまま別のターミナルで cargo run すると、ポート 3000 が使用中の状態になります。ステップ 5 以降で再起動するときは、前のサーバーを Ctrl + C で確実に止めてから起動してください。

まとめ

cargo new と cargo add でプロジェクトを用意し、Router にルートを登録して axum::serve で起動する、最小の Axum サーバーを作りました。 あわせて、#[tokio::main] が async fn main を動かすために必要なことも確かめました。 次の項目では、ルーティングとハンドラについて学び、複数のエンドポイントやパスパラメーターを扱えるようにします。
