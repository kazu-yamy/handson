プロジェクト構成と設定の外部化

  • ⏱ 所要時間: 60分
  • 📊 難易度: 初級
  • 👤 対象: 06 で users の API を作り終え、1 つのファイルにまとまったコードを整理して、ポートや API キーをコードの外から渡せるようにしたい人
  • 📋 前提: Rust の基本文法（モジュールと pub・トレイトの実装・Result と ? 演算子）、cargo と curl の基本操作
  • 🔗 前提となる項目: 06: エラーハンドリングとバリデーション

🎯 このレッスンで学ぶこと

  • Cargo.toml の [lib] と [[bin]] で、ライブラリ名 app と実行ファイル名 server を決める
  • main.rs 1 つにまとまったコードを、lib.rs と役割ごとのモジュールに分割する
  • エラーの JSON を {"error":{"code","message","fields"}} の形にそろえる
  • ポート・DB の URL・API キーを、環境変数と .env ファイルから読み込む
  • 必須の設定が無いときや値が不正なときに、起動の時点でエラー終了させる
  • .env をコミットせず、見本の .env.example だけをコミットする

概要

07 からは、06 までに作った users の API を、実務で使う API サーバー「Handson Blog API」に少しずつ育てていきます。 最初のこの項目では機能を増やしません。コードの置き場所と設定の読み方を整え、この先の項目でコードを足しやすい土台を作ります。

06 の完成コードは、234 行が src/main.rs 1 つに入っています。 また、待ち受けるポート 3000 と API キー secret がコードに直接書かれています。 このレッスンでは、コードを役割ごとのファイルに分け、設定を環境変数から読むように変えます。 あわせて、02 で作った練習用のルートを片付け、エラーの JSON をより細かい形にそろえます。

項目0607
コードの置き場所src/main.rs だけsrc/lib.rs と config・state・error・middleware・routes の各モジュール
待ち受けるアドレス127.0.0.1:3000（直書き）APP_HOST・APP_PORT（既定は 127.0.0.1:8080）
DB の URLsqlite://app.db?mode=rwc（直書き）DATABASE_URL（既定は同じ値）
API キーsecret（直書き）API_KEY（必須。既定値なし）
エラーの本文{"error":"user not found"}{"error":{"code":"not_found","message":"user not found"}}
401 の本文text/plain のメッセージほかのエラーと同じ形の JSON
練習用のルート（GET /・/users/{user_id}/posts/{post_id}・/search）あり削除

既定のポートを 3000 から 8080 に変えるのは、Next.js の開発サーバー（3000）と同時に起動しても衝突しないようにするためです。

ℹ️

Rust src/main.rs 
use app::{build_app, state::AppState};
use sqlx::SqlitePool;

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    let pool = SqlitePool::connect("sqlite://app.db?mode=rwc").await?;

    sqlx::migrate!().run(&pool).await?;

    let app = build_app(AppState { pool });

    let listener = tokio::net::TcpListener::bind("127.0.0.1:3000").await?;
    println!("listening on {}", listener.local_addr()?);
    axum::serve(listener, app).await?;
    Ok(())
}
  • main.rs は実行ファイル server の入口で、lib.rs とは別のクレートとしてコンパイルされます。そのため、use app::... でライブラリを参照します。
  • main.rs には mod error; などを書きません。書くと、同じモジュールがライブラリと実行ファイルの両方に入ってしまいます。
  • main の戻り値を Result<(), Box<dyn std::error::Error>> にし、06 の .unwrap() を ? に置き換えました。失敗したときの表示はステップ 7 で確かめます。

use axum::{
    Json,
    extract::rejection::JsonRejection,
    http::StatusCode,
    response::{IntoResponse, Response},
};
use serde_json::json;

pub enum AppError {
    NotFound,
    Validation(String),
    Database(sqlx::Error),
    JsonRejection(JsonRejection),
}

impl IntoResponse for AppError {
    fn into_response(self) -> Response {
        let (status, message) = match self {
            AppError::NotFound => (StatusCode::NOT_FOUND, "user not found".to_string()),
            AppError::Validation(message) => (StatusCode::UNPROCESSABLE_ENTITY, message),
            AppError::Database(error) => {
                eprintln!("database error: {error}");
                (
                    StatusCode::INTERNAL_SERVER_ERROR,
                    "internal server error".to_string(),
                )
            }
            AppError::JsonRejection(rejection) => (rejection.status(), rejection.body_text()),
        };
        (status, Json(json!({ "error": message }))).into_response()
    }
}

impl From<sqlx::Error> for AppError {
    fn from(error: sqlx::Error) -> Self {
        AppError::Database(error)
    }
}

impl From<JsonRejection> for AppError {
    fn from(rejection: JsonRejection) -> Self {
        AppError::JsonRejection(rejection)
    }
}

use axum::{
    extract::Request,
    http::StatusCode,
    middleware::Next,
    response::{IntoResponse, Response},
};
use std::time::Instant;

pub async fn log_request(req: Request, next: Next) -> Response {
    let method = req.method().clone();
    let uri = req.uri().clone();
    let start = Instant::now();

    let response = next.run(req).await;

    let elapsed = start.elapsed();
    println!("{method} {uri} -> {} ({elapsed:?})", response.status());
    response
}

pub async fn require_api_key(req: Request, next: Next) -> Response {
    let is_valid = req
        .headers()
        .get("x-api-key")
        .and_then(|value| value.to_str().ok())
        == Some("secret");

    if !is_valid {
        return (StatusCode::UNAUTHORIZED, "invalid or missing x-api-key").into_response();
    }

    next.run(req).await
}

pub mod users;

use axum::{
    Extension, Router,
    middleware::{self},
    routing::{get, post, put},
};

use crate::middleware::{log_request, require_api_key};
use crate::state::AppState;

#[derive(Clone)]
pub struct AppConfig {
    pub app_name: String,
}

pub fn router(state: AppState) -> Router {
    let protected_users = Router::new()
        .route("/users", post(users::create_user))
        .route(
            "/users/{id}",
            put(users::update_user).delete(users::delete_user),
        )
        .route_layer(middleware::from_fn(require_api_key));

    Router::new()
        .route("/", get(misc::root))
        .route("/health", get(health::health))
        .route("/users", get(users::list_users))
        .route("/users/{id}", get(users::get_user))
        .merge(protected_users)
        .route("/users/{user_id}/posts/{post_id}", get(misc::get_user_post))
        .route("/search", get(misc::search))
        .fallback(misc::not_found)
        .layer(Extension(AppConfig {
            app_name: "Handson Axum".to_string(),
        }))
        .layer(middleware::from_fn(log_request))
        .with_state(state)
}

Rust src/routes/users.rs 
use axum::{
    Json,
    extract::{Path, State, rejection::JsonRejection},
    http::StatusCode,
};
use serde::{Deserialize, Serialize};

use crate::error::AppError;
use crate::state::AppState;

#[derive(Clone, Serialize, sqlx::FromRow)]
pub struct User {
    id: i64,
    name: String,
}

#[derive(Deserialize)]
pub struct CreateUser {
    name: String,
}

impl CreateUser {
    fn validate(&self) -> Result<(), AppError> {
        let name = self.name.trim();
        if name.is_empty() {
            return Err(AppError::Validation("name must not be empty".to_string()));
        }
        if name.chars().count() > 50 {
            return Err(AppError::Validation(
                "name must be 50 characters or less".to_string(),
            ));
        }
        Ok(())
    }
}

pub async fn list_users(State(state): State<AppState>) -> Result<Json<Vec<User>>, AppError> {
    let users = sqlx::query_as::<_, User>("SELECT id, name FROM users ORDER BY id")
        .fetch_all(&state.pool)
        .await?;
    Ok(Json(users))
}

pub async fn create_user(
    State(state): State<AppState>,
    payload: Result<Json<CreateUser>, JsonRejection>,
) -> Result<(StatusCode, Json<User>), AppError> {
    let Json(payload) = payload?;
    payload.validate()?;
    let user = sqlx::query_as::<_, User>("INSERT INTO users (name) VALUES (?) RETURNING id, name")
        .bind(&payload.name)
        .fetch_one(&state.pool)
        .await?;
    Ok((StatusCode::CREATED, Json(user)))
}

pub async fn get_user(
    State(state): State<AppState>,
    Path(id): Path<i64>,
) -> Result<Json<User>, AppError> {
    let user = sqlx::query_as::<_, User>("SELECT id, name FROM users WHERE id = ?")
        .bind(id)
        .fetch_optional(&state.pool)
        .await?;
    user.map(Json).ok_or(AppError::NotFound)
}

pub async fn update_user(
    State(state): State<AppState>,
    Path(id): Path<i64>,
    payload: Result<Json<CreateUser>, JsonRejection>,
) -> Result<Json<User>, AppError> {
    let Json(payload) = payload?;
    payload.validate()?;
    let user =
        sqlx::query_as::<_, User>("UPDATE users SET name = ? WHERE id = ? RETURNING id, name")
            .bind(&payload.name)
            .bind(id)
            .fetch_optional(&state.pool)
            .await?;
    user.map(Json).ok_or(AppError::NotFound)
}

pub async fn delete_user(
    State(state): State<AppState>,
    Path(id): Path<i64>,
) -> Result<StatusCode, AppError> {
    let result = sqlx::query("DELETE FROM users WHERE id = ?")
        .bind(id)
        .execute(&state.pool)
        .await?;
    if result.rows_affected() == 0 {
        Err(AppError::NotFound)
    } else {
        Ok(StatusCode::NO_CONTENT)
    }
}

エラーの JSON の形をそろえる

06 のエラーの本文は {"error":"user not found"} のように、メッセージの文字列だけでした。これを次の形にそろえます。この形は、後の項目で API を呼び出す Next.js 側と合わせたものです。

JSON 
{"error":{"code":"validation_failed","message":"invalid request","fields":{"name":["name must not be empty"]}}}
  • code: エラーの種類を表す固定の文字列です。クライアントはメッセージではなく、この値で分岐します。
  • message: 人が読むための説明です。
  • fields: 入力の検証エラー（422）のときだけ付けます。「フィールド名 → 文言の配列」の形です。

このレッスンで使う code とステータスの対応は次のとおりです。

codeステータス返す場面
bad_request400JSON の構文エラー
unauthorized401API キーが無い・違う
not_found404ユーザーがいない、どのルートにもマッチしない
payload_too_large413本文が大きすぎる（Json extractor の拒否）
unsupported_media_type415content-type が JSON でない
validation_failed422入力の検証エラー、JSON の型の不一致
internal500DB の操作に失敗した

src/error.rs を次の内容に置き換えます。

Rust src/error.rs 
use axum::{
    Json,
    extract::rejection::JsonRejection,
    http::StatusCode,
    response::{IntoResponse, Response},
};
use serde::Serialize;
use std::collections::BTreeMap;

#[derive(Serialize)]
pub struct ErrorBody {
    pub error: ErrorDetail,
}

#[derive(Serialize)]
pub struct ErrorDetail {
    pub code: &'static str,
    pub message: String,
    #[serde(skip_serializing_if = "Option::is_none")]
    pub fields: Option<BTreeMap<String, Vec<String>>>,
}

pub fn error_response(
    status: StatusCode,
    code: &'static str,
    message: impl Into<String>,
) -> Response {
    let body = ErrorBody {
        error: ErrorDetail {
            code,
            message: message.into(),
            fields: None,
        },
    };
    (status, Json(body)).into_response()
}

pub enum AppError {
    NotFound,
    Validation(BTreeMap<String, Vec<String>>),
    Database(sqlx::Error),
    JsonRejection(JsonRejection),
}

impl AppError {
    pub fn field(name: &str, message: &str) -> Self {
        AppError::Validation(BTreeMap::from([(
            name.to_string(),
            vec![message.to_string()],
        )]))
    }
}

impl IntoResponse for AppError {
    fn into_response(self) -> Response {
        match self {
            AppError::NotFound => {
                error_response(StatusCode::NOT_FOUND, "not_found", "user not found")
            }
            AppError::Validation(fields) => {
                let body = ErrorBody {
                    error: ErrorDetail {
                        code: "validation_failed",
                        message: "invalid request".to_string(),
                        fields: Some(fields),
                    },
                };
                (StatusCode::UNPROCESSABLE_ENTITY, Json(body)).into_response()
            }
            AppError::Database(error) => {
                eprintln!("database error: {error}");
                error_response(
                    StatusCode::INTERNAL_SERVER_ERROR,
                    "internal",
                    "internal server error",
                )
            }
            AppError::JsonRejection(rejection) => {
                let status = rejection.status();
                let code = match status {
                    StatusCode::UNPROCESSABLE_ENTITY => "validation_failed",
                    StatusCode::UNSUPPORTED_MEDIA_TYPE => "unsupported_media_type",
                    StatusCode::PAYLOAD_TOO_LARGE => "payload_too_large",
                    _ => "bad_request",
                };
                error_response(status, code, rejection.body_text())
            }
        }
    }
}

impl From<sqlx::Error> for AppError {
    fn from(error: sqlx::Error) -> Self {
        AppError::Database(error)
    }
}

impl From<JsonRejection> for AppError {
    fn from(rejection: JsonRejection) -> Self {
        AppError::JsonRejection(rejection)
    }
}
  • ErrorBody・ErrorDetail: 本文の形を #[derive(Serialize)] の構造体で定義します。json! で組み立てる場所があちこちにあると、形を変えるときに直し漏れが出ます。構造体にしておけば、形は 1 か所で決まります。
  • #[serde(skip_serializing_if = "Option::is_none")]: fields が None のときは、キーごと出力しません。
  • error_response: ステータス・code・message から応答を作る共通の関数です。AppError を通らない 401 と fallback の 404 でも、この関数を使います。
  • Validation は文字列ではなく BTreeMap<String, Vec<String>>（フィールド名 → 文言の配列）を持ちます。HashMap ではなく BTreeMap にしたのは、出力するキーの順序を安定させるためです。
  • AppError::field: 1 つのフィールドに 1 つの文言を持つ Validation を作る補助関数です。
  • JsonRejection は、拒否のステータスから code を決めます。message は axum が返す文言（body_text()）のままです。

ポート・DB の URL・API キーを、環境変数から読むようにします。設定は Config という構造体にまとめ、起動時に 1 回だけ読み込みます。読み込む環境変数は次の 4 つです。

環境変数既定値内容

DATABASE_URLsqlite://app.db?mode=rwcDB の接続先

src/config.rs を新しく作ります。

Rust src/config.rs 
use std::env;
use std::fmt;

pub struct Config {
    pub host: String,
    pub port: u16,
    pub database_url: String,
    pub api_key: String,
}

#[derive(Debug)]
pub enum ConfigError {
    Missing(&'static str),
    Invalid(&'static str, String),
}

impl fmt::Display for ConfigError {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        match self {
            ConfigError::Missing(name) => write!(f, "{name} must be set"),
            ConfigError::Invalid(name, value) => write!(f, "{name} is invalid: {value:?}"),
        }
    }
}

impl std::error::Error for ConfigError {}

impl Config {
    pub fn from_env() -> Result<Config, ConfigError> {
        let host = env::var("APP_HOST").unwrap_or_else(|_| "127.0.0.1".to_string());
        let port = match env::var("APP_PORT") {
            Ok(value) => value
                .parse()
                .map_err(|_| ConfigError::Invalid("APP_PORT", value))?,
            Err(_) => 8080,
        };
        let database_url =
            env::var("DATABASE_URL").unwrap_or_else(|_| "sqlite://app.db?mode=rwc".to_string());
        let api_key = env::var("API_KEY")
            .ok()
            .filter(|value| !value.is_empty())
            .ok_or(ConfigError::Missing("API_KEY"))?;

        Ok(Config {
            host,
            port,
            database_url,
            api_key,
        })
    }
}

impl fmt::Debug for Config {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        f.debug_struct("Config")
            .field("host", &self.host)
            .field("port", &self.port)
            .field("database_url", &self.database_url)
            .field("api_key", &"***")
            .finish()
    }
}
  • env::var は環境変数を読み、無ければ Err を返します。APP_HOST と DATABASE_URL は、無ければ unwrap_or_else で既定値を使います。
  • APP_PORT は parse() で u16 に変換し、失敗したら ConfigError::Invalid を返します。
  • API_KEY には既定値を持たせません。無いときと空文字のときは ConfigError::Missing を返し、サーバーを起動させません。
  • Config の Debug は derive せず、手で実装します。api_key は値の代わりに "***" を出力するので、{config:?} でログに出しても秘密が漏れません。

  • main が Err を返すと、Rust はエラーを Error: に続けて Debug 形式で表示し、終了コード 1 で終了します。
  • ConfigError は #[derive(Debug)] なので、Missing("API_KEY") とバリアント名がそのまま出ます。原因は分かりますが、読みやすくはありません。

ConfigError の Debug を手で実装し、Display と同じ文言を出すようにします。#[derive(Debug)] を外し、impl fmt::Debug を追加します。

演習

以下のチェックリストを使って、このレッスンの内容を振り返りましょう。

つまずきポイント

💡

main.rs にも mod を書いてしまう

main.rs に mod error; などを書くと、同じモジュールがライブラリと実行ファイルの両方に入ります。mod の宣言は lib.rs にだけ書き、main.rs は use app::... で参照してください（ステップ 2 を参照）。

💡

ほかのモジュールの関数や型が見つからない

ほかのモジュールから使う関数・型・モジュールには pub が必要です。pub を付け忘れていないか、use crate::... のパスが合っているかを確認してください。

💡

require_api_key を変えたらビルドが失敗する

State を受け取るミドルウェアは、middleware::from_fn_with_state(state.clone(), require_api_key) で登録します。from_fn のままだとコンパイルエラーになります（ステップ 5 を参照）。

💡

.env を書いたのに API_KEY must be set になる

.env は、起動したときのカレントディレクトリから親ディレクトリへさかのぼって探されます。07-project-structure ディレクトリで起動しているか確認してください。また、API_KEY= のように空の環境変数を設定していると、.env の値より優先されます。

💡

.env を書き換えても値が変わらない

実際の環境変数は .env より優先されます。シェルで export APP_PORT=... などを実行したままになっていないか、env | grep APP_ で確認してください。

💡

curl の結果が教材と違う

前のステップの app.db が残っていると、ユーザーの一覧や id が教材と変わります。rm -f app.db* で DB ファイルを消してから起動してください。また、.env の API_KEY と curl の x-api-key が一致しているかも確認してください。

💡

.env.example が git status に出ない

ルートの .gitignore の **/.env* に巻き込まれています。プロジェクトの .gitignore に !.env.example を追加してください（ステップ 8 を参照）。

まとめ

[lib] と [[bin]] を使い、ライブラリ app を実行ファイル server から分け、main.rs 1 つにあったコードを役割ごとのモジュールに移しました。 main.rs は、設定を読んで DB に接続し、build_app で作ったアプリを起動するだけになりました。 エラーの本文は {"error":{"code","message","fields"}} にそろえ、401 と fallback の 404 も同じ形で返します。 ポート・DB の URL・API キーは Config::from_env で環境変数と .env から読み、必須の API_KEY が無ければ起動時にエラーで止まります。
