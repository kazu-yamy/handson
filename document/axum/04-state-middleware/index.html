共有状態とミドルウェア

  • ⏱ 所要時間: 45分
  • 📊 難易度: 入門
  • 👤 対象: 03 で JSON の API を作れるようになり、次にリクエストをまたいでデータを保持したり、共通の処理を差し込んだりしたい人
  • 📋 前提: Rust の基本文法（構造体・Option / Result・クロージャー）、cargo run と curl の基本操作ができること、Arc / Mutex を知っていること
  • 🔗 前提となる項目: 03: JSON リクエスト/レスポンス

🎯 このレッスンで学ぶこと

  • State と with_state で、全ハンドラから読み書きできる共有状態（Arc<Mutex<...>>）を持つ
  • Extension で設定値をハンドラへ渡し、付け忘れると実行時エラー（500）になることを確かめる
  • middleware::from_fn で、全リクエストのログを出すミドルウェアを書く
  • route_layer と merge で、一部のルートにだけ API キー認証を掛ける
  • with_state を書き忘れるとコンパイルエラーになることを確かめ、Extension との違いを説明できるようになる

概要

03 の API は、POST /users でユーザーを作っても保存されず、GET /users は常に同じ 2 件を返していました。 このレッスンでは、axum の State を使ってユーザーの一覧をメモリー上に持ち、全てのハンドラから読み書きできるようにします。 また、設定値を Extension で渡す方法と、ハンドラの前後に共通の処理を差し込むミドルウェアの書き方を学びます。

このレッスンの完成時には、サーバーが次のルートへ応答します。03 から変わったところを太字にしています。ミドルウェアの列は、そのルートに掛かるミドルウェアです。

メソッドパス返す内容ミドルウェア
GET/Extension の設定値を使った Hello from Handson Axumログ
GET/healthJSON {"status":"ok"}ログ
GET/users共有状態に保存されているユーザーの JSON 配列ログ
POST/users共有状態にユーザーを追加し、201 と作成したユーザーの JSONログ + API キー認証
GET/users/{id}共有状態から探したユーザーの JSON（なければ 404）ログ
PUT/users/{id}共有状態のユーザーの名前を更新し、更新後の JSON（なければ 404）ログ + API キー認証
GET/users/{user_id}/posts/{post_id}user {user_id} post {post_id}ログ
GET/search受け取ったクエリパラメーターの一覧ログ
（上記以外）どれにもマッチしないパス404 と本文 Not Foundログ

2

ユーザーの一覧をサーバーのメモリー上に持ち、ハンドラから読めるようにします。 axum では、アプリ全体で共有したい値を構造体にまとめて Router に渡し、ハンドラでは State extractor で受け取ります。 src/main.rs を次のように変更してください。

  • AppState 構造体: 共有状態をまとめる構造体です。ユーザーの一覧 Vec<User> を Mutex で包んで複数のリクエストから安全に読み書きできるようにし、さらに Arc で包んで複数の場所から同じデータを指せるようにしています。#[derive(Clone)] を付けても、複製されるのは Arc（参照）だけで、中の Vec は 1 つのままです。

  • User: users.clone() で Vec<User> を複製するために、#[derive(Clone)] を追加します。
ℹ️

tokio の Mutex ではなく std の Mutex を使う理由

ここで使っている Mutex は標準ライブラリの std::sync::Mutex です。このレッスンのハンドラは、ロックを持っている間（Vec を読み書きする間）に .await を挟みません。そのため非同期用の tokio::sync::Mutex は不要で、軽量でロックの取得も同期的に終わる std::sync::Mutex を選んでいます。

変更後の src/main.rs 全体を見る
Rust src/main.rs 
use axum::{
    Json, Router,
    extract::{Path, Query, State},
    http::StatusCode,
    routing::get,
};
use serde::{Deserialize, Serialize};
use serde_json::json;
use std::collections::HashMap;
use std::sync::{Arc, Mutex};

#[derive(Clone, Serialize)]
struct User {
    id: u32,
    name: String,
}

#[derive(Deserialize)]
struct CreateUser {
    name: String,
}

#[derive(Clone)]
struct AppState {
    users: Arc<Mutex<Vec<User>>>,
}

#[tokio::main]
async fn main() {
    let state = AppState {
        users: Arc::new(Mutex::new(vec![
            User {
                id: 1,
                name: "alice".to_string(),
            },
            User {
                id: 2,
                name: "bob".to_string(),
            },
        ])),
    };

    let app = Router::new()
        .route("/", get(root))
        .route("/health", get(health))
        .route("/users", get(list_users).post(create_user))
        .route("/users/{id}", get(get_user).put(update_user))
        .route("/users/{user_id}/posts/{post_id}", get(get_user_post))
        .route("/search", get(search))
        .fallback(not_found)
        .with_state(state);

    let listener = tokio::net::TcpListener::bind("127.0.0.1:3000")
        .await
        .unwrap();
    println!("listening on {}", listener.local_addr().unwrap());
    axum::serve(listener, app).await.unwrap();
}

async fn root() -> &'static str {
    "Hello, Axum!"
}

async fn health() -> Json<serde_json::Value> {
    Json(json!({ "status": "ok" }))
}

async fn list_users(State(state): State<AppState>) -> Json<Vec<User>> {
    let users = state.users.lock().unwrap();
    Json(users.clone())
}

async fn create_user(Json(payload): Json<CreateUser>) -> (StatusCode, Json<User>) {
    let user = User {
        id: 1,
        name: payload.name,
    };
    (StatusCode::CREATED, Json(user))
}

async fn get_user(Path(id): Path<u32>) -> Json<User> {
    Json(User {
        id,
        name: "alice".to_string(),
    })
}

async fn update_user(Path(id): Path<u32>, Json(payload): Json<CreateUser>) -> Json<User> {
    Json(User {
        id,
        name: payload.name,
    })
}

async fn get_user_post(Path((user_id, post_id)): Path<(u32, u32)>) -> String {
    format!("user {user_id} post {post_id}")
}

async fn search(Query(params): Query<HashMap<String, String>>) -> String {
    format!("search params: {params:?}")
}

async fn not_found() -> (StatusCode, &'static str) {
    (StatusCode::NOT_FOUND, "Not Found")
}

3

共有状態を更新する（POST /users、GET /users/{id}、PUT /users/{id}）

残りのユーザー関連のハンドラも、共有状態を使うように書き換えます。 POST /users は一覧に追加し、GET /users/{id} と PUT /users/{id} は一覧から id で探します。見つからなければ 404 を返します。

変更点は次の 3 つです。

  • create_user: State と Json を受け取ります。Json は 03 で確かめたとおり引数の最後に置きます。id は「今の件数 + 1」で決め、push で一覧に追加します。
  • get_user: 戻り値を Result<Json<User>, StatusCode> にします。見つかれば Ok(Json(...))、見つからなければ Err(StatusCode::NOT_FOUND) になり、axum はどちらもレスポンスに変換します。
  • update_user: iter_mut() で書き換え可能な参照を探し、見つからなければ ? で 404 を返して終わります。見つかったら名前を書き換え、clone() した値を返します。
ℹ️

id の決め方は簡易版

「今の件数 + 1」で id を決める方法は、削除がない前提でしか重複を防げません。このレッスンでは削除（DELETE）を扱わないのでこのままにしますが、本来は連番のカウンターや UUID を使います。

use axum::{
    Json, Router,
    extract::{Path, Query, State},
    http::StatusCode,
    routing::get,
};
use serde::{Deserialize, Serialize};
use serde_json::json;
use std::collections::HashMap;
use std::sync::{Arc, Mutex};

#[derive(Clone, Serialize)]
struct User {
    id: u32,
    name: String,
}

#[derive(Deserialize)]
struct CreateUser {
    name: String,
}

#[derive(Clone)]
struct AppState {
    users: Arc<Mutex<Vec<User>>>,
}

#[tokio::main]
async fn main() {
    let state = AppState {
        users: Arc::new(Mutex::new(vec![
            User {
                id: 1,
                name: "alice".to_string(),
            },
            User {
                id: 2,
                name: "bob".to_string(),
            },
        ])),
    };

    let app = Router::new()
        .route("/", get(root))
        .route("/health", get(health))
        .route("/users", get(list_users).post(create_user))
        .route("/users/{id}", get(get_user).put(update_user))
        .route("/users/{user_id}/posts/{post_id}", get(get_user_post))
        .route("/search", get(search))

async fn root() -> &'static str {
    "Hello, Axum!"
}

async fn health() -> Json<serde_json::Value> {
    Json(json!({ "status": "ok" }))
}

async fn list_users(State(state): State<AppState>) -> Json<Vec<User>> {
    let users = state.users.lock().unwrap();
    Json(users.clone())
}

async fn create_user(
    State(state): State<AppState>,
    Json(payload): Json<CreateUser>,
) -> (StatusCode, Json<User>) {
    let mut users = state.users.lock().unwrap();
    let user = User {
        id: users.len() as u32 + 1,
        name: payload.name,
    };
    users.push(user.clone());
    (StatusCode::CREATED, Json(user))
}

async fn get_user(
    State(state): State<AppState>,
    Path(id): Path<u32>,
) -> Result<Json<User>, StatusCode> {
    let users = state.users.lock().unwrap();
    users
        .iter()
        .find(|user| user.id == id)
        .cloned()
        .map(Json)
        .ok_or(StatusCode::NOT_FOUND)
}

async fn update_user(
    State(state): State<AppState>,
    Path(id): Path<u32>,
    Json(payload): Json<CreateUser>,
) -> Result<Json<User>, StatusCode> {
    let mut users = state.users.lock().unwrap();
    let user = users
        .iter_mut()
        .find(|user| user.id == id)
        .ok_or(StatusCode::NOT_FOUND)?;
    user.name = payload.name;
    Ok(Json(user.clone()))
}

async fn get_user_post(Path((user_id, post_id)): Path<(u32, u32)>) -> String {
    format!("user {user_id} post {post_id}")
}

async fn search(Query(params): Query<HashMap<String, String>>) -> String {
    format!("search params: {params:?}")
}

async fn not_found() -> (StatusCode, &'static str) {
    (StatusCode::NOT_FOUND, "Not Found")
}

Extension で設定値を渡す（GET /）

共有したい値を渡すもう 1 つの方法が Extension です。Router に .layer(Extension(値)) で値を追加し、ハンドラでは Extension extractor で受け取ります。 ここでは、アプリ名を持つ設定 AppConfig を渡し、GET / がその名前を返すようにします。

use axum::{
    Extension, Json, Router,
    extract::{Path, Query, State},
    http::StatusCode,
    routing::get,
};
use serde::{Deserialize, Serialize};
use serde_json::json;
use std::collections::HashMap;
use std::sync::{Arc, Mutex};

#[derive(Clone, Serialize)]
struct User {
    id: u32,
    name: String,
}

#[derive(Deserialize)]
struct CreateUser {
    name: String,
}

#[derive(Clone)]
struct AppState {
    users: Arc<Mutex<Vec<User>>>,
}

struct AppConfig {
    app_name: String,
}

リクエストログのミドルウェアを全ルートに掛ける

ミドルウェアは、ハンドラの前後に共通の処理を差し込む仕組みです。 axum では middleware::from_fn を使うと、普通の async fn をミドルウェアにできます。 ここでは、全てのリクエストについてメソッド・URI・ステータス・処理時間を標準出力に出すミドルウェア log_request を作ります。

次は、データを変更する POST /users と PUT /users/{id} にだけ、簡単な API キー認証を掛けます。 リクエストヘッダー x-api-key が secret でなければ 401 を返すミドルウェア require_api_key を作ります。 認証を掛けたいルートだけを別の Router に分け、route_layer で適用します。

  • require_api_key: x-api-key ヘッダーの値を to_str().ok() で Option<&str> にして、Some("secret") と比べます。ヘッダーがない場合や、文字列として読めない値の場合も「無効」になります。無効なら next.run を呼ばずに 401 を返すので、ハンドラは実行されません。(StatusCode, &str) を Response へ変換するため、IntoResponse を読み込んでいます。

ℹ️

route_layer が掛かる範囲

上の 2 つのリクエストの結果から、route_layer で掛けたミドルウェアの範囲が分かります。

  • パスが一致しない場合（/nope）: require_api_key は掛からず、fallback の 404 がそのまま返ります。
  • パスは一致するがメソッドが定義されていない場合（/users への DELETE）: 本来は 405 Method Not Allowed になる状況です。しかし require_api_key を通り、401 が返りました。allow: GET,HEAD,POST ヘッダーが付いているとおり、リクエストは 405 応答の処理に回されています。ただし、その 405 応答の処理を require_api_key が包んでいるので、先に 401 が返ります。

Router の route_layer は、その Router に登録済みの各パスの MethodRouter に掛かります。対象は登録したメソッド（ここでは POST と PUT）と、そのパスでメソッドが一致しないときの 405 応答です。merge で /users を合流すると、405 応答には protected 側（認証付き）のものが使われます。そのため DELETE /users は 401 になります。allow ヘッダーは 405 応答を作った後に付け足されるので、401 にも付きます。

パスが一致しない場合は Router の fallback が処理するので、route_layer は掛からず 404 のままです。なお、x-api-key: secret を付けて DELETE /users を送ると、認証を通過して本来の 405（allow: GET,HEAD,POST）が返ります。この 405 → 401 の挙動はドキュメントに明記されておらず、merge の順序に依存する実装上の挙動です。

✅ 確認ポイント

POST と PUT が x-api-key: secret のときだけ成功し、GET はヘッダーなしでも 200 を返せば OK です。DELETE /users が 401、/nope が 404 になることも確認してください。確認できたら、サーバーを止めておきます。
