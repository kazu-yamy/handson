ルーティングとハンドラ

  • ⏱ 所要時間: 45分
  • 📊 難易度: 入門
  • 👤 対象: 01 で最小の Axum サーバーを動かし、次にエンドポイントを増やしたい人
  • 📋 前提: Rust の基本文法（関数・タプル・パターンによる分解）、cargo run と curl の基本操作ができること
  • 🔗 前提となる項目: 01: Hello Axum: 最小の Web サーバーを起動する

🎯 このレッスンで学ぶこと

  • 1 つのパスに GET と POST の 2 つのハンドラを登録し、404 と 405 の違いを確かめる
  • {id} 構文のパスパラメーターを Path<u32> で受け取り、型に合わない値が 400 になることを確かめる
  • 複数のパスパラメーターをタプルで受け取る
  • クエリパラメーターを Query<HashMap<String, String>> で受け取る
  • ハンドラを名前付きの関数に整理し、fallback で 404 の本文を返す
  • axum 0.7 以前の :id 構文を書くと起動時に panic することを確かめる

概要

01 で作った最小のサーバーに、ユーザー一覧・ユーザー詳細・検索などのエンドポイントを足していきます。 パスやクエリ文字列から値を取り出す仕組み（エクストラクター）の Path と Query を使い、ハンドラの引数として値を受け取れるようにします。

このレッスンの完成時には、サーバーが次のルートへ応答します。

メソッドパス返す内容
GET/Hello, Axum!
GET/healthok
GET/userslist users
POST/userscreate user
GET/users/{id}user {id}（id が数値でなければ 400）
GET/users/{user_id}/posts/{post_id}user {user_id} post {post_id}
GET/search受け取ったクエリパラメーターの一覧
（上記以外）どれにもマッチしないパス404 と本文 Not Found
ℹ️

使用バージョン

Rust（rustc）1.98.1 / cargo 1.98.1 / axum 0.8.9 / tokio 1.53.1（Rust edition 2024）で動作を確認しています。 バージョンは執筆時点（2026年9月）のものです。依存クレートは 01 から追加しません。

2

/users に GET と POST を登録する

/users というパスに、GET なら list users、POST なら create user を返すハンドラを登録します。 src/main.rs を次のように変更してください。

Diff src/main.rs 
- use axum::{Router, routing::get};+ use axum::{+     Router,+     routing::{get, post},+ };   #[tokio::main]  ...      let app = Router::new()          .route("/", get(|| async { "Hello, Axum!" }))-         .route("/health", get(|| async { "ok" }));+         .route("/health", get(|| async { "ok" }))+         .route(+             "/users",+             get(|| async { "list users" }).post(|| async { "create user" }),+         );       let listener = tokio::net::TcpListener::bind("127.0.0.1:3000")

get(...) の戻り値に .post(...) をつなげると、1 つのパスにメソッドごとのハンドラをまとめて登録できます。 use 文には post も追加しています。

変更後の src/main.rs 全体を見る
Rust src/main.rs 
use axum::{
    Router,
    routing::{get, post},
};

#[tokio::main]
async fn main() {
    let app = Router::new()
        .route("/", get(|| async { "Hello, Axum!" }))
        .route("/health", get(|| async { "ok" }))
        .route(
            "/users",
            get(|| async { "list users" }).post(|| async { "create user" }),
        );

    let listener = tokio::net::TcpListener::bind("127.0.0.1:3000")
        .await
        .unwrap();
    println!("listening on {}", listener.local_addr().unwrap());
    axum::serve(listener, app).await.unwrap();
}

ℹ️

メソッドチェーンの .post に use は不要

get(...).post(...) の .post は get(...) が返す値のメソッドなので、routing::post を use しなくても呼べます。 use した post 関数はどこでも使っていないため、「unused import」という警告になりました。警告なのでサーバーは起動します。use 文は次のステップで書き換えるときに整理します。

2 つ目のターミナルから、GET・POST・DELETE の 3 つのメソッドで /users にリクエストを送ります。curl の -X でメソッドを指定できます。

Terminal（2 つ目） 
$ curl -i http://127.0.0.1:3000/usersHTTP/1.1 200 OKcontent-type: text/plain; charset=utf-8content-length: 10date: Fri, 25 Sep 2026 16:03:51 GMTlist users$ curl -i -X POST http://127.0.0.1:3000/usersHTTP/1.1 200 OKcontent-type: text/plain; charset=utf-8content-length: 11date: Fri, 25 Sep 2026 16:03:51 GMTcreate user$ curl -i -X DELETE http://127.0.0.1:3000/usersHTTP/1.1 405 Method Not Allowedallow: GET,HEAD,POSTcontent-length: 0date: Fri, 25 Sep 2026 16:03:51 GMT
💡

404 と 405 の違い

01 で見たとおり、ルートに登録していないパスへのリクエストは 404 Not Found になります。 一方、パスは登録済みでもメソッドに対応するハンドラがない場合は 405 Method Not Allowed になります。 405 のレスポンスには、そのパスが受け付けるメソッドの一覧が allow ヘッダーで返ります。 登録したのは GET と POST だけですが、allow には HEAD も含まれています。GET を登録すると HEAD リクエストにも応答するためです。

✅ 確認ポイント

GET で list users、POST で create user が返り、DELETE が 405 と allow: GET,HEAD,POST になれば OK です。確認できたら、サーバーを止めておきます。

3

パスパラメーターを受け取る（/users/{id}）

/users/42 のように、パスの一部に ID を含むルートを追加します。 ルートのパスに {id} と書くと、その部分に来た値をハンドラで受け取れます。 今回はハンドラを名前付きの関数 get_user として main の外に書きます。

Diff src/main.rs 
- use axum::{-     Router,-     routing::{get, post},- };+ use axum::{Router, extract::Path, routing::get};   #[tokio::main]  ...              "/users",              get(|| async { "list users" }).post(|| async { "create user" }),-         );+         )+         .route("/users/{id}", get(get_user));       let listener = tokio::net::TcpListener::bind("127.0.0.1:3000")  ...      axum::serve(listener, app).await.unwrap();  }+ + async fn get_user(Path(id): Path<u32>) -> String {+     format!("user {id}")+ }

変更点は次の 3 つです。

  • use 文: 使っていない post を外し、extract::Path を追加します。これでステップ 2 の警告も消えます。
  • .route("/users/{id}", get(get_user)): {id} の部分がパスパラメーターです。
  • get_user 関数: 引数を Path(id): Path<u32> と書くと、パスの {id} の値が u32 に変換されて id に入ります。
変更後の src/main.rs 全体を見る
Rust src/main.rs

    let app = Router::new()

        .route(

            get(|| async { "list users" }).post(|| async { "create user" }),

        .await
        .unwrap();

    axum::serve(listener, app).await.unwrap();

async fn get_user(Path(id): Path<u32>) -> String {
    format!("user {id}")
}

サーバーを起動します。今度は警告が出ません。

Terminal 
$ cargo run   Compiling routing v0.1.0 (/path/to/02-routing)    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.40s     Running `target/debug/routing`listening on 127.0.0.1:3000

数値の ID と、数値として読めない値の 2 通りでリクエストを送ります。

Terminal（2 つ目） 
$ curl -i http://127.0.0.1:3000/users/42HTTP/1.1 200 OKcontent-type: text/plain; charset=utf-8content-length: 7date: Fri, 25 Sep 2026 16:04:12 GMTuser 42$ curl -i http://127.0.0.1:3000/users/abcHTTP/1.1 400 Bad Requestcontent-type: text/plain; charset=utf-8content-length: 42date: Fri, 25 Sep 2026 16:04:12 GMTInvalid URL: Cannot parse `abc` to a `u32`

id の型を u32 にしたので、abc のように変換できない値が来ると、ハンドラが呼ばれる前に Axum が 400 Bad Request を返します。 ハンドラの中で文字列を数値に変換する処理を書く必要はありません。 なお、エラー本文の文言は Axum の既定のものです。独自の文言に変える方法は、このレッスンでは扱いません。

✅ 確認ポイント

/users/42 で user 42、/users/abc で 400 Bad Request が返れば OK です。確認できたら、サーバーを止めておきます。

4

複数のパスパラメーターを受け取る

ユーザーごとの投稿を表す /users/{user_id}/posts/{post_id} を追加します。パスパラメーターが 2 つある場合は、Path の型をタプルにして受け取ります。

Diff src/main.rs 
              get(|| async { "list users" }).post(|| async { "create user" }),          )-         .route("/users/{id}", get(get_user));+         .route("/users/{id}", get(get_user))+         .route("/users/{user_id}/posts/{post_id}", get(get_user_post));       let listener = tokio::net::TcpListener::bind("127.0.0.1:3000")  ...      format!("user {id}")  }+ + async fn get_user_post(Path((user_id, post_id)): Path<(u32, u32)>) -> String {+     format!("user {user_id} post {post_id}")+ }

Path((user_id, post_id)): Path<(u32, u32)> は、パス内の並び順どおり、1 つ目の値を user_id、2 つ目の値を post_id に入れます。

ℹ️

パラメーターの数とタプルの要素数をそろえる

パスの {...} の数と、タプルの要素数は一致させてください。数が合わなくてもコンパイルと起動は通り、リクエストした時点で 500 Internal Server Error が返ります。Step 7 の起動時の panic とは違い、実行時まで検出されない点に注意しましょう。

たとえば型を Path<(u32, u32, u32)> にして同じ URL にリクエストすると、次のようになります。

Terminal（2 つ目） 
$ curl -i http://127.0.0.1:3000/users/3/posts/99HTTP/1.1 500 Internal Server Error...Wrong number of path arguments for `Path`. Expected 3 but got 2
変更後の src/main.rs 全体を見る
Rust src/main.rs

5

クエリパラメーターを受け取る（/search）

/search?q=axum のような、URL の ? 以降に付くクエリパラメーターを受け取るルートを追加します。 クエリパラメーターは Query で受け取ります。今回は、キーと値の組をまとめて HashMap<String, String> に入れて、そのまま文字列にして返します。

Diff src/main.rs 
- use axum::{Router, extract::Path, routing::get};+ use axum::{+     Router,+     extract::{Path, Query},+     routing::get,+ };+ use std::collections::HashMap;   #[tokio::main]  ...          )          .route("/users/{id}", get(get_user))-         .route("/users/{user_id}/posts/{post_id}", get(get_user_post));+         .route("/users/{user_id}/posts/{post_id}", get(get_user_post))+         .route("/search", get(search));       let listener = tokio::net::TcpListener::bind("127.0.0.1:3000")  ...      format!("user {user_id} post {post_id}")  }+ + async fn search(Query(params): Query<HashMap<String, String>>) -> String {+     format!("search params: {params:?}")+ }

HashMap は標準ライブラリの型なので、use std::collections::HashMap; を追加しています。{params:?} は、HashMap の中身をデバッグ表示の形式で文字列にします。変更後の src/main.rs の全体は次のとおりです。

Rust src/main.rs 
use axum::{
    Router,
    extract::{Path, Query},
    routing::get,
};
use std::collections::HashMap;

#[tokio::main]
async fn main() {
    let app = Router::new()
        .route("/", get(|| async { "Hello, Axum!" }))
        .route("/health", get(|| async { "ok" }))
        .route(
            "/users",
            get(|| async { "list users" }).post(|| async { "create user" }),
        )
        .route("/users/{id}", get(get_user))
        .route("/users/{user_id}/posts/{post_id}", get(get_user_post))
        .route("/search", get(search));

    let listener = tokio::net::TcpListener::bind("127.0.0.1:3000")
        .await
        .unwrap();
    println!("listening on {}", listener.local_addr().unwrap());
    axum::serve(listener, app).await.unwrap();
}

async fn get_user(Path(id): Path<u32>) -> String {
    format!("user {id}")
}

async fn get_user_post(Path((user_id, post_id)): Path<(u32, u32)>) -> String {
    format!("user {user_id} post {post_id}")
}

async fn search(Query(params): Query<HashMap<String, String>>) -> String {
    format!("search params: {params:?}")
}

サーバーを起動し、クエリパラメーターが 1 つ・2 つ・なしの 3 通りでリクエストを送ります。URL に ? や & を含むので、シェルに解釈されないよう URL をダブルクォートで囲みます。

ℹ️

表示の順番はクエリ文字列の順番と一致しない

HashMap はキーの順番を保持しないため、2 つ目のリクエストでは、クエリ文字列では後ろ側の limit が先に表示されています。実行するたびに順番が変わることもあります。 また、クエリパラメーターがないリクエストもエラーにはならず、空の HashMap（{}）が渡されます。 特定のパラメーターを必須にするには、パラメーターに対応する構造体と serde を使います。これは次の項目以降で扱います。

✅ 確認ポイント

3 つのリクエストがどれも 200 OK になり、送ったクエリパラメーターが本文に表示されれば OK です。確認できたら、サーバーを止めておきます。

6

ハンドラを整理し、fallback で 404 の本文を返す

ルートが増えてきたので、main の中に無名のクロージャで書いていたハンドラも、全て名前付きの関数に分けます。 あわせて、どのルートにもマッチしないリクエストに本文付きの 404 を返すようにします。

変更する前に、登録していないパス /nope にリクエストを送り、今の 404 の本文が空であることを確認しておきます。Step 5 の状態でサーバーを起動し、2 つ目のターミナルで実行してください。

Terminal（2 つ目） 
$ curl -i http://127.0.0.1:3000/nopeHTTP/1.1 404 Not Foundcontent-length: 0date: Fri, 25 Sep 2026 16:05:16 GMT

確認できたらサーバーを止め、src/main.rs を次のように変更します。

Diff src/main.rs 
      Router,      extract::{Path, Query},+     http::StatusCode,      routing::get,  };  ...  async fn main() {      let app = Router::new()-         .route("/", get(|| async { "Hello, Axum!" }))-         .route("/health", get(|| async { "ok" }))-         .route(-             "/users",-             get(|| async { "list users" }).post(|| async { "create user" }),-         )+         .route("/", get(root))+         .route("/health", get(health))+         .route("/users", get(list_users).post(create_user))          .route("/users/{id}", get(get_user))          .route("/users/{user_id}/posts/{post_id}", get(get_user_post))-         .route("/search", get(search));+         .route("/search", get(search))+         .fallback(not_found);       let listener = tokio::net::TcpListener::bind("127.0.0.1:3000")  ...  } + async fn root() -> &'static str {+     "Hello, Axum!"+ }+ + async fn health() -> &'static str {+     "ok"+ }+ + async fn list_users() -> &'static str {+     "list users"+ }+ + async fn create_user() -> &'static str {+     "create user"+ }+   async fn get_user(Path(id): Path<u32>) -> String {      format!("user {id}")  ...      format!("search params: {params:?}")  }+ + async fn not_found() -> (StatusCode, &'static str) {+     (StatusCode::NOT_FOUND, "Not Found")+ }

変更点は次の 3 つです。

  • /・/health・/users のクロージャを、root・health・list_users・create_user の 4 つの関数に置き換えます。ルートの一覧が 1 行ずつ並び、読みやすくなります。
  • .fallback(not_found): どのルートにもマッチしないリクエストを not_found 関数で処理します。
  • not_found 関数: (StatusCode, &'static str) のタプルを返すと、1 つ目の要素がステータスコード、2 つ目の要素が本文になります。StatusCode を使うため、use 文に http::StatusCode を追加しています。

これでこの項目の完成形です。変更後の src/main.rs の全体は次のとおりです。

Rust src/main.rs 
use axum::{
    Router,
    extract::{Path, Query},
    http::StatusCode,
    routing::get,
};
use std::collections::HashMap;

#[tokio::main]
async fn main() {
    let app = Router::new()
        .route("/", get(root))
        .route("/health", get(health))
        .route("/users", get(list_users).post(create_user))
        .route("/users/{id}", get(get_user))
        .route("/users/{user_id}/posts/{post_id}", get(get_user_post))
        .route("/search", get(search))
        .fallback(not_found);

    let listener = tokio::net::TcpListener::bind("127.0.0.1:3000")
        .await
        .unwrap();
    println!("listening on {}", listener.local_addr().unwrap());
    axum::serve(listener, app).await.unwrap();
}

async fn root() -> &'static str {
    "Hello, Axum!"
}

async fn health() -> &'static str {
    "ok"
}

async fn list_users() -> &'static str {
    "list users"
}

async fn create_user() -> &'static str {
    "create user"
}

async fn get_user(Path(id): Path<u32>) -> String {
    format!("user {id}")
}

async fn get_user_post(Path((user_id, post_id)): Path<(u32, u32)>) -> String {
    format!("user {user_id} post {post_id}")
}

async fn search(Query(params): Query<HashMap<String, String>>) -> String {
    format!("search params: {params:?}")
}

async fn not_found() -> (StatusCode, &'static str) {
    (StatusCode::NOT_FOUND, "Not Found")
}

fallback は 405 には使われない

fallback が呼ばれるのは、どのルートにもパスがマッチしなかったときだけです。ステップ 2 の DELETE /users のように、パスは登録済みでメソッドだけが対応していない場合は、これまでどおり 405 になります。

旧構文 :id を書いて起動時の panic を確かめる

インターネット上の古い記事では、パスパラメーターを /users/:id のようにコロンで書いている例がよく見つかります。これは axum 0.7 以前の構文です。 axum 0.8 でこの書き方をするとどうなるか、あえて試してみます。サーバーを止めた状態で、src/main.rs の 1 行を一時的に書き換えてください。

Diff src/main.rs 
          .route("/health", get(health))          .route("/users", get(list_users).post(create_user))-         .route("/users/{id}", get(get_user))+         .route("/users/:id", get(get_user))          .route("/users/{user_id}/posts/{post_id}", get(get_user_post))          .route("/search", get(search))

コンパイルは通りますが、listening on ... が表示される前にプロセスが panic して終了します。 panic の位置 src/main.rs:15:10 は、書き換えた .route("/users/:id", ...) の行です。 ルートの書き方の誤りは、リクエストを受けたときではなく、Router を組み立てる時点（サーバーの起動前）で検出されます。

⚠️

axum 0.8 のパスパラメーターは {id} で書く

axum 0.8 では、パスパラメーターの構文が :id から {id} に変わりました。古い記事のコードをそのまま写すと、このステップと同じ panic になります。 エラーメッセージの For capture groups, use `{capture}`. が、{...} 構文を使うよう案内しています。panic したらまずメッセージを読みましょう。

確認できたら、"/users/:id" を "/users/{id}" に戻してください。

✅ 確認ポイント

:id で書くと起動時に Path segments must not start with `:` の panic になり、{id} に戻すとサーバーが起動することを確認してください。確認できたら、サーバーを止めておきます。

コードを変えたのに結果が変わらない

cargo run で起動したサーバーは、ソースコードを保存しても変更を反映しません。各ステップでコードを変えたら、前のサーバーを Ctrl + C で止めてから cargo run し直してください。止め忘れたまま別のターミナルで起動すると、ポート 3000 が使用中のエラーになります（01 の「つまずきポイント」を参照）。

💡

起動した直後にサーバーが終了する

listening on 127.0.0.1:3000 が表示されずに panicked at が出る場合は、ルートのパスの書き方を見直してください。:id のようなコロン構文を使っていると、ステップ 7 と同じ panic になります。
