概要

03 の Todo リストは、Rust 側のメモリーに状態を持つだけでした。アプリを閉じると、追加した Todo は消えてしまいます。 この項目では、Todo をファイルに保存して次回の起動時に復元します。さらに、ユーザーがダイアログで選んだ場所への書き出しと、そこからの読み込みもできるようにします。

プラグインと権限の仕組み

Tauri 2 では、ファイル操作やダイアログは公式プラグインとして提供されます。フロントエンドからの呼び出しは、capabilities で許可したものだけが通ります。この項目で扱う要素は次のとおりです。

要素役割この項目での例
プラグインRust の crate と npm パッケージの組で提供される。tauri add が両側に追加し、lib.rs の .plugin(...) で登録するtauri-plugin-fs + @tauri-apps/plugin-fs
capabilityどのウィンドウに、どの権限を与えるかをまとめた設定ファイルsrc-tauri/capabilities/default.json（対象は main ウィンドウ）
permission（権限）どのコマンドを呼べるかを決める。複数の権限をまとめたセットもあるfs:default、fs:allow-app-write、dialog:default
scope権限が対象にできるパスの範囲。fs の操作は権限と scope の両方を満たす必要があるfs:allow-app-write の scope は $APPDATA とその直下など
ベースディレクトリOS ごとに場所が違うアプリ用フォルダを表す。scope では $APPDATA、JavaScript では BaseDirectory.AppData、Rust では app_data_dir()macOS では ~/Library/Application Support/com.handson.tauri04
ダイアログ経由のパスsave / open でユーザーが選んだファイルは、その 1 ファイルだけ fs の scope に追加される書き出し（ステップ 4）と読み込み（ステップ 5）

一方、Rust のコマンドの中で std::fs を使うと、capabilities の検査は通りません。両者の違いはステップ 6 で比べます。

2

権限と保存先を確かめる

プラグインを追加しただけでは、フロントエンドから自由にファイルを書けるわけではありません。Tauri 2 では、フロントエンドから呼べる操作を capability（capabilities/default.json）の権限で許可します。fs:default が何を許可しているかを、プラグインの定義ファイル（tauri-plugin-fs 2.5.2 の permissions/default.toml）で確認します。

権限中身許可されること
fs:defaultcreate-app-specific-dirsアプリ用フォルダ（AppConfig / AppData / AppLocalData / AppCache / AppLog）の作成（mkdir）
read-app-specific-dirs-recursiveアプリ用フォルダとその中のファイル・サブフォルダの読み取り
deny-defaultWebView のデータフォルダなど、重要な場所へのアクセスを拒否（Windows / Linux 向け）

3

AppData に保存して起動時に復元する

Todo を AppData の todos.json に保存し、次回の起動時に読み込みます。ファイルの読み書きは、フロントエンドから fs プラグインで行います。保存と読み込みの処理を storage.ts にまとめます。

TypeScript src/features/todos/api/storage.ts（新規） 
import {
  BaseDirectory,
  exists,
  mkdir,
  readTextFile,
  writeTextFile,
} from "@tauri-apps/plugin-fs";
import type { Todo } from "../types";

// AppData（macOS では ~/Library/Application Support/<identifier>）の直下に保存する。
const FILE_NAME = "todos.json";
const OPTIONS = { baseDir: BaseDirectory.AppData } as const;

export async function saveTodos(todos: Todo[]): Promise<void> {
  // AppData のフォルダは初回起動時には存在しないので、先に作っておく。
  // 既にあっても recursive: true なら失敗しない。
  await mkdir("", { ...OPTIONS, recursive: true });
  await writeTextFile(FILE_NAME, JSON.stringify(todos, null, 2), OPTIONS);
}

export async function loadTodos(): Promise<Todo[]> {
  if (!(await exists(FILE_NAME, OPTIONS))) {
    return [];
  }
  const text = await readTextFile(FILE_NAME, OPTIONS);
  return JSON.parse(text) as Todo[];
}

{ baseDir: BaseDirectory.AppData } を渡すと、パス（ここでは todos.json）は AppData からの相対パスとして扱われます。saveTodos では、書き込む前に mkdir で AppData のフォルダを作っています。

このフォルダは、初回の起動時には存在しません。筆者が mkdir を呼ばずに書き込んだところ、権限は通ったものの次のエラーになりました。

Terminal

import type { Todo } from "../types";

/// JSON 文字列を Todo の配列として検証する。
/// 壊れた JSON は JSON.parse が SyntaxError を投げ、形が違うものは Error を投げる。
export function parseTodos(text: string): Todo[] {
  const value: unknown = JSON.parse(text);
  if (!Array.isArray(value)) {
    throw new Error("Todo の配列（[ ... ]）ではありません");
  }

  value.forEach((item: unknown, index: number) => {
    const at = `${index + 1} 件目`;
    if (typeof item !== "object" || item === null) {
      throw new Error(`${at}: オブジェクトではありません`);
    }
    const todo = item as Record<string, unknown>;
    if (typeof todo.id !== "number" || !Number.isInteger(todo.id)) {
      throw new Error(`${at}: id が整数ではありません`);
    }
    if (typeof todo.title !== "string") {
      throw new Error(`${at}: title が文字列ではありません`);
    }
    if (typeof todo.done !== "boolean") {
      throw new Error(`${at}: done が真偽値ではありません`);
    }
    // Rust 側の Todo は createdAt も必須なので、ここで確かめておく。
    if (typeof todo.createdAt !== "number") {
      throw new Error(`${at}: createdAt が数値ではありません`);
    }
  });

  return value as Todo[];
}

export function TodoList() {
  const [todos, setTodos] = useState<Todo[]>([]);
  const [loaded, setLoaded] = useState(false);
  const [location, setLocation] = useState("");
  const [title, setTitle] = useState("");
  const [error, setError] = useState("");

      setError(String(e));

      const updated = await toggleTodo(id);
      setTodos((prev) => prev.map((t) => (t.id === id ? updated : t)));

      setError(String(e));
    }

/// Todo の一覧と次に割り振る id を保持するアプリ状態。
/// `tauri::Builder::manage()` で登録し、各コマンドは `tauri::State<'_, AppState>` で受け取る。

/// アプリ独自のエラー型。`thiserror` でメッセージを定義し、
/// `impl serde::Serialize` でフロントエンドに文字列として返す。
#[derive(Debug, thiserror::Error)]
enum AppError {
    #[error("タイトルを入力してください")]
    EmptyTitle,
    #[error("id {0} の Todo が見つかりません")]
    NotFound(u32),
    #[error("イベント送信に失敗しました: {0}")]
    Emit(String),
    #[error("ファイル操作に失敗しました: {0}")]
    Io(String),
}

impl Serialize for AppError {
    fn serialize<S>(&self, serializer: S) -> Result<S::Ok, S::Error>
    where
        S: serde::Serializer,
    {
        serializer.serialize_str(&self.to_string())
    }
}

// --- ここから下は Mutex や tauri::State から切り離した純粋関数。
// ロジック自体は `&mut Vec<Todo>` 等の素のデータ構造だけを操作するため、
// Tauri のモックアプリを使わないテスト（cargo test の高速なユニットテスト）がそのまま書ける。

fn add_todo_pure(
    todos: &mut Vec<Todo>,
    next_id: &mut u32,
    title: String,
) -> Result<Todo, AppError> {
    let title = title.trim().to_string();
    if title.is_empty() {
        return Err(AppError::EmptyTitle);
    }
    let id = *next_id;
    *next_id += 1;
    let todo = Todo {
        id,
        title,
        done: false,
        created_at: current_unix_time(),
    };
    todos.push(todo.clone());
    Ok(todo)
}

fn toggle_todo_pure(todos: &mut [Todo], id: u32) -> Result<Todo, AppError> {
    let todo = todos
        .iter_mut()
        .find(|t| t.id == id)
        .ok_or(AppError::NotFound(id))?;
    todo.done = !todo.done;
    Ok(todo.clone())
}

fn delete_todo_pure(todos: &mut Vec<Todo>, id: u32) -> Result<(), AppError> {
    let len_before = todos.len();
    todos.retain(|t| t.id != id);
    if todos.len() == len_before {
        Err(AppError::NotFound(id))
    } else {
        Ok(())
    }
}

/// 保存ファイルから読み込んだ Todo で状態を置き換える。
/// 次に振る id は、読み込んだ中の最大値 + 1 にそろえて id が重ならないようにする。
fn replace_todos_pure(todos: &mut Vec<Todo>, next_id: &mut u32, loaded: Vec<Todo>) {
    *next_id = loaded.iter().map(|t| t.id).max().unwrap_or(0) + 1;
    *todos = loaded;
}

fn export_todos_rust(path: String, state: tauri::State<'_, AppState>) -> Result<(), AppError> {
    let todos = state.todos.lock().unwrap();
    write_todos_file(std::path::Path::new(&path), &todos)
}

/// `app_data_dir()` で AppData の todos.json のパスを解決して返す。
/// フロントエンドの BaseDirectory.AppData と同じフォルダを指す。
#[tauri::command]
fn app_data_todos_path<R: tauri::Runtime>(app: tauri::AppHandle<R>) -> Result<String, AppError> {
    use tauri::Manager;

    let dir = app
        .path()
        .app_data_dir()
        .map_err(|e| AppError::Io(e.to_string()))?;
    Ok(dir.join("todos.json").to_string_lossy().into_owned())
}

        .expect("system clock before unix epoch")
        .as_secs()
}

演習

以下のチェックリストを使って、このレッスンの内容を振り返りましょう。

つまずきポイント

⚠️

fs.write_text_file not allowed. になる

fs:default は、アプリ用フォルダの読み取りとフォルダの作成だけを許可します。書き込みには fs:allow-app-write などを capabilities に追加します。エラーの後ろに並ぶ権限名の一覧から、必要な範囲の権限を選びます。

⚠️

forbidden path になる

コマンドの権限はあるものの、パスが scope の外にあります。fs:allow-app-write の scope はアプリ用フォルダの直下だけです。サブフォルダに書くなら fs:allow-app-write-recursive を、ユーザーが選んだ場所に書くならダイアログを使います。

⚠️

権限を足したのに No such file or directory (os error 2) になる

AppData のフォルダは自動では作られません。書き込む前に mkdir("", { baseDir: BaseDirectory.AppData, recursive: true }) を呼びます。recursive: true なら、既にあっても失敗しません。

⚠️

起動するたびに保存した Todo が消える

読み込みが終わる前に、最初の描画の空配列 [] を保存していないかを確認します。保存の useEffect は、読み込みが終わったこと（loaded）を条件にします。

⚠️

読み込みで missing field `createdAt` になる

Rust 側の Todo は createdAt が必須です。外部の JSON は、parseTodos で検証してから set_todos に渡します。足りないフィールドがあれば、フロントエンドの段階で弾きます。

⚠️

Found version mismatched Tauri packages と表示される

tauri add は npm 側に最新版を入れるため、Rust crate とマイナーバージョンがずれることもあります。表示された Rust 側のバージョンに合わせ、npm install @tauri-apps/plugin-fs@~2.5.2 のように ~ を付けて入れ直します。@tauri-apps/api も上がっている場合があるので、表示の 1 行目も確認します。

⚠️

Rust のコマンドなら任意のパスに書けてしまう

コマンドの中の std::fs は capabilities の権限と scope を通りません。フロントエンドからパスを受け取るコマンドでは、書いてよい場所かどうかをコマンドの中で検証します。

💡

$APPDATA の実際の場所を知りたい

フロントエンドでは appDataDir()、Rust では app.path().app_data_dir() で取得できます。macOS では ~/Library/Application Support/ の下のフォルダになります。フォルダ名は tauri.conf.json の identifier（この項目では com.handson.tauri04）です。

💡

ダイアログで選んだファイルだけが自動で許可される

save / open は、選ばれたファイルを fs の scope に追加します。追加されるのはそのファイル 1 つで、同じフォルダの別のファイルは許可されません。

💡

tauri add の後の差分に整形が混ざる

tauri add は最後に cargo fmt を実行します。lib.rs が未整形だった場合は、プラグインの行以外にも整形による差分が出ます。また、capabilities/default.json は書き換えの結果、末尾の改行が無くなりました（差分では \ No newline at end of file と表示されます）。

💡

プロジェクトを移動したら target と gen を作り直す

src-tauri/target と src-tauri/gen には古い絶対パスが残ります。ディレクトリを移動・改名したら rm -rf target gen を実行してから、ビルドし直します。

まとめ

tauri add で fs / dialog プラグインを追加し、npm と Rust のバージョンをそろえました。 capabilities の権限（permission）と scope でフロントエンドのファイル操作を許可し、AppData に Todo を保存して起動時に復元しました。 ダイアログで選んだファイルは自動で scope に加わるので、ユーザーが選んだ場所への書き出しと読み込みもできます。外部から読み込む JSON は検証してから使いました。 また、Rust の std::fs は capabilities を通らないので、パスの検証を自分で書く必要があることも確かめました。
