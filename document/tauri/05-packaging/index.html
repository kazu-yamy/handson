パッケージングと配布

  • ⏱ 所要時間: 45分
  • 📊 難易度: 初級
  • 👤 対象: Tauri 04 を終えた人。tauri build で .app / .dmg を作ったことがある人
  • 📋 前提: 04 と同じ開発環境（macOS）。ステップ 6 は GitHub のリポジトリがあると試せる
  • 🔗 前提となる項目: 04: ファイルシステム API の利用

🎯 このレッスンで学ぶこと

  • bundle の設定で、OS ごとに作る形式と中身を決める
  • [profile.release] でリリースビルドを小さくする
  • Universal バイナリ、コード署名、公証の役割と手順を知る
  • updater プラグインと署名鍵で、自動アップデートの仕組みを組み込む
  • GitHub Actions と tauri-action で、各 OS 向けのビルドと Release を自動化する

概要

04 までで、Todo を保存できるデスクトップアプリができました。この項目は Tauri トラックの最後です。ここでは、このアプリを他の人が使える形で配ります。 アプリを配るまでには、ビルドのほかにもいくつかの段階があります。

配布までの流れ

段階やることこの項目のステップ
ビルドRust とフロントエンドをリリース用にビルドする。サイズや対応するアーキテクチャもここで決まる2（最適化）、3（Universal）
署名OS が配布元を確かめられるように、アプリにコード署名を付ける。macOS では公証も受ける4

更新配ったアプリに新しいバージョンを届ける。更新ファイルは署名して改ざんを防ぐ5

2

リリースビルドを最適化する

既定のリリースビルドは、実行速度を優先した設定です。配布するデスクトップアプリでは、ダウンロードの大きさも気になります。Cargo.toml に [profile.release] を追加して、サイズを小さくします。

Diff src-tauri/Cargo.toml 
  ...  [dev-dependencies]  tauri = { version = "2.11.6", features = ["test"] }+ + [profile.release]+ codegen-units = 1+ lto = true+ opt-level = "s"+ panic = "abort"+ strip = true
キー意味注意
codegen-units = 1クレートを 1 つの単位でコード生成する。並列化をやめる代わりに、クレート全体を見た最適化が効くコンパイルの並列度が下がる
lto = trueリンク時最適化（Link Time Optimization）。依存クレートをまたいで使われないコードを削り、インライン化するリンクに時間がかかる
opt-level = "s"サイズを優先した最適化。既定のリリースビルドは 3（速度優先）処理が重いアプリでは 3 と比べて選ぶ
strip = true実行ファイルからシンボル情報を取り除くパニック時のバックトレースに関数名が出なくなる
panic = "abort"パニックしたら巻き戻し（unwind）をせずに即座に終了する。巻き戻し用のコードが要らなくなるcatch_unwind でパニックを捕まえる処理が効かなくなる

このプロジェクトが catch_unwind を使っていないことを確かめておきます。何も表示されなければ、panic = "abort" にしても影響はありません。

Terminal 
$ grep -rn catch_unwind src-tauri/src

3

Universal バイナリを作る（macOS）

Apple Silicon の Mac でビルドした .app は arm64 専用です（ステップ 1 の .dmg の名前にも aarch64 が入っています）。Intel の Mac にも配るには、arm64 と x86_64 の両方を 1 つにまとめた Universal バイナリを作ります。それには、Rust の 2 つの target（aarch64-apple-darwin と x86_64-apple-darwin）が必要です。入っている target を確かめます（出力は抜粋）。

Terminal 
$ rustup target list --installedaarch64-apple-darwinaarch64-apple-iosaarch64-apple-ios-simaarch64-linux-androidarmv7-linux-androideabii686-linux-androidwasm32-unknown-unknownx86_64-apple-iosx86_64-linux-android

執筆環境には x86_64-apple-darwin が入っていませんでした。執筆時はツールを追加でインストールしない方針にしたため、ここから先の手順は（未実行）です。手順は次のとおりです。

Terminal 
$ rustup target add x86_64-apple-darwin$ npm run tauri build -- --target universal-apple-darwin$ lipo -archs src-tauri/target/universal-apple-darwin/release/bundle/macos/handson-tauri-05.app/Contents/MacOS/handson-tauri-05

lipo -archs は、実行ファイルに含まれるアーキテクチャを表示するコマンドです。Universal バイナリになっていれば、出力には x86_64 と arm64 の 2 つが表示されます。表示の順番は環境によって異なるため、ここでは並び順を示しません（未実行）。成果物は target/release/ ではなく target/universal-apple-darwin/release/ の下にできます。

⚠️

クロスコンパイルは OS をまたげない

Universal バイナリは、同じ Mac に 2 つの target を入れれば作れます。一方、macOS から Windows 向けや Linux 向けをビルドするようなクロスコンパイルは、一般には行えません。Windows 向けは Windows で、Linux 向けは Linux でビルドします。ステップ 6 では、GitHub Actions の matrix で OS ごとにビルドを分けます。

✅ 確認ポイント

rustup target list --installed の結果に、aarch64-apple-darwin と x86_64-apple-darwin の両方があるかを確認します。両方そろえば Universal ビルドができます。執筆時は（未実行）。

4

コード署名と公証（macOS）

macOS では、配布するアプリにコード署名を付け、Apple の公証（notarization）を受けるのが基本です。署名の無いアプリや、Apple 発行の証明書で署名していないアプリは、Gatekeeper（macOS の実行前チェック）に止められます。まず証明書が無くてもできる ad-hoc 署名でビルドし、Gatekeeper の判定を確かめます。

bundle.macOS.signingIdentity に "-" を指定すると、ad-hoc 署名になります。

更新を確認するコンポーネントを作る

「更新を確認」ボタンを押すと check() で latest.json を取得します。新しいバージョンがあれば「インストールして再起動」ボタンを出し、downloadAndInstall() の後に relaunch() で再起動します。構成は ProgressTask と同じく、index.ts の re-export と .module.scss を同じフォルダに置きます。

TypeScript src/components/UpdateChecker/UpdateChecker.tsx 
"use client";

import { useState } from "react";
import { check, type Update } from "@tauri-apps/plugin-updater";
import { relaunch } from "@tauri-apps/plugin-process";
import styles from "./UpdateChecker.module.scss";

type Status = "idle" | "checking" | "available" | "upToDate" | "installing" | "error";

export function UpdateChecker() {
  const [status, setStatus] = useState<Status>("idle");
  const [update, setUpdate] = useState<Update | null>(null);
  const [message, setMessage] = useState("");

  const handleCheck = async () => {
    setStatus("checking");
    setMessage("");
    try {
      // endpoints の latest.json を取得し、現在のバージョンより新しければ Update を返す。
      const found = await check();
      if (found) {
        setUpdate(found);
        setStatus("available");
        setMessage(`新しいバージョン ${found.version} があります`);
      } else {
        setUpdate(null);
        setStatus("upToDate");
        setMessage("最新のバージョンです");
      }
    } catch (e) {
      setStatus("error");
      setMessage(String(e));
    }
  };

  const handleInstall = async () => {
    if (!update) return;
    setStatus("installing");
    setMessage("ダウンロードとインストールを実行中...");
    try {
      // 署名の検証に成功したものだけがインストールされる（pubkey と .sig の照合）。
      await update.downloadAndInstall();
      await relaunch();
    } catch (e) {
      setStatus("error");
      setMessage(String(e));
    }
  };

  const busy = status === "checking" || status === "installing";

  return (
    <section className={styles.updateChecker}>
      <button
        type="button"
        className={styles.button}
        onClick={handleCheck}
        disabled={busy}
      >
        更新を確認
      </button>

      {status === "available" && (
        <button
          type="button"
          className={styles.button}
          onClick={handleInstall}
          disabled={busy}
        >
          インストールして再起動
        </button>
      )}

      {message && (
        <p className={status === "error" ? styles.error : styles.message}>
          {message}
        </p>
      )}
    </section>
  );
}

GitHub Actions で各 OS 向けにビルドする

Windows 向けは Windows で、Linux 向けは Linux でビルドする必要があります。手元にすべての OS を用意する代わりに、GitHub Actions で OS ごとにビルドし、GitHub Release に成果物を載せます。Tauri 公式の tauri-apps/tauri-action を使います。

ワークフローは、実際には自分のアプリのリポジトリのルートにある .github/workflows/ に置きます。このハンズオンのリポジトリでは、ほかの項目の CI と混ざらないように、プロジェクトの中（05-packaging/.github/workflows/release.yml）に置いています。そのため、この教材のリポジトリではワークフローは動きません。GitHub 上での実行は（未実行）です。

YAML .github/workflows/release.yml 
# このファイルは教材用にプロジェクト内に置いています。
# 実際に動かすときは、アプリのリポジトリのルートの .github/workflows/ に置きます。
name: release

on:
  push:
    tags:
      - "v*"

jobs:
  publish:
    permissions:
      contents: write # tauri-action が GitHub Release を作成・更新するために必要
    strategy:
      fail-fast: false
      matrix:
        include:
          - platform: macos-latest
            args: --target aarch64-apple-darwin
          - platform: macos-latest
            args: --target x86_64-apple-darwin
          - platform: ubuntu-22.04
            args: ""
          - platform: windows-latest
            args: ""
    runs-on: ${{ matrix.platform }}
    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Install Linux system dependencies
        if: matrix.platform == 'ubuntu-22.04'
        run: |
          sudo apt-get update
          sudo apt-get install -y \
            libwebkit2gtk-4.1-dev \
            libappindicator3-dev \
            librsvg2-dev \
            patchelf

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: 24
          cache: npm

      - name: Setup Rust
        uses: dtolnay/rust-toolchain@stable
        with:
          targets: ${{ matrix.platform == 'macos-latest' && 'aarch64-apple-darwin,x86_64-apple-darwin' || '' }}

      - name: Cache Rust build
        uses: swatinem/rust-cache@v2
        with:
          workspaces: ./src-tauri -> target

      - name: Install npm dependencies
        run: npm ci

      - name: Build and release with tauri-action
        uses: tauri-apps/tauri-action@v0
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
          TAURI_SIGNING_PRIVATE_KEY: ${{ secrets.TAURI_SIGNING_PRIVATE_KEY }}
          TAURI_SIGNING_PRIVATE_KEY_PASSWORD: ${{ secrets.TAURI_SIGNING_PRIVATE_KEY_PASSWORD }}
        with:
          tagName: v__VERSION__
          releaseName: "handson-tauri-05 v__VERSION__"
          releaseBody: "変更点は Release の説明を参照してください。"
          releaseDraft: true
          prerelease: false
          args: ${{ matrix.args }}
部分内容
on.push.tags: "v*"v0.5.0 のような v で始まるタグを push したときに動く
permissions.contents: writetauri-action が GITHUB_TOKEN で GitHub Release を作成・更新するための権限
strategy.matrixmacOS（aarch64 / x86_64 の 2 つ）、Ubuntu 22.04、Windows の 4 つのジョブを並列に動かす。fail-fast: false で、1 つが失敗しても残りを続ける
Install Linux system dependenciesUbuntu のジョブだけで、WebKitGTK（libwebkit2gtk-4.1-dev）などのシステムパッケージを入れる

Cache Rust buildsrc-tauri/target をキャッシュして、2 回目以降のビルドを速くする

⚠️

tauri-action には contents: write が要る

permissions で contents: write を与えないと、GITHUB_TOKEN で Release を作れず、tauri-action が失敗します。特に、リポジトリの既定のワークフロー権限が読み取りのみ（新しいリポジトリの既定）の場合に失敗します。

⚠️

Linux のビルドにはシステムパッケージが要る

Linux 版の Tauri は WebView に WebKitGTK を使うので、libwebkit2gtk-4.1-dev などをビルドの前に入れておく必要があります。ubuntu-latest は指す版が時期によって変わるので、パッケージ名がそろっている ubuntu-22.04 に固定しています。

💡

macOS を Universal 1 本にまとめる

このワークフローは、macOS の aarch64 と x86_64 を別々のジョブでビルドします。Universal バイナリ 1 本にしたい場合は、macOS のジョブを 1 つにまとめ、args を --target universal-apple-darwin にします。2 つの target は Setup Rust で入れています。

✅ 確認ポイント

actionlint .github/workflows/release.yml が何も表示せずに終わることを確認します。自分のアプリのリポジトリで試すときは、ワークフローをルートの .github/workflows/ に置きます。Secrets を登録してから v0.5.0 のタグを push します（未実行）。

演習

以下のチェックリストを使って、このレッスンの内容を振り返りましょう。

つまずきポイント

⚠️

他の OS の形式は警告なしで無視される

配列に他の OS の形式を書いても、その OS で作れない形式は警告なしで無視されます。CI で全 OS 向けに作るには、全形式を列挙します（ステップ 6）。

⚠️

macOS から Windows / Linux 向けにはビルドできない

OS をまたぐクロスコンパイルは一般に行えません。Universal バイナリは同じ Mac で 2 つの target を入れれば作れますが、片方の target が無いと作れません（ステップ 3）。

⚠️

ad-hoc 署名のアプリは Gatekeeper に止められる

signingIdentity: "-" の署名は、spctl では rejected（no usable signature）です。インターネット経由で受け取った利用者は、初回の起動時に個別の許可が必要になります（ステップ 4）。

⚠️

公証には Developer ID Application の証明書が要る

ad-hoc 署名では公証できません。公証には有料の Apple Developer Program の証明書が必要です（ステップ 4）。

🚫

updater の秘密鍵を失うと更新を配れない

配ったアプリには公開鍵が埋め込まれています。秘密鍵やパスワードを失うと、既存の利用者に更新を届けられません。鍵はバックアップし、リポジトリにはコミットしません（ステップ 5）。

⚠️

Found version mismatched Tauri packages でビルドが止まる

tauri add は npm 側を >=2 で入れます。そのため、Rust の crate とマイナーバージョンがずれる場合があります。エラーに表示された crate のバージョンに合わせて、npm 側を ~ で固定します（ステップ 5）。

⚠️

鍵のパス指定では .sig が作られなかった

執筆時の CLI では TAURI_SIGNING_PRIVATE_KEY_PATH で鍵を渡すと失敗しました。TAURI_SIGNING_PRIVATE_KEY に鍵の中身を渡します（ステップ 5）。

⚠️

tauri-action が Release を作れない

ワークフローの permissions に contents: write が無いと、Release を作れずに失敗します。既定のワークフロー権限が読み取りのみのリポジトリでは特にこの指定が必要です（ステップ 6）。

⚠️

Linux のジョブが依存パッケージ不足で失敗する

Linux のビルドには WebKitGTK（libwebkit2gtk-4.1-dev）などが必要です。ランナーの版は ubuntu-22.04 に固定します（ステップ 6）。

💡

パニックの原因が追いにくくなったら

strip = true と panic = "abort" を付けると、パニック時のバックトレースが読みにくくなります。原因を調べるときは、一時的に外してビルドします（ステップ 2）。

💡

requireSignedVersion で更新が拒否される

tauri add updater は requireSignedVersion: true を入れます。署名に対象のバージョンが入っていない更新は、エラーで拒否されます。updater のソースには、次の文言が定義されています。

The update signature does not specify the version it was signed for, which `requireSignedVersion` requires. Re-sign and re-publish this release, or disable `requireSignedVersion`.

まとめ

bundle の設定で作る形式と OS ごとの中身を決め、[profile.release] で実行ファイルを約 11.6 MB から約 5.0 MB に小さくしました。 ad-hoc 署名では Gatekeeper を通らないことを確かめ、配布に必要な Developer ID の署名と公証の流れを整理しました。 updater プラグインと署名鍵で更新の仕組みを組み込み、GitHub Actions で各 OS 向けにビルドして Release を作るワークフローを用意しました。

ℹ️

完成コード

このレッスンの完成コードは、ブランチ tauri/05-packaging の tauri/05-packaging/ ディレクトリにあります。updater の秘密鍵は含まれていません。tauri.conf.json の pubkey は執筆時に作った公開鍵なので、自分の鍵の公開鍵に置き換えて使ってください。
