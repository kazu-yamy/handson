概要

02 までは、Rust のコードには手を入れずに、設定ファイルとフロントエンドだけでアプリを作ってきました。 この項目から Rust のコードを書きます。フロントエンド（WebView 上の Next.js）から Rust の関数を呼び出す仕組みを使います。あいさつ文を返すコマンドから始めて、状態を持つ Todo リストと、進捗を知らせる重い処理まで作ります。

IPC の仕組み

フロントエンドと Rust はプロセス間通信（IPC）でやり取りします。invoke を呼んでから結果が返るまでの流れは次のとおりです。

順番場所起きること
1フロントエンドinvoke("greet", { userName: "World" }) を呼ぶ。引数のオブジェクトは JSON になって Rust へ送られる
2Rust（generate_handler!）コマンド名 greet で、登録済みのコマンドから呼び出す関数を探す
3Rust（serde）JSON の userName を、関数の引数 user_name に変換する（Deserialize）
4Rust（#[tauri::command]）関数を実行する
5Rust（serde）戻り値を JSON にする（Serialize）。Result の場合は Err の値も JSON にする
6フロントエンドOk なら invoke の Promise が resolve し、Err なら reject する

逆向きに、Rust からフロントエンドへ通知したいときは「イベント」を使います。Rust で emit し、フロントエンドで listen して受け取ります（ステップ 5）。

export function TodoList() {

  const [title, setTitle] = useState("");
  const [error, setError] = useState("");

  useEffect(() => {
    listTodos()
      .then(setTodos)
      .catch(() => setError("ブラウザで実行中（Tauri API は利用できません）"));

    const todo = await addTodo(title);
    setTodos((prev) => [...prev, todo]);

  };

      {error && <p className={styles.error}>{error}</p>}

          type="text"
          className={styles.input}
          placeholder="やることを入力"
          value={title}
          onChange={(e) => setTitle(e.target.value)}
        />
        <button type="button" className={styles.addButton} onClick={handleAdd}>
          追加
        </button>
      </div>
      <ul className={styles.items}>
        {todos.map((todo) => (
          <li key={todo.id} className={styles.item}>

              <input

              onClick={() => handleDelete(todo.id)}
            >
              削除
            </button>
          </li>
        ))}
      </ul>
    </section>
  );
}

/// `impl serde::Serialize` でフロントエンドに文字列として返す。
#[derive(Debug, thiserror::Error)]
enum AppError {
    #[error("タイトルを入力してください")]
    EmptyTitle,
    #[error("id {0} の Todo が見つかりません")]
    NotFound(u32),
}

impl Serialize for AppError {
    fn serialize<S>(&self, serializer: S) -> Result<S::Ok, S::Error>

        S: serde::Serializer,

        serializer.serialize_str(&self.to_string())

Rust src-tauri/src/lib.rs（impl Serialize for AppError の後ろに追加） 
// --- ここから下は Mutex や tauri::State から切り離した純粋関数。
// ロジック自体は `&mut Vec<Todo>` 等の素のデータ構造だけを操作するため、
// Tauri のモックアプリを使わないテスト（cargo test の高速なユニットテスト）がそのまま書ける。

fn add_todo_pure(
    todos: &mut Vec<Todo>,
    next_id: &mut u32,
    title: String,
) -> Result<Todo, AppError> {
    let title = title.trim().to_string();
    if title.is_empty() {
        return Err(AppError::EmptyTitle);
    }
    let id = *next_id;
    *next_id += 1;
    let todo = Todo {
        id,
        title,
        done: false,
        created_at: current_unix_time(),
    };
    todos.push(todo.clone());
    Ok(todo)
}

fn toggle_todo_pure(todos: &mut [Todo], id: u32) -> Result<Todo, AppError> {
    let todo = todos
        .iter_mut()
        .find(|t| t.id == id)
        .ok_or(AppError::NotFound(id))?;
    todo.done = !todo.done;
    Ok(todo.clone())
}

fn delete_todo_pure(todos: &mut Vec<Todo>, id: u32) -> Result<(), AppError> {
    let len_before = todos.len();
    todos.retain(|t| t.id != id);
    if todos.len() == len_before {
        Err(AppError::NotFound(id))
    } else {
        Ok(())
    }
}

上のログの Watching ... for changes... のとおり、tauri dev は src-tauri を監視しています。Rust のコードを保存すると、再コンパイルしてアプリのプロセスごと起動し直します。フロントエンドの変更が Fast Refresh ですぐ反映されるのとは違い、反映まで数秒から数十秒かかります。状態（AppState）もリセットされるので、追加した Todo は消えます。

use serde::{Deserialize, Serialize};

#[tauri::command]
fn greet(user_name: &str) -> String {
    format!("こんにちは、{user_name} さん！ Rust から呼び出されました。")
}

#[derive(Debug, Clone, Serialize, Deserialize)]
#[serde(rename_all = "camelCase")]
struct Todo {
    id: u32,
    title: String,
    done: bool,
    // rename_all = "camelCase" が無いと JSON のキーは created_at のままになり、
    // フロントの todo.createdAt は undefined になる。
    created_at: u64,
}

/// Todo の一覧と次に割り振る id を保持するアプリ状態。
/// `tauri::Builder::manage()` で登録し、各コマンドは `tauri::State<'_, AppState>` で受け取る。
struct AppState {
    todos: std::sync::Mutex<Vec<Todo>>,
    next_id: std::sync::Mutex<u32>,
}

impl AppState {
    fn new() -> Self {
        Self {
            todos: std::sync::Mutex::new(Vec::new()),
            next_id: std::sync::Mutex::new(1),
        }
    }
}

/// アプリ独自のエラー型。`thiserror` でメッセージを定義し、
/// `impl serde::Serialize` でフロントエンドに文字列として返す。
#[derive(Debug, thiserror::Error)]
enum AppError {
    #[error("タイトルを入力してください")]
    EmptyTitle,
    #[error("id {0} の Todo が見つかりません")]
    NotFound(u32),
    #[error("イベント送信に失敗しました: {0}")]
    Emit(String),
}

impl Serialize for AppError {
    fn serialize<S>(&self, serializer: S) -> Result<S::Ok, S::Error>
    where
        S: serde::Serializer,
    {
        serializer.serialize_str(&self.to_string())
    }
}

// --- ここから下は Mutex や tauri::State から切り離した純粋関数。
// ロジック自体は `&mut Vec<Todo>` 等の素のデータ構造だけを操作するため、
// Tauri のモックアプリを使わないテスト（cargo test の高速なユニットテスト）がそのまま書ける。

fn add_todo_pure(
    todos: &mut Vec<Todo>,
    next_id: &mut u32,
    title: String,
) -> Result<Todo, AppError> {
    let title = title.trim().to_string();
    if title.is_empty() {
        return Err(AppError::EmptyTitle);
    }
    let id = *next_id;
    *next_id += 1;
    let todo = Todo {
        id,
        title,
        done: false,
        created_at: current_unix_time(),
    };
    todos.push(todo.clone());
    Ok(todo)
}

fn toggle_todo_pure(todos: &mut [Todo], id: u32) -> Result<Todo, AppError> {
    let todo = todos
        .iter_mut()
        .find(|t| t.id == id)
        .ok_or(AppError::NotFound(id))?;
    todo.done = !todo.done;
    Ok(todo.clone())
}

fn delete_todo_pure(todos: &mut Vec<Todo>, id: u32) -> Result<(), AppError> {
    let len_before = todos.len();
    todos.retain(|t| t.id != id);
    if todos.len() == len_before {
        Err(AppError::NotFound(id))
    } else {
        Ok(())
    }
}

#[tauri::command]
fn add_todo(title: String, state: tauri::State<'_, AppState>) -> Result<Todo, AppError> {
    let mut next_id = state.next_id.lock().unwrap();
    let mut todos = state.todos.lock().unwrap();
    add_todo_pure(&mut todos, &mut next_id, title)
}

#[tauri::command]
fn list_todos(state: tauri::State<'_, AppState>) -> Vec<Todo> {
    state.todos.lock().unwrap().clone()
}

#[tauri::command]
fn toggle_todo(id: u32, state: tauri::State<'_, AppState>) -> Result<Todo, AppError> {
    let mut todos = state.todos.lock().unwrap();
    toggle_todo_pure(&mut todos, id)
}

#[tauri::command]
fn delete_todo(id: u32, state: tauri::State<'_, AppState>) -> Result<(), AppError> {
    let mut todos = state.todos.lock().unwrap();
    delete_todo_pure(&mut todos, id)
}

/// 進捗を `progress` イベントで通知しながら時間のかかる処理を模した非同期コマンド。
#[tauri::command]
async fn slow_task<R: tauri::Runtime>(app: tauri::AppHandle<R>) -> Result<(), AppError> {
    use tauri::Emitter;

    for percent in [0u8, 25, 50, 75, 100] {
        tokio::time::sleep(std::time::Duration::from_millis(200)).await;
        app.emit("progress", percent)
            .map_err(|e| AppError::Emit(e.to_string()))?;
    }
    Ok(())
}

fn current_unix_time() -> u64 {
    std::time::SystemTime::now()
        .duration_since(std::time::UNIX_EPOCH)
        .expect("system clock before unix epoch")
        .as_secs()
}

#[cfg_attr(mobile, tauri::mobile_entry_point)]
pub fn run() {
    tauri::Builder::default()
        .setup(|app| {
            if cfg!(debug_assertions) {
                app.handle().plugin(
                    tauri_plugin_log::Builder::default()
                        .level(log::LevelFilter::Info)
                        .build(),
                )?;
            }
            Ok(())
        })
        .manage(AppState::new())
        .invoke_handler(tauri::generate_handler![
            greet,
            add_todo,
            list_todos,
            toggle_todo,
            delete_todo,
            slow_task
        ])
        .run(tauri::generate_context!())
        .expect("error while running tauri application");
}

演習

以下のチェックリストを使って、このレッスンの内容を振り返りましょう。

つまずきポイント

⚠️

引数を渡しているのにコマンドがエラーになる

Rust の引数名が user_name なら、invoke では { userName: ... } と camelCase のキーで渡します。user_name のまま渡すとエラーになることを、ステップ 1 のテストで確かめました。一方、コマンド名は変換されないので、invoke("add_todo") のように snake_case のまま書きます。

⚠️

コマンドを追加したのに呼び出せない

generate_handler! への登録漏れを疑います。登録を忘れてもコンパイルは通るので、invoke を実行するまで気づけません（エラーは Command add_todo not found という文字列の reject です）。テスト用の make_full_app にも同じ一覧があるので、両方に追加します。

⚠️

フロントエンドで構造体のプロパティが undefined になる

構造体に #[serde(rename_all = "camelCase")] が付いているかを確認します。付いていないと、created_at は created_at のまま JSON になり、TypeScript の型で createdAt と書いていても値は届きません。

⚠️

Result を返すコマンドがコンパイルできない

Err の型が serde::Serialize を実装しているかを確認します。thiserror::Error の derive だけでは足りないので、impl Serialize for AppError を書きます。

⚠️

AppHandle を受け取るコマンドで、テストだけコンパイルエラーになる

AppHandle の型引数を省略すると既定のランタイムに固定され、MockRuntime を使うテストと合わなくなります。async fn slow_task<R: tauri::Runtime>(app: tauri::AppHandle<R>) のようにジェネリックにします。

💡

State を使うなら manage() を忘れない

State<'_, AppState> を引数に書いても、Builder::manage() で登録していなければ、呼び出した時点で reject されます（文言は state not managed for field `state` on command ...）。コンパイルは通るので注意しましょう。

💡

lock().unwrap() は連鎖的にパニックすることがある

ロックを持ったスレッドがパニックすると Mutex は poisoned になり、以降の lock().unwrap() もパニックします。

💡

listen は必ず解除する

listen() が返す unlisten を useEffect のクリーンアップで呼ばないと、再マウントのたびにリスナーが増え、同じイベントを何度も処理します。

💡

Rust の変更は反映に時間がかかる

tauri dev 中に src-tauri のコードを保存すると、再コンパイルとアプリの再起動が走ります。反映まで数秒から数十秒かかり、AppState の中身もリセットされます。

まとめ

#[tauri::command] と generate_handler! で Rust の関数をコマンドにし、フロントエンドから invoke で呼び出しました。 引数と戻り値は serde で JSON になるため、引数名は camelCase で渡し、構造体には rename_all を付けます。 さらに、State による状態の保持、Result と AppError によるエラー、async コマンドとイベントによる進捗の通知を実装し、IPC レベルのテストとユニットテストで確かめました。 次の項目では、Tauri のファイルシステム API とダイアログ API を使います。
