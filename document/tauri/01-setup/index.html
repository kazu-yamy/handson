🎯 このレッスンで学ぶこと

  • Tauri の仕組み（Rust 製のネイティブ部分 + OS の WebView）を把握する
  • Next.js を静的エクスポート（output: "export"）してフロントエンドとして用意する
  • @tauri-apps/cli を導入し、tauri init で src-tauri/ を作成する

  • npm run tauri dev で開発モードを起動し、npm run tauri build -- --debug で .app / .dmg を作る

概要

Tauri トラックの最初の項目です。Next.js で作った画面を、Tauri でデスクトップアプリとして動かすところまでをひと通り体験します。 以降の項目は、ここで作るプロジェクト（Next.js の静的エクスポート + src-tauri/）を前提に進めます。

Tauri とは

Tauri は、Web の技術（HTML / CSS / JavaScript）で画面を作り、デスクトップアプリとして配布するためのフレームワークです。 アプリ本体は Rust で書かれたネイティブの実行ファイルで、画面の表示には OS に組み込まれている WebView（macOS では WebKit）を使います。

同じ目的のフレームワークに Electron があります。Electron はブラウザーエンジン（Chromium）と Node.js をアプリごとに同梱しますが、Tauri は OS の WebView を使うため、ブラウザーエンジンを同梱しません。 その分、配布物が小さくなります。このレッスンで作るデバッグビルドの .dmg は約 7.5 MB です。

Next.js を組み込む構成

Tauri のアプリに Node.js のサーバーは含まれません。そこで Next.js を静的エクスポートし、できあがった HTML / JS / CSS を WebView に読み込ませます。 Tauri の設定ファイル tauri.conf.json では、開発時と本番ビルド時で読み込む先を切り替えます。

Text npm run tauri dev / build の流れ 
npm run tauri dev
  ├─ beforeDevCommand: npm run dev  → Next.js 開発サーバー（http://localhost:3000）
  └─ cargo run                      → ネイティブウィンドウの WebView が devUrl を表示

npm run tauri build
  ├─ beforeBuildCommand: npm run build → out/（静的な HTML / JS / CSS）
  └─ cargo build + バンドル            → frontendDist（../out）を同梱した .app / .dmg
コマンド読み込む先（設定キー）事前に実行されるコマンドWebView に表示されるもの
tauri devdevUrl: http://localhost:3000beforeDevCommand: npm run devNext.js の開発サーバーが返すページ
tauri buildfrontendDist: ../outbeforeBuildCommand: npm run buildアプリに同梱した out/ の静的ファイル

最後に、next.config.ts で静的エクスポートを有効にします。この設定が Tauri に組み込むための要です。

Diff next.config.ts 
  import type { NextConfig } from "next";   const nextConfig: NextConfig = {-   /* config options here */+   output: "export",+   images: {+     unoptimized: true,+   },  };   export default nextConfig;
  • output: "export": next build の結果を、サーバーなしで配信できる静的ファイル（HTML / JS / CSS）として out/ に書き出します。
  • images.unoptimized: true: Next.js の <Image> の画像最適化を無効にします。画像最適化はリクエストのたびにサーバーで画像を変換する仕組みのため、サーバーのない静的エクスポートでは使えません。
⚠️

output: "export" が必須な理由

Tauri は、ビルドした静的ファイルをアプリ本体に同梱し、WebView に読み込ませます。アプリの中に Node.js のサーバーはありません。Next.js の既定のビルド成果物はサーバーで動かす前提なので、そのままでは Tauri に組み込めません。output: "export" を指定して、out/ だけで完結する静的ファイルを出力させます。

3

Tauri CLI を導入して tauri init を実行する

Tauri の CLI（@tauri-apps/cli）を開発用の依存としてプロジェクトに入れます。CLI は npm パッケージとして配布されているので、グローバルにインストールする必要はありません。

Terminal 
$ npm i -D @tauri-apps/cli@latestadded 2 packages, and audited 356 packages in 2sfound 0 vulnerabilities$ npx tauri --versiontauri-cli 2.11.5

次に tauri init で、Rust 側のプロジェクト src-tauri/ を作ります。対話形式でも作れますが、ここでは設定をすべてフラグで渡します。コマンドは何も出力せずに終わります。

Terminal 
$ npx tauri init --ci \  --app-name "handson-tauri-01" \  --window-title "handson-tauri-01" \  --frontend-dist "../out" \  --dev-url "http://localhost:3000" \  --before-dev-command "npm run dev" \  --before-build-command "npm run build"

各フラグの意味は次のとおりです（npx tauri init --help の説明に基づきます）。

フラグ意味
--ci値の入力プロンプトを出さない（非対話で実行する）
--app-nameアプリ名。tauri.conf.json の productName になる
--window-titleウィンドウのタイトル
--frontend-dist本番ビルドで同梱する Web 資産の場所（src-tauri/ からの相対パス）。ステップ 2 の out/ を指す
--dev-url開発時に表示する開発サーバーの URL
--before-dev-commandtauri dev の前に実行するコマンド（Next.js の開発サーバー起動）
--before-build-commandtauri build の前に実行するコマンド（静的エクスポート）

生成された src-tauri/ の主なファイルと役割は次のとおりです。

ファイル役割

lib.rs の全文です。このレッスンでは Rust のコードを書きません。tauri::Builder がアプリを組み立て、tauri::generate_context!() が tauri.conf.json の内容を取り込む、という流れだけ押さえておきましょう。デバッグビルドのときだけログ用のプラグイン（tauri_plugin_log）を有効にしています。

Rust src-tauri/src/lib.rs 
#[cfg_attr(mobile, tauri::mobile_entry_point)]
pub fn run() {
  tauri::Builder::default()
    .setup(|app| {
      if cfg!(debug_assertions) {
        app.handle().plugin(
          tauri_plugin_log::Builder::default()
            .level(log::LevelFilter::Info)
            .build(),
        )?;
      }
      Ok(())
    })
    .run(tauri::generate_context!())
    .expect("error while running tauri application");
}
ℹ️

開発時のバイナリ名は app

Cargo.toml の [package] の name は app です。そのため、開発時に起動する実行ファイルは target/debug/app になります。productName（handson-tauri-01）はバンドル名（.app や .dmg）や、Info.plist の CFBundleName などに使われます。

✅ 確認ポイント

プロジェクト直下に src-tauri/ ができていることを確認します。tauri.conf.json の build.frontendDist が ../out、build.devUrl が http://localhost:3000 になっていることを確認してください。

設定を調整して @tauri-apps/api を使う

生成された設定を調整し、ページから Tauri の API を呼び出してみます。まず identifier を変更します。

⚠️

identifier は必ず変更する

identifier はアプリを一意に識別する逆ドメイン形式の ID（例: com.handson.tauri01）です。--app-name を指定しても、tauri init は既定値の com.tauri.dev のまま生成しますが、この既定値のままだと tauri build（ステップ 6）が「The default value `com.tauri.dev` is not allowed」というエラーで失敗します。macOS のバンドル ID や各ストアへの登録にも使われるため、公開する場合はこの値を使います。

@tauri-apps/api はブラウザでは動かない

getVersion などの関数は、内部で window.__TAURI_INTERNALS__ を呼び出します。この値は Tauri の WebView の中でだけ注入されます。npm run dev で起動した Next.js のページを通常のブラウザで開くと、呼び出しは reject されます。そのため .catch() でブラウザ用の表示（ブラウザで実行中（Tauri API は利用できません））を用意しています。

続いて、ESLint の対象から Rust のビルド成果物を外します。src-tauri/target/ には、次のステップ以降の Rust のビルドで JavaScript のファイルも生成されます。これが ESLint の対象に入ると、npm run lint がエラー（実装時は 10 errors / 2 warnings）になります。

5

npm run tauri dev で開発モードを起動する

開発モードでアプリを起動します。tauri dev は、まず beforeDevCommand（npm run dev）で Next.js の開発サーバーを起動します。devUrl（http://localhost:3000）へ接続できるようになったら、Rust 側をビルドしてネイティブのウィンドウを開きます。

💡

先にポート 3000 の空きを確認する

tauri dev は devUrl の応答を待たずに起動します。ポート 3000 を別のプロセスが使っていると、WebView にはその別のアプリの画面が表示されてしまいます。起動前に lsof -iTCP:3000 -sTCP:LISTEN で空いていることを確認してください（何も表示されなければ空いています）。Next.js のページが出ないときは、まずポート 3000 の使用状況を確認してください。

初回のコンパイルは時間がかかる

初回は Rust の依存クレート約 350 個をすべてビルドするため、数十秒かかります（執筆環境では 35.02 秒）。2 回目以降は差分だけをビルドするので短くなります。止まって見えても、進捗表示が進んでいれば待ってください。

ウィンドウが開いたら、表示を確認します。ウィンドウ（800×600）に、見出し「Hello, Tauri!」と、tauri.conf.json の version に基づく「Tauri アプリのバージョン: 0.1.0」が表示されます。

プロセスが残った場合

Ctrl + C で止まらない場合は、次のコマンドでアプリ・Tauri CLI・Next.js の開発サーバーを個別に止めてください。開発時に起動するのは target/debug/app なので、pgrep -fl handson-tauri-01 では見つかりません。pgrep -fl "target/debug/app" のようにバイナリのパスで探してください。

なぜ --debug を付けるのか

--debug を付けない tauri build は、最適化を行うリリースビルド（cargo build --release）になり、ビルド時間が大幅に長くなります。このレッスンの目的は「ビルドが通り、.app ができること」の確認なので、デバッグビルドで十分です。

⚠️

未署名の .app と Gatekeeper

今回のビルドはコード署名をしていません。未署名の .app を Finder から開いたり、ほかの Mac に配ったりすると、macOS の Gatekeeper に警告される場合があります。このレッスンでは生成物ができたことの確認までにとどめ、動作確認はステップ 5 の tauri dev で行います。署名と公証は 05（パッケージングと配布）で扱います。

仕上げに、ステップ 4 で追加した ESLint の除外設定が効いていることを確かめます。src-tauri/target/ にビルド成果物ができた状態でも、エラーなく終わります。

つまずきポイント

⚠️

ウィンドウに別のアプリの画面が表示される

ポート 3000 を別のプロセス（ほかの Next.js の開発サーバーなど）が使っていると、tauri dev は待たずに起動し、WebView にはその 3000 番を占有している別のアプリの画面が表示されます。Next.js のページが出ないときは、lsof -iTCP:3000 -sTCP:LISTEN で使用中のプロセスを確認し、止めてから起動し直してください。

⚠️

npm run lint が src-tauri/target/ の中でエラーになる

eslint.config.mjs の globalIgnores に src-tauri/target/** を追加し忘れたとします。すると Rust のビルドを一度でも実行した後は、ビルドキャッシュ内の生成 JS を ESLint が解析してエラーになります。ステップ 4 の設定を確認してください。

💡

2 回目以降の起動は速くなる

初回の tauri dev は依存クレートをすべてビルドするため数十秒かかりますが、2 回目以降は差分だけをビルドします。ステップ 6 のビルドでは、コンパイルが 14.71 秒で終わりました。
