ウィンドウ設定とビルド

  • ⏱ 所要時間: 30分
  • 📊 難易度: 入門
  • 👤 対象: Tauri 01 を終えた人。Rust のコードは書きません
  • 📋 前提: macOS（透明タイトルバーとアイコン生成の手順は macOS 前提）、01 と同じ開発環境
  • 🔗 前提となる項目: 01: 環境構築とプロジェクト作成

🎯 このレッスンで学ぶこと

  • tauri.conf.json の app.windows でウィンドウのサイズ・位置・テーマを設定する
  • titleBarStyle: "Overlay" と data-tauri-drag-region で、透明なタイトルバーとドラッグ領域を作る
  • 2 つ目のウィンドウを定義し、Capabilities で権限を許可してフロントエンドから開く
  • tauri icon でアイコンを差し替え、version とバンドルのメタデータを設定する
  • npm run tauri build でリリースビルドを作り、デバッグビルドとの違いを知る

概要

01 では、Next.js の静的エクスポートを Tauri に組み込み、デバッグビルドの .app を作りました。 この項目では、設定ファイル tauri.conf.json を中心にウィンドウの見た目と振る舞い・アイコン・バージョンを整えます。最後に、配布に使うリリースビルドを作ります。

tauri.conf.json の構造

01 の完成時点の tauri.conf.json は、大きく次の 4 つの部分でできています。このレッスンで触るのは app.windows と bundle、トップレベルの version などです。

キー役割このレッスンで変更する内容
productName / version / identifierアプリ名・バージョン・一意な ID02 用の名前と ID、version を 0.2.0 に（準備・ステップ 5）
buildフロントエンドの読み込み先（devUrl / frontendDist）と、事前に実行するコマンド変更しない（01 で設定済み）
app.windows起動時に作るウィンドウの一覧と、それぞれの設定サイズ・タイトルバーの設定、2 つ目のウィンドウ（ステップ 1〜3）
bundle配布物（.app / .dmg など）の作り方。アイコン、説明、カテゴリなどメタデータの追加（ステップ 5）。アイコンはファイルを差し替える（ステップ 4）

app には windows のほかに、01 から変更しない security（CSP の設定）があります。

ℹ️

使用バージョン

使用するツールとライブラリのバージョンは 01 と同じです。Tauri 関連は Tauri CLI 2.11.5 / tauri クレート 2.11.6 / @tauri-apps/api 2.11.1 です。そのほかは Next.js 16.3.6 / rustc 1.98.1 / Node.js 24.21.0 などです。 バージョンは執筆時点（2026年9月）のものです。

手順

1

ウィンドウの基本設定をする

tauri.conf.json の app.windows は、起動時に開くウィンドウの配列です。01 では要素が 1 つだけで、tauri init が生成した title / width / height / resizable / fullscreen だけが書かれていました。ここに最小サイズ・中央配置・テーマの設定を加えます。

Diff src-tauri/tauri.conf.json 
  ...    "app": {      "windows": [        {-         "title": "handson-tauri-01",+         "title": "handson-tauri-02",          "width": 800,          "height": 600,+         "minWidth": 480,+         "minHeight": 360,          "resizable": true,-         "fullscreen": false+         "fullscreen": false,+         "center": true,+         "theme": null        }      ],  ...

各キーの意味は次のとおりです（説明は node_modules/@tauri-apps/cli/config.schema.json の記述に基づきます）。

キー意味既定値
titleウィンドウのタイトルTauri App
width / heightウィンドウの幅と高さ（論理ピクセル）800 / 600
minWidth / minHeightウィンドウの最小の幅と高さ（論理ピクセル）なし
resizableリサイズできるか。false にすると最大化ボタンも無効になるtrue
fullscreenフルスクリーンで起動するかfalse
center画面の中央に配置して起動するかfalse
themeウィンドウの初期テーマ（"Light" / "Dark"）。null または省略で OS の設定に従う。Windows と macOS 10.14 以降のみなし（OS の設定）

theme は既定値と同じ null ですが、「OS の設定に従う」ことを明示するために書いています。設定できたら、開発モードで起動します。

💡

ウィンドウのサイズをコマンドで確かめる

macOS では、System Events（アクセシビリティ）経由でウィンドウの名前・位置・サイズを取得できます。初回はターミナルにアクセシビリティの許可を求められる場合があります。許可してもウィンドウの一覧が取得できず、空の結果（,,）が返る環境もあります。その場合はターミナルのアクセシビリティ権限（システム設定 → プライバシーとセキュリティ → アクセシビリティ）を見直すか、画面を直接見てサイズを確認してください。結果は「名前・X・Y・幅・高さ」の順に並びます。位置の値は画面の大きさによって変わります。

Terminal 
$ osascript -e 'tell application "System Events" to tell process "handson-tauri-02" to get {name, position, size} of every window'handson-tauri-02, 1520, 795, 800, 600

確認できたら、tauri dev を実行しているターミナルで Ctrl + C を押して止めます。止まらない場合は、01 と同じ要領でプロセスを個別に止めます。実行ファイル名が変わったので、パスも handson-tauri-02 になります。

Terminal 
$ pkill -f "target/debug/handson-tauri-02"$ pkill -f "node_modules/.bin/tauri"$ pkill -f "node_modules/.bin/next dev"

✅ 確認ポイント

800×600 のウィンドウが画面の中央に開き、タイトルが handson-tauri-02 になっていれば成功です。実際にウィンドウの端をドラッグして縮め、480×360 より小さくならないことを目で確認してください。

2

タイトルバーを透明にしてドラッグ領域を作る

macOS の標準のタイトルバーを透明にし、ページの内容をウィンドウの最上部まで広げます。左上のトラフィックライト（閉じる・最小化・拡大の赤黄緑ボタン）はそのまま残ります。titleBarStyle と hiddenTitle を追加します。

Diff src-tauri/tauri.conf.json 
  ...          "center": true,-         "theme": null+         "theme": null,+         "titleBarStyle": "Overlay",+         "hiddenTitle": true        }      ],  ...
  • titleBarStyle: "Overlay": タイトルバーを透明にし、トラフィックライトをページの内容の上に重ねて表示します。既定値は "Visible"（通常のタイトルバー）です。
  • hiddenTitle: true: タイトルバーのタイトル文字列を隠します。

タイトルバーが透明になると、ウィンドウをつかんで動かす場所がなくなります。そこで、ページの上端にドラッグ用の領域を作ります。ルート専用の部品を置く src/app/_components/ に、TitleBar コンポーネントを 1 コンポーネント 1 フォルダで作ります。

TypeScript src/app/_components/TitleBar/TitleBar.tsx 
import styles from "./TitleBar.module.scss";

export function TitleBar() {
  return (
    <header className={styles.titleBar} data-tauri-drag-region>
      <span className={styles.label} data-tauri-drag-region>
        handson-tauri-02
      </span>
    </header>
  );
}

data-tauri-drag-region 属性を付けた要素をマウスでつかむと、ウィンドウ全体をドラッグして動かせます。header だけでなく中の span にも付けているのは、この属性が付けた要素自身にしか効かず、子要素には伝わらないためです（Tauri 2 では data-tauri-drag-region="deep" を付けると子要素にも効くようになります）。padding-left: 78px は、左上に重なるトラフィックライトの分の余白です。

最後に、ドラッグ領域を使うための権限を追加します。data-tauri-drag-region の領域をドラッグすると、フロントエンドから Tauri の start_dragging コマンドが呼ばれます。01 で許可した core:default にはこのコマンドが含まれないため、core:window:allow-start-dragging を明示的に許可します。

Diff src-tauri/capabilities/default.json 
  ...    "windows": [      "main"    ],    "permissions": [-     "core:default"+     "core:default",+     "core:window:allow-start-dragging"    ]  }

windows の "main" は、この権限を与えるウィンドウのラベルです。app.windows で label を省略したウィンドウのラベルは main になります。

ℹ️

Capabilities（権限）の仕組み

Tauri 2 では、フロントエンドから呼べる Tauri のコマンドを src-tauri/capabilities/ の JSON で許可制にしています。許可していないコマンドを呼ぶと、エラーになります（実際のエラーはステップ 3 で確認します）。core:default はウィンドウの状態の取得など、読み取り中心の基本的なコマンドだけを含むセットです。

npm run tauri dev で起動し直して、見た目を確かめます。

試してみる: decorations: false との違い

比較のため、app.windows[0] に一時的に "decorations": false を追加して起動してみます。decorations は「ウィンドウの枠やバーを表示するか」の設定で、既定値は true です。既定（decorations を指定しない通常時）では、トラフィックライト（閉じる・最小化・拡大のボタン）が左上に表示されます。decorations: false にすると、このトラフィックライトを含む OS 標準のウィンドウ装飾がすべて消えます。閉じるボタンもなくなるため、閉じる手段を自前で用意しない限り不便です。確かめたら "decorations": false を削除して、元の設定に戻してください。

⚠️

titleBarStyle は macOS 専用

titleBarStyle と hiddenTitle は macOS 専用の設定です。スキーマの説明もそれぞれ「macOS のタイトルバーのスタイル」「macOS でタイトルを隠す」となっています。複数の OS に配布する場合は、Windows / Linux 向けの見た目を別途確認してください。

✅ 確認ポイント

タイトルバーが透明になり、トラフィックライトがページの左上に重なって表示されます。上端の中央に handson-tauri-02 のラベルが表示されます。実際に上端の帯をドラッグして、ウィンドウを移動できることを目で確認してください。確認後は Ctrl + C で止めます。

3

2 つ目のウィンドウを追加する

app.windows に 2 つ目の要素を追加すると、起動時に作られるウィンドウが増えます。ボタンを押したときに開く「About」ウィンドウを、最初は非表示の状態で定義します。

Diff src-tauri/tauri.conf.json

実装時の確認方法について

演習

以下のチェックリストを使って、このレッスンの内容を振り返りましょう。

つまずきポイント

⚠️

data-tauri-drag-region を付けたのにドラッグできない

まず capabilities/default.json に core:window:allow-start-dragging があるかを確認します。次に、属性を付けた要素の上をつかんでいるかを確認します。この属性は付けた要素自身にしか効かず、子要素には伝わりません。TitleBar で中の span にも属性を付けているのはこのためです。逆に、ボタンなどクリックしたい要素に付けると、クリックではなくドラッグとして扱われます。

⚠️

ボタンを押しても About ウィンドウが開かない

show() / setFocus() は、capabilities/default.json での許可が必要です。許可がないと Promise が reject されますが、画面には何も出ないので「何も起きない」ように見えます。tauri dev のターミナルに window.show not allowed などのエラーが出ていないかを確認してください。

⚠️

ビルドしたアプリで About ウィンドウのページが見つからない

output: "export" の既定では /about は out/about.html として出力され、ウィンドウの url: "/about/" と形が合いません。next.config.ts に trailingSlash: true があるか、out/about/index.html ができているかを確認してください。trailingSlash を使わない場合は、url を /about.html にする方法もあります。

💡

visible: false のウィンドウも起動時に読み込まれる

visible: false は「表示しない」だけで、ウィンドウとページは起動時に作られます。tauri dev の起動直後に GET /about/ 200 が出るのはこのためです。定義するウィンドウが増えるほど、起動時の読み込みも増えます。

💡

tauri icon の元画像は正方形にする

npm run tauri icon --help の説明では、入力は正方形の PNG または SVG とされています。このレッスンでは 1024×1024 の PNG を使いました。渡す前に sips -g pixelWidth -g pixelHeight で縦横のサイズを確かめておくと安心です。

💡

リリースビルドは時間がかかる

執筆環境では、リリースビルドが約 1 分 25 秒、デバッグビルドが約 40 秒でした。リリースビルドは依存クレートも最適化付きでコンパイルするため、初めて実行するときはさらに長くなる場合があります。開発中の動作確認は tauri dev で行い、リリースビルドは配布物を作るときだけにしましょう。

💡

getVersion() の値が変わらない

getVersion() が返すのは tauri.conf.json の version です。package.json や Cargo.toml の version を変えても、表示は変わりません。
