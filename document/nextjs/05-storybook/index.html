Storybook でのコンポーネントカタログ構築

  • ⏱ 所要時間: 45分
  • 📊 難易度: 入門
  • 👤 対象: 04 を終え、作った部品をページから切り離して開発・確認したい人
  • 📋 前提: React のコンポーネントと props、TypeScript の型の基本が分かること
  • 🌐 ネットワーク: npm パッケージと Playwright 用ブラウザ（Chromium）のダウンロードが必要
  • 🔗 前提となる項目: 04: クライアントコンポーネントと状態管理

🎯 このレッスンで学ぶこと

  • Next.js（App Router）のプロジェクトに Storybook を導入し、起動・静的ビルドできる
  • CSF3（Meta / StoryObj / args）でストーリーを書き、Controls と Docs で確認できる
  • fn() と Actions でコールバックの呼び出しを、argTypes で Controls の入力部品を調整できる
  • children を受け取る部品や、usePathname を使う部品のストーリーを書ける
  • play 関数でインタラクションテストを書き、Vitest でコマンドから実行できる

概要

04 までは、部品の見た目や動きをアプリのページに組み込んでから確かめていました。この方法では、「いいね 10 の状態」「一覧が開いた状態」のように、特定の状態を見るたびにページを操作する必要があります。 このレッスンでは Storybook を導入し、04 までに作った LikeButton / Collapsible / Header をページから切り離して表示できるようにします。

Storybook とは

Storybook は、UI の部品（コンポーネント）をアプリ本体から切り離して表示・開発するためのツールです。 部品の「ある状態」を 1 つのストーリーとして書いておくと、ブラウザ上の一覧（コンポーネントカタログ）からいつでもその状態を開けます。

うれしいこと内容このレッスンでの例
コンポーネント単位の開発ページやデータ取得を用意しなくても、部品だけを表示して作業できるHeader をルーティングなしで表示する
状態の網羅props の組み合わせごとの見た目を並べて確認できる。Controls で props をその場で変えられるいいね 0 / 10、一覧の開閉
ドキュメントprops の一覧とストーリーのプレビューをまとめたページを自動生成できるtags: ["autodocs"]
テスト操作と検証をストーリーに書き、コマンドから一括実行できるplay 関数と Vitest

手順

作業はプロジェクトのディレクトリで行います。Next.js の開発サーバー（ポート 3000）は使わないので、起動している場合は止めておいてかまいません。

💡

Storybook の起動と停止

npm run storybook は、ポート 6006 で Storybook の開発サーバーを起動します。ポート番号は、storybook init が package.json に書き込んだ -p 6006 で決まります。 Next.js の開発サーバー（ポート 3000）とはぶつかりませんが、Storybook を 2 つ同時に起動するとポートが競合します。確認が終わるたびに Ctrl + C で停止してください。 バックグラウンドで起動した場合は pkill -f "storybook dev -p 6006" で止められます。 ストーリーファイルを保存すると表示は自動で更新されるため、ステップ 3〜7 は起動したままでも進められます。

💡

SCSS と @/ のパスエイリアスは追加設定なしで動く

@storybook/nextjs-vite は Vite をベースにしています。Vite は .scss の Sass コンパイルと、*.module.scss の CSS Modules 変換を標準でサポートしています。 また、tsconfig.json の paths（"@/*": ["./src/*"]）も解決されるため、import '@/styles/globals.scss' はそのまま通ります。 グローバル CSS は preview.tsx で 1 回読み込めば十分で、各コンポーネントの .module.scss には何もする必要はありません。

3

LikeButton の最初のストーリーを書く

04 で作った LikeButton のストーリーを書きます。ストーリーファイルは LikeButton.tsx と同じフォルダに LikeButton.stories.tsx として作ります。

TSX src/components/LikeButton/LikeButton.stories.tsx 
import type { Meta, StoryObj } from "@storybook/nextjs-vite";
import { LikeButton } from "./LikeButton";

const meta = {
  title: "Components/LikeButton",
  component: LikeButton,
  tags: ["autodocs"],
} satisfies Meta<typeof LikeButton>;

export default meta;
type Story = StoryObj<typeof meta>;

export const Default: Story = {
  args: {
    postId: 1,
    initialCount: 0,
  },
};

export const WithInitialCount: Story = {
  args: {
    postId: 1,
    initialCount: 10,
  },
};

この書き方を CSF3（Component Story Format 3）と呼びます。ファイルは「default export の meta」と「名前付き export のストーリー」でできています。

要素役割
meta（default export）このファイルのストーリーすべてに共通する設定。component で対象のコンポーネントを指定する
titleサイドバーでの位置。/ で階層を区切る（Components/LikeButton → Components の下の LikeButton）
tags: ["autodocs"]このコンポーネントのドキュメントページ（Docs）を自動生成する
satisfies Meta<typeof LikeButton>meta の形を型でチェックしつつ、meta 自身の型は推論させる。StoryObj<typeof meta> がそれを使う
名前付き export（Default など）1 つのストーリー = コンポーネントの 1 つの状態。export 名がストーリー名になる
argsそのストーリーでコンポーネントに渡す props

Default は「いいね 0」の状態、WithInitialCount は「いいね 10」から始まる状態です。 このように、アプリの画面では作りにくい状態も、args を変えたストーリーとして並べておけます。

ℹ️

ストーリーファイルはコンポーネントと同じフォルダに置く

構成規約では、src/components/<Name>/ に <Name>.tsx / <Name>.module.scss / <Name>.stories.tsx を同居させます。 リポジトリ直下の .vscode/settings.json では file nesting を設定しています。そのため、VS Code のエクスプローラーでは LikeButton.stories.tsx が LikeButton.tsx の下に折りたたまれて表示されます。 ファイルが増えても、フォルダの見た目は散らかりません。

✅ 確認ポイント

npm run storybook で起動し、ブラウザで次の順に操作します。

  1. 左のサイドバーで Components > LikeButton を開き、Default と WithInitialCount が並んでいることを確認する。
  2. Default を選び、中央のプレビューに「👍 いいね 0」のボタンが表示されることを確認する。ボタンをクリックすると数が増える。
  3. WithInitialCount を選び、「👍 いいね 10」から始まることを確認する。
  4. アドオンパネル（プレビューの下）の Controls タブを開き、postId と initialCount の入力欄が並んでいることを確認する。
  5. サイドバーの LikeButton 直下にある Docs を開き、props の一覧表（名前・型）と各ストーリーのプレビューが 1 ページにまとまっていることを確認する。
⚠️

initialCount を Controls で変えても表示が変わらないとき

LikeButton は initialCount を useState の初期値としてだけ使っています。React の useState は初回の描画でしか初期値を読まないため、表示は「いいね 0」のまま変わりません（useState の初期値だけに使われるため）。 ツールバーの「Reload story」ボタン（ストーリーの再読み込み）を押すと「いいね 10」になります。別のストーリーに移ってから戻っても反映されます。

4

⚠️

コールバックは setCount の updater 関数の外で呼ぶ

setCount((current) => { ...; onLiked?.(next); return next; }) のように updater 関数の中で onLiked を呼ぶと、React の StrictMode では開発時に updater が 2 回呼ばれるため、onLiked も 2 回呼ばれてしまいます（updater は副作用のない純粋関数であるべきです）。 Next.js の App Router は開発時に StrictMode が既定で有効なので、この問題はアプリ側で起こります。Storybook 上では 1 回しか呼ばれないため気づきにくく、注意が必要です。

onLiked は省略可能（?）にしているので、アプリ本体の blog/[slug]/page.tsx は変更不要です。 04 で確認したとおり、サーバーコンポーネントからクライアントコンポーネントへ関数は渡せないため、アプリ側では今後も onLiked を渡しません。

  • argTypes は Controls パネルの入力部品を調整します。ここでは initialCount を、0 未満にならない数値入力にしています。
⚠️

エディタに [71007] の警告が出るが、ビルドには影響しない

"use client" のファイルの props に関数型（onLiked）を追加すると、VS Code などのエディタに 04 のステップ 3 と同じ警告が出ます。 「Props must be serializable for components in the "use client" entry file.」（コード 71007）という警告です。 これは Next.js の TypeScript プラグイン（エディタ上の言語サーバー）だけが出す注意で、npm run build の型チェックでは警告やエラーになりません。 サーバーコンポーネントからこの props に関数を渡さない限り実害はないので、Storybook の Actions で使う用途に限ってこのままにします。

✅ 確認ポイント

Storybook を開き直して、次の順に操作します。

  1. Components > LikeButton > Default を開く。
  2. プレビューのボタンをクリックし、アドオンパネルの Actions タブに onLiked の呼び出しが引数 1 とともに記録されることを確認する。もう一度クリックすると 2 が記録される。
  3. Controls タブの initialCount が、増減ボタン付きの数値入力になっていることを確認する（min: 0 により 0 より小さくできない）。
5

children を受け取る Collapsible のストーリーを書く

04 で作った Collapsible は、children に中身の JSX を受け取る開閉パネルです。 children は必須の props なので、ストーリーでも何かを渡す必要があります。

TSX src/components/Collapsible/Collapsible.stories.tsx 
import type { Meta, StoryObj } from "@storybook/nextjs-vite";
import { Collapsible } from "./Collapsible";

// children に JSX を渡す例で共通して使うダミーの中身。
// Collapsible は Next.js のアプリ内では children としてサーバーコンポーネント（AuthorList）を
// 受け取るが、Storybook 上では Collapsible 自身の開閉の振る舞いを確認したいだけなので、
// 代わりに簡単な静的 JSX を渡している。
const sampleChildren = (
  <ul>
    <li>Leanne Graham</li>
    <li>Ervin Howell</li>
    <li>Clementine Bauch</li>
  </ul>
);

const meta = {
  title: "Components/Collapsible",
  component: Collapsible,
  tags: ["autodocs"],
  args: {
    children: sampleChildren,
  },
} satisfies Meta<typeof Collapsible>;

export default meta;
type Story = StoryObj<typeof meta>;

export const Default: Story = {
  args: {
    title: "著者一覧",
  },
  // render 関数の引数 args から children を受け取り、そのまま Collapsible に渡す。
  render: (args) => <Collapsible {...args} />,
};

// defaultOpen で最初から開いた状態を確認する。
export const Open: Story = {
  args: {
    title: "著者一覧",
    defaultOpen: true,
  },
  render: (args) => <Collapsible {...args} />,
};
  • meta.args.children に、全ストーリー共通のダミーの <ul> を持たせています。
  • render 関数は、ストーリーの描画方法を自分で書くための関数です。引数の args（children を含む）をそのまま <Collapsible {...args} /> に展開しています。
  • Open では、既存の props defaultOpen に true を渡し、最初から開いた状態を確認します。
⚠️

children を meta.args に置かないと型エラーになる

StoryObj<typeof meta> の args の型は、component に指定したコンポーネントの props から作られます。Collapsible は children が必須です。そのため、args のどこかで children を渡していないと Property 'children' is missing という型エラーになります。 render の中で JSX を直接書いて渡すだけでは、この型エラーは消えません。 meta.args に既定値を置いておけば、各ストーリーは title や defaultOpen だけを書けば済みます。

💡

サーバーコンポーネントの中身はダミーで置き換える

アプリの blog/page.tsx では、Collapsible の children にサーバーコンポーネントの AuthorList を渡していました。AuthorList は fetch を行う async コンポーネントです。 Storybook で確かめたいのは Collapsible 自身の開閉の振る舞いなので、中身は静的な JSX で代用しています。 「開閉の振る舞い」と「著者一覧のデータ取得」は、別々に確認する対象として切り分けます。

✅ 確認ポイント

  1. サイドバーの Components > Collapsible に Default と Open が並んでいることを確認する。
  2. Default を開くと、先頭の三角が ▸ のタイトル行だけが表示される。クリックすると ▾ に変わり、Leanne Graham / Ervin Howell / Clementine Bauch の一覧が開く。
  3. Open を開くと、最初から ▾ で一覧が見えている。
  4. Controls タブで title の文字列を書き換えると、タイトル行の表示がその場で変わる。
6

usePathname を使う Header のストーリーを書く

02 で作った Header は、next/navigation の usePathname() で現在のパスを取得し、該当するリンクを強調します。 Storybook にはアプリのルーティングがないため、usePathname() が返す値をストーリーの側で指定します。 ファイルは Header.tsx と同じ src/app/_components/Header/ に作ります。

TSX src/app/_components/Header/Header.stories.tsx 
import type { Meta, StoryObj } from "@storybook/nextjs-vite";
import { Header } from "./Header";

const meta = {
  title: "App/Header",
  component: Header,
  tags: ["autodocs"],
  parameters: {
    // Header は next/navigation の usePathname を使うため、
    // @storybook/nextjs-vite の Next.js 用モックで App Router の状態を再現する。
    nextjs: {
      appDirectory: true,
    },
    layout: "fullscreen",
  },
} satisfies Meta<typeof Header>;

export default meta;
type Story = StoryObj<typeof meta>;

// pathname を "/" にして、Home が現在ページとして強調されることを確認する。
export const Home: Story = {
  parameters: {
    nextjs: {
      navigation: {
        pathname: "/",
      },
    },
  },
};

// pathname を "/blog" にして、Blog が現在ページとして強調されることを確認する。
export const Blog: Story = {
  parameters: {
    nextjs: {
      navigation: {
        pathname: "/blog",
      },
    },
  },
};
  • parameters.nextjs.appDirectory: true は「App Router のコンポーネントとして扱う」という指定です。 これにより、next/navigation（App Router 用）のフックが Storybook 用のモックに差し替わります。meta に書いたので、このファイルの全ストーリーに効きます。
  • 各ストーリーの parameters.nextjs.navigation.pathname に書いた値が、そのまま usePathname() の戻り値になります。 自前でモックを書く必要はありません。
  • layout: "fullscreen" は、プレビューの余白をなくして画面幅いっぱいに表示する指定です。ヘッダーのように横幅いっぱいに広がる部品に向いています。
  • title は App/Header とし、再利用部品（Components/）ではなくアプリ専用の部品であることがサイドバーで分かるようにしています。
ℹ️

ThemeToggle は追加設定なしで動く

Header の中の ThemeToggle は、04 のとおり useEffect の中でだけ localStorage / matchMedia を読みます。 Storybook はブラウザで動くので window が常にあり、window is not defined は起きません。 同じ理由で、Storybook 上では "use client" の有無を意識する必要はなく、どのコンポーネントも普通の React コンポーネントとして描画されます。

✅ 確認ポイント

  1. サイドバーの App > Header に Home と Blog が並んでいることを確認する。
  2. Home を開くと、ナビゲーションの Home リンクだけが強調色（アクティブ状態のスタイル）になっている。
  3. Blog を開くと、強調が Blog リンクに移る。ページ遷移は起きておらず、usePathname() の戻り値だけが差し替わっている。
  4. 右側のテーマ切り替えボタン（🌙 ダーク）をクリックすると、プレビュー内のテーマ色が切り替わる。
7

play 関数でインタラクションテストを書き、コマンドで実行する

ここまでのストーリーは、状態を「目で見て」確かめるものでした。play 関数を使うと、ストーリーを表示したあとに行う操作と、その結果の検証をコードで書けます。 LikeButton.stories.tsx に、クリックで数が増えることを検証するストーリーを追加します。

Diff src/components/LikeButton/LikeButton.stories.tsx

  • expect で、表示が「👍 いいね 0」から「👍 いいね 1」に変わったこと、ステップ 4 の fn() で作った onLiked が 1 を引数に呼ばれたことを検証します。toHaveBeenCalledTimes(1) を使うと、二重呼び出しも検出できます。
