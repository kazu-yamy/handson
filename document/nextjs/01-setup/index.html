環境構築とプロジェクト作成

  • ⏱ 所要時間: 30分
  • 📊 難易度: 入門
  • 👤 対象: JavaScript / TypeScript の基本文法は分かるが、Next.js は初めての人
  • 📋 前提: Node.js がインストール済みであること、ターミナルで基本的なコマンド操作ができること
  • 🔗 前提となる項目: なし（トラック最初の項目）

🎯 このレッスンで学ぶこと

  • create-next-app で TypeScript + App Router の Next.js プロジェクトを作成する
  • 生成されたファイル構成と、それぞれの役割を把握する
  • 開発サーバーを起動し、ページ編集がブラウザに即時反映される（Hot Reload）ことを確かめる
  • Sass を導入し、CSS ファイルを SCSS に置き換える
  • npm run build と npm run lint でビルドと静的解析が通ることを確認する

概要

Next.js トラックの最初の項目です。公式の雛形生成ツール create-next-app でプロジェクトを作り、 開発サーバーでの表示確認、SCSS への切り替え、本番ビルドまでをひと通り体験します。 以降の項目は、ここで作るプロジェクトの構成（TypeScript・App Router・src/ ディレクトリ・SCSS）を前提に進めます。

ℹ️

使用バージョン

Node.js 24.21.0 / npm 11.19.0 / Next.js 16.3.6 / React 19.2.8 / sass 1.105.0 で動作を確認しています。 バージョンは執筆時点（2026年9月）のものです。@latest を指定するため、実行する時期によっては新しいバージョンがインストールされ、出力の内容も多少変わります。

手順

1

Node.js と npm のバージョンを確認する

まず、Node.js と npm がインストールされていることを確認します。ターミナルで次のコマンドを実行してください。

Terminal 
$ node -vv24.21.0$ npm -v11.19.0

✅ 確認ポイント

どちらのコマンドもバージョン番号が表示されれば準備完了です。command not found になる場合は、Node.js をインストールしてからやり直してください。

2

create-next-app でプロジェクトを作成する

作業用のディレクトリに移動し、create-next-app を実行します。 オプションを指定しないと対話形式で設定を聞かれますが、ここでは全ての設定をフラグで渡します。こうすると、誰が実行しても同じ構成のプロジェクトができます。

Terminal 
$ npx create-next-app@latest 01-setup --ts --eslint --app --src-dir --no-tailwind --import-alias "@/*" --use-npm --disable-git --agents-md --yesCreating a new Next.js app in /path/to/01-setup.Using npm.Initializing project with template: appInstalling dependencies:- next- react- react-domInstalling devDependencies:- @types/node- @types/react- @types/react-dom- eslint- eslint-config-next- typescriptnpm warn deprecated eslint@9.39.5: This version is no longer supported. ...added 345 packages, and audited 346 packages in 23sfound 0 vulnerabilitiesGenerating route types...✓ Types generated successfullySkipping git initialization.Success! Created 01-setup at /path/to/01-setup

出力は要点のみを抜粋しています。各フラグの意味は次のとおりです。

  • 01-setup: 作成するプロジェクトのディレクトリ名
  • --ts: TypeScript プロジェクトとして作成する
  • --eslint: ESLint の設定を含める
  • --app: App Router 構成で作成する
  • --src-dir: アプリのコードを src/ ディレクトリの中に置く
  • --no-tailwind: Tailwind CSS を導入しない（このトラックではスタイルを SCSS で書くため）
  • --import-alias "@/*": @/ で src/ 以下を参照できる import エイリアスを設定する
  • --use-npm: パッケージマネージャーに npm を使う
  • --disable-git: プロジェクト内で git init を行わない
  • --agents-md: AGENTS.md を生成する（このフラグは既定で有効ですが、環境によらず生成させるために明示しています）
  • --yes: フラグで指定しなかった項目は、保存済みの設定または既定値を使う（対話プロンプトを出さない）
💡

Tip

npm warn deprecated eslint@9.39.5 の警告が出ますが、プロジェクトの作成やこの後の npm run lint には影響しません。

💡

Tip

--yes はフラグで指定しなかった項目に保存済みの設定を使うため、React Compiler の有効/無効など一部の項目は実行環境によって教材と異なる結果になることがあります。生成結果が教材と違う場合は、該当する設定を明示的にフラグで指定してください（本執筆時点の create-next-app には React Compiler を無効化する専用フラグはありません）。

✅ 確認ポイント

最後に Success! Created 01-setup at ... と表示され、01-setup ディレクトリができていれば成功です。以降のコマンドは全て cd 01-setup で移動してから実行します。

ℹ️

このトラックでのディレクトリの使い分け

このトラックでは src/app/ をルーティング専用にし、再利用する部品は src/components/、共通 SCSS は src/styles/ に置く構成をとります。 詳細はトラックの README（nextjs/README.md）の「プロジェクト構成」を参照してください。今回のレッスンでは、このあと src/styles/ を作成します。

主なファイルの役割は次のとおりです。

  • src/app/: App Router のルートディレクトリ。この中のフォルダ構成がそのまま URL になります（詳しくは次の項目で扱います）。
  • src/app/layout.tsx: 全ページ共通のレイアウト（<html> と <body>）を定義するルートレイアウト。globals.css もここで読み込みます。
  • src/app/page.tsx: トップページ（/）の内容です。
  • src/app/page.module.css: page.tsx 専用の CSS Modules。クラス名はこのファイルを import したコンポーネントの中だけで有効になります。
  • public/: 画像などの静的ファイル置き場。/next.svg のように URL のルートから参照できます。
  • next.config.ts: Next.js の設定ファイル。
  • tsconfig.json: TypeScript の設定。"paths": { "@/*": ["./src/*"] } が --import-alias で指定したエイリアスです。
  • eslint.config.mjs: ESLint の設定。Next.js 用のルール（eslint-config-next）を読み込んでいます。
  • next-env.d.ts: Next.js の型定義を読み込むためのファイル。自動生成されるので編集しません。
ℹ️

AGENTS.md と CLAUDE.md について

AGENTS.md と CLAUDE.md は、コーディング支援用の AI エージェント向けの説明ファイルです。create-next-app の --agents-md が既定で有効なため生成されます。 アプリの動作には関係しないので、削除しても影響はありません。

✅ 確認ポイント

src/app/ の中に layout.tsx・page.tsx・globals.css・page.module.css があることを確認してください。

4

開発サーバーを起動して表示を確認する

プロジェクトのディレクトリで開発サーバーを起動します。

Terminal 
$ cd 01-setup$ npm run dev> 01-setup@0.1.0 dev> next dev▲ Next.js 16.3.6 (Turbopack)- Local:         http://localhost:3000- Network:       http://192.168.x.x:3000✓ Ready in 239ms

ブラウザで http://localhost:3000 を開くと、create-next-app が用意したスタートページが表示されます。 Network の IP アドレスは環境によって異なります。サーバーはターミナルで Ctrl + C を押すと止まりますが、次のステップ以降もページを確認するので、起動したままにしておいてください。

✅ 確認ポイント

ターミナルに ✓ Ready が表示され、ブラウザで http://localhost:3000 を開くとページが表示されれば OK です。

5

Sass を導入して SCSS に置き換える

このトラックではスタイルを SCSS で書きます。Next.js は sass パッケージを入れるだけで .scss ファイルを読み込めるようになります。開発サーバーを動かしたまま、別のターミナルで次のコマンドを実行してください。

Terminal 
$ cd 01-setup$ npm install sassadded 8 packages, and audited 354 packages in 778msfound 0 vulnerabilities

次に、共通スタイルの置き場所を src/styles/ に変え、拡張子も .scss に変えます（このコマンドは何も出力しません）。 page.module.css は page.tsx と同じ場所のまま、拡張子だけ変えます。中身はどちらも変更しません。

Terminal 
$ mkdir -p src/styles$ mv src/app/globals.css src/styles/globals.scss$ mv src/app/page.module.css src/app/page.module.scss
💡

なぜ src/styles/ に移すのか

このトラックでは、複数のページやコンポーネントから参照する共通 SCSS（globals.scss など）を src/styles/ に集約する規約にしています。 src/app/ はルーティング専用の場所として空けておくためです。 参照には @/ という import エイリアスを使います。これは tsconfig.json の "paths": { "@/*": ["./src/*"] } によって @/* が ./src/* を指すよう設定されているためで、create-next-app 実行時に --import-alias "@/*" を指定したことで生成されています。

ℹ️

Note

この時点でブラウザを開くと Module not found: Can't resolve './globals.css' というエラー画面が一時的に表示されますが、これは失敗ではありません。次の手順で layout.tsx の import を書き換えれば解消します。

layout.tsx で読み込んでいるファイルのパスを、移動先に合わせて @/ エイリアス経由の指定に書き換えます。

Diff src/app/layout.tsx 
- import "./globals.css";+ import "@/styles/globals.scss";

page.module.scss は、中身を全て次の内容に置き換えます。ページ中央に見出しとバージョン表記を並べるだけの最小限のスタイルです。

SCSS src/app/page.module.scss 
.main {
  display: flex;
  flex-direction: column;
  align-items: center;
  justify-content: center;
  min-height: 100dvh;
  gap: 0.5rem;
  text-align: center;
}

.title {
  font-size: 2rem;
  font-weight: 700;
}

.version {
  color: #666;
}

最後に page.tsx も、中身を全て次の内容に置き換えます。 見出しと、インストールされている Next.js のバージョンを表示するだけのページです。 next/package.json から version を読み込めるのは、tsconfig.json で "resolveJsonModule": true が有効になっているためです。

TypeScript src/app/page.tsx 
import { version } from "next/package.json";
import styles from "./page.module.scss";

export default function Home() {
  return (
    <main className={styles.main}>
      <h1 className={styles.title}>Hello, Next.js!</h1>
      <p className={styles.version}>Next.js v{version}</p>
    </main>
  );
}

✅ 確認ポイント

ブラウザの http://localhost:3000 に、画面中央に「Hello, Next.js!」と「Next.js v16.3.6」が表示されれば成功です。package.json の dependencies に "sass": "^1.105.0" が追加されていることも確認しておきましょう。

6

page.tsx を書き換えて Hot Reload を体験する

開発サーバーは、ファイルを保存すると変更をすぐブラウザに反映します（Hot Reload）。ブラウザを開いたまま、見出しの文言を書き換えて保存してみましょう。

Diff src/app/page.tsx 
-       <h1 className={styles.title}>Hello, Next.js!</h1>+       <h1 className={styles.title}>こんにちは、Next.js!</h1>

同じように、page.module.scss の .title の font-size を変えて保存すると、スタイルの変更も即座に反映されます。試し終わったら、両方とも元の内容に戻しておいてください。

✅ 確認ポイント

ブラウザを手動で再読み込みしなくても、保存した直後に見出しの文言や大きさが変わることを確認してください。

7

本番ビルドと Lint を実行する

開発サーバーを Ctrl + C で止めてから、本番用のビルドを実行します。TypeScript の型チェックもこの中で行われます。

Terminal 
$ npm run build> 01-setup@0.1.0 build> next build▲ Next.js 16.3.6 (Turbopack)✓ Running next.config.ts took 12ms  Creating an optimized production build ...✓ Compiled successfully in 1504ms  Running TypeScript ... Route (app) の一覧に / が ○ (Static) として表示されています。これは、トップページがビルド時に静的な HTML として生成されたことを表します。続いて Lint（ESLint による静的解析）を実行します。

npm run build がエラーなく終わり、Route (app) の一覧が表示されることを確認してください。npm run lint は、エラーや警告を出さずに終われば OK です。

演習

以下のチェックリストを使って、このレッスンの内容を振り返りましょう。

つまずきポイント

⚠️

Git リポジトリの中で作成するときは --disable-git を付ける

--disable-git を付けないと、create-next-app がプロジェクト内に独自の .git を作ります。既存の Git リポジトリの中で実行すると、リポジトリが入れ子になってしまいます。

⚠️

「workspace root」の警告が出る

親ディレクトリにも package-lock.json がある場所でプロジェクトを作ると、npm run dev や npm run build の実行時に警告が出ます。 警告の文面は ⚠ Warning: Next.js inferred your workspace root, but it may not be correct. です。 ビルド自体は成功するので、このレッスンでは無視して構いません。気になる場合は、next.config.ts で turbopack.root を設定するか、lockfile が 1 つになるよう作業場所を見直してください。

💡

ポート 3000 が使用中の場合

別の開発サーバーなどがポート 3000 を使っていると、⚠ Port 3000 is in use by process ..., using available port 3001 instead. と表示され、自動的に 3001 番で起動します。 ターミナルの - Local: に表示された URL を開いてください。

💡

--no-tailwind がヘルプに見当たらない

npx create-next-app@latest --help には --tailwind（既定で有効）しか載っていませんが、--no-tailwind で Tailwind CSS なしのプロジェクトを作れます。 CLI のバージョンが変わって挙動が異なる場合は、--help で --tailwind の扱いを確認してください。

💡

sass が dependencies に入る

npm install sass はパッケージを dependencies に追加します。devDependencies に入れたい場合は npm install --save-dev sass のように --save-dev を付けてください。どちらでも動作は変わりません。
