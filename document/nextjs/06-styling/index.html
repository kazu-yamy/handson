スタイリングとレイアウト実装

  • ⏱ 所要時間: 30分
  • 📊 難易度: 入門
  • 👤 対象: 05 を終え、部品ごとにばらばらだったスタイルを共通の変数とレイアウトで整えたい人
  • 📋 前提: CSS のセレクタ・Flexbox・メディアクエリの基本が分かること
  • 🔗 前提となる項目: 05: Storybook でのコンポーネントカタログ構築

🎯 このレッスンで学ぶこと

  • CSS Modules がクラス名をファイルごとに一意にする仕組みを説明でき、複数クラスを結合できる
  • SCSS 変数と CSS カスタムプロパティを使い分けて、共通の変数・ミックスインを定義できる
  • sassOptions.additionalData で変数・ミックスインを全ファイルに自動で読み込ませ、Storybook にも同じ設定を入れられる
  • ルートレイアウトと CSS Grid で、ヘッダー固定・センタリング・レスポンシブなサイドバーを組める
  • data-* 属性でバリアントを切り替える Button コンポーネントを作り、既存の部品から再利用できる

概要

05 までは、部品ごとの .module.scss に色や余白の値を直接書いていました。 同じ #e5e5e5 や 1rem があちこちに散らばり、ダークテーマに切り替えても一部の色が変わらない状態です。 このレッスンでは、共通の変数とミックスインを src/styles/ にまとめ、すべての部品から使えるようにします。 あわせて、サイト全体のレイアウトと、再利用できる Button コンポーネントを作ります。

Next.js のスタイリング手法

Next.js（App Router）では、主に次の方法でスタイルを書けます。

手法概要このトラックでの扱い
グローバル CSSルートレイアウトで読み込み、サイト全体に効かせるリセットや body の指定だけに使う（globals.scss）
CSS Modules*.module.css のクラス名をファイルごとに一意の名前へ変換する採用。部品ごとのスタイルはすべてこれで書く
Sass（SCSS）変数・ミックスイン・ネストを使える CSS の拡張言語。CSS Modules と組み合わせられる採用（*.module.scss）
CSS-in-JSJavaScript の中にスタイルを書くライブラリ群使わない
Tailwind CSSユーティリティクラスを組み合わせて見た目を作る CSS フレームワーク使わない

このトラックが CSS Modules + SCSS を選ぶ理由は次のとおりです。

  • デザインフレームワークを使わない方針: 見た目を自分の CSS で組み立てることを学ぶため、Tailwind CSS のようなフレームワークは使いません。
  • サーバーコンポーネントと相性が良い: CSS Modules は import styles from "./x.module.scss" でクラス名の文字列を受け取るだけなので、サーバーコンポーネントでもクライアントコンポーネントでも同じ書き方で使えます。実行時に JavaScript でスタイルを生成する CSS-in-JS のライブラリは、サーバーコンポーネントでは使えないものがあります。
  • ビルド時に静的な CSS になる: SCSS の変数やミックスインはビルド時に展開され、ブラウザには通常の CSS だけが届きます。

1

CSS Modules のスコープと複数クラスの結合を確認する

まず、05 までに使ってきた CSS Modules の仕組みを確認します。 Header.module.scss で .header を定義し、Header.tsx で import styles from "./Header.module.scss" のように読み込みます。 このとき styles.header には、ファイルごとに一意の名前へ変換されたクラス名の文字列が入ります。 別のファイルに同じ .header があっても、変換後の名前が違うので衝突しません。これを「スタイルのスコープがファイルに閉じている」と言います。

ここでは手始めに、Header.tsx で複数のクラスを結合している箇所を書き換えます。 05 まではテンプレートリテラルと三項演算子で書いていましたが、クラスが増えると読みにくくなります。 外部ライブラリ（clsx など）は使わず、配列を filter(Boolean) してから join(" ") する書き方に統一します。

"page" : undefined}                  >                    {item.label}  ...

isActive && styles.linkActive は、isActive が false のときは false になり、filter(Boolean) で取り除かれます。 条件付きのクラスが 2 つ、3 つと増えても、配列に要素を足すだけで済みます。この書き方はステップ 5 の Button でも使います。

💡

:global が必要になる場面

CSS Modules の中で、変換されない素のクラス名にスタイルを当てたいときは :global(.foo) { ... } と書いてグローバルスコープへ抜けます。 たとえば、外部ライブラリが出力する固定のクラス名を上書きする場合です。 このレッスンで作る .module.scss は自作の部品のクラスだけを対象にしているので、:global は登場しません。

✅ 確認ポイント

npm run build がエラーなく終わり、生成された HTML の header クラスが Header-module-scss-module__…__header のようなハッシュ付きの名前になっていれば成功です。 npm run dev でブラウザを開き、ヘッダーの現在ページのリンクが 05 と同じく青色で強調されることも確かめておきましょう。

2

共通の変数とミックスインを用意する

色・余白・ブレークポイントなどの共通の値を src/styles/_variables.scss に、よく使うスタイルのまとまりを src/styles/_mixins.scss にまとめます。 ファイル名の先頭の _ は、単独では CSS に変換しない「部品用のファイル（パーシャル）」であることを示す Sass の慣習です。

ここで大事なのは、SCSS 変数（$〜）と CSS カスタムプロパティ（--〜）を使い分けることです。

種類値が決まるタイミングこのレッスンで入れるもの
SCSS 変数 $space-4ビルド時に値へ展開されるブレークポイント・余白スケール・角丸
CSS カスタムプロパティ --color-bgブラウザで実行時に解決されるライト/ダークで切り替わる色

04 で作った ThemeToggle は、html 要素の data-theme 属性を "dark" / "light" に切り替えます。 SCSS 変数はビルド時に値が埋め込まれてしまうため、この属性に応じて色を変えられません。 そこで、切り替わる色は CSS カスタムプロパティにして :root に出し、:root[data-theme="dark"] で値を上書きします。 この仕組み自体は 05 までの globals.scss と同じで、:root の定義も引き続き globals.scss に置きます。 _variables.scss はその値の元になる SCSS 変数だけを持ち、CSS そのもの（:root など）は書きません。理由はステップ 3 で説明します。 変数名は --background / --foreground から --color-bg / --color-fg などに整理し、境界線や補助テキストの色を加えます。

SCSS src/styles/_variables.scss（新規） 
// 色・余白・ブレークポイント・角丸などをまとめた共通変数（$ 変数のみ）。
//
// このファイルには CSS を出力する記述（:root や @media など）を書かない。
// additionalData により全ての .module.scss にこのファイルが @use されるが、
// module.scss はそれぞれ別のコンパイル単位としてビルドされるため、
// ここに :root を書くと module.scss の数だけ CSS が複製されてしまう。
// 実際の CSS カスタムプロパティの出力は globals.scss（1 回しか @use されない）で行う。

// ブレークポイント（mixins.scss の mq() から使う）
$breakpoint-sm: 480px;
$breakpoint-md: 768px;
$breakpoint-lg: 960px;

// 余白スケール（4px 刻み）
$space-1: 0.25rem; // 4px
$space-2: 0.5rem; // 8px

// ライト/ダークで変わらない色（アクセントカラーなど）
$color-accent: #0070f3;

// ライトテーマの色（globals.scss の :root の既定値に使う）
$color-bg-light: #ffffff;
$color-fg-light: #171717;
$color-border-light: #e5e5e5;
$color-text-muted-light: #666666;
$color-text-subtle-light: #888888;

// ダークテーマの色（globals.scss の prefers-color-scheme / data-theme で使う）

アクセントカラーのようにテーマで変わらない値も、CSS カスタムプロパティ側に出しておくと、部品からは var(--color-accent) の 1 通りで参照できます。 SCSS 変数を CSS カスタムプロパティの値に入れるときは、#{$color-accent} のように #{}（インターポレーション）で囲みます。

SCSS src/styles/_mixins.scss（新規） 
// 共通で使うミックスイン。
@use "sass:map";
@use "variables" as vars;

// ブレークポイント名を指定してメディアクエリを書くためのミックスイン。
// 例: @include mq(md) { flex-direction: column; }
$breakpoints: (
  sm: vars.$breakpoint-sm,
  md: vars.$breakpoint-md,
  lg: vars.$breakpoint-lg,
);

@mixin mq($name) {
  $width: map.get($breakpoints, $name);

  @if $width == null {
    @error "mq: 不明なブレークポイント名です (#{$name})。sm / md / lg を使ってください。";
  }

  @media (max-width: $width) {
    @content;
  }
}

// キーボード操作時のフォーカスリング。マウス操作時（:focus のみで :focus-visible ではない場合）には出さない。
@mixin focus-ring {
  &:focus-visible {
    outline: 2px solid var(--color-accent);
    outline-offset: 2px;
  }
}

// ボタンの見た目をリセットして、テキストリンクのように使いたいときに使う。
@mixin button-reset {
  border: none;
  background: none;
  padding: 0;
  font: inherit;
  color: inherit;
  cursor: pointer;
}
  • mq($name): ブレークポイント名（sm / md / lg）を渡すと、その幅以下に効くメディアクエリを出力します。@content の位置に、呼び出し側のブロックの中身が入ります。存在しない名前を渡すと @error でビルドを止めます。
  • focus-ring: キーボードで操作したときだけ（:focus-visible）フォーカス枠を出します。
  • button-reset: <button> の既定の見た目を消して、テキストのように使うためのリセットです。

_mixins.scss の先頭では、@use "variables" as vars; で変数を vars.$breakpoint-sm のように名前空間付きで読み込んでいます。 @use "sass:map"; は Sass の組み込みモジュールで、map.get() を使うために読み込みます。

最後に、globals.scss を書き換えます。:root の構造はそのまま残し、直接書いていた色（#ffffff など）を _variables.scss の $color-bg-light のような SCSS 変数からの #{}（インターポレーション）に置き換え、変数名を --background / --foreground から --color-bg / --color-fg などに整理します。 この時点ではまだ sassOptions を設定していないので、ファイルの先頭に @use "variables" as *; を手書きします。

⚠️

@import ではなく @use を使う

Sass には古い読み込み方の @import もありますが、Dart Sass では非推奨です。 @import は読み込むたびに変数やミックスインをグローバルな名前空間に展開するため、同じファイルを複数の場所から読み込むと多重に展開され、警告や重複の原因になります。 @use はモジュールを 1 回だけ評価し、既定では variables.$space-4 のように名前空間越しに参照します。 as * を付けると名前空間を省略して $space-4 と書けます。

ただし「1 回だけ評価」はそのファイルの中で 1 回という意味です。ステップ 3 で導入する additionalData は @use を SCSS ファイルごとに差し込むため、.module.scss が 10 個あれば @use も 10 回評価されます。 @use されたファイルが変数の定義だけならファイルごとに再評価されても問題になりませんが、:root のように実際に CSS を出力する記述が入っていると、その CSS が .module.scss の数だけ複製されてしまいます。 そのため _variables.scss / _mixins.scss には CSS を出力する記述を書かず、:root の出力は 1 回しか @use されない globals.scss だけに置いています。

この時点では、変数を使っているのは globals.scss だけです。各部品の .module.scss はまだ直接値を書いたままで、次のステップで書き換えます。

src/styles/_variables.scss と src/styles/_mixins.scss ができ、npm run build がエラーなく終われば成功です。 npm run dev でブラウザを開き、ヘッダーのテーマ切り替えボタンで背景色と文字色がライト/ダークに切り替わることも確かめておきましょう。

3

sassOptions で変数とミックスインを自動で読み込ませる

このままでは、各 .module.scss で変数を使うたびに @use "../../../styles/variables" as *; のような相対パスを書く必要があります。 そこで next.config.ts の sassOptions を使い、すべての SCSS ファイルの先頭に @use を自動で差し込みます（自動プレリュード）。

Diff next.config.ts 
  import type { NextConfig } from "next";+ import path from "node:path";   const nextConfig: NextConfig = {-   /* config options here */+   sassOptions: {+     loadPaths: [path.join(process.cwd(), "src/styles")],+     additionalData: '@use "variables" as *; @use "mixins" as *;',+   },  };   export default nextConfig;
  • additionalData: SCSS としてコンパイルされるすべてのファイル（globals.scss も .module.scss も）の先頭に、この文字列を挿入します。これで、どのファイルからも $space-4 や @include mq(md) をそのまま書けます。
  • loadPaths: @use "variables" の "variables" を探すディレクトリです。src/styles/ を指定しているので、src/styles/_variables.scss が見つかります。
⚠️

includePaths は使えない

最初に sassOptions を古い Sass API のオプション名である includePaths: ["./src/styles"] だけで書いてビルドすると、.module.scss を含むすべての SCSS ファイルで次のエラーになります。 includePaths を path.join(process.cwd(), "src/styles") のような絶対パスに変えても結果は同じでした。

Terminal

現在の Dart Sass の API では、このディレクトリ指定は loadPaths という名前に変わっています。 Next.js 16 の sass-loader は modern API を使うため、includePaths を渡しても無視されます（Turbopack だけでなく webpack でビルドしたときも同じでした）。 includePaths は削除し、loadPaths だけを書きます。

バリアントを持つ Button コンポーネントを作る

再利用できる Button コンポーネントを src/components/Button/ に作ります。 見た目の種類（variant）として primary / secondary / ghost の 3 つ、大きさ（size）として sm / md の 2 つを持たせます。

バリアントの切り替えには、variant と size を data-variant / data-size 属性として DOM に出し、CSS の属性セレクタで見た目を変える方式を使います。 クラス名は常に .button の 1 つだけです。

TSX src/components/Button/Button.tsx（新規） 
import type { ButtonHTMLAttributes, ReactNode } from "react";
import styles from "./Button.module.scss";

type ButtonVariant = "primary" | "secondary" | "ghost";
type ButtonSize = "sm" | "md";

type ButtonProps = ButtonHTMLAttributes<HTMLButtonElement> & {
  variant?: ButtonVariant;
  size?: ButtonSize;
  children: ReactNode;
};

// variant / size は className を出し分ける（styles[variant]）のではなく、
// data-variant / data-size 属性として DOM に出し、CSS 側で属性セレクタ
// （[data-variant="primary"] など）を使って切り替える方式にしている。
// 理由は Button.module.scss 冒頭のコメントを参照。
export function Button({
  variant = "primary",
  size = "md",
  className,
  children,
  ...rest
}: ButtonProps) {
  return (
    <button
      type="button"
      className={[styles.button, className].filter(Boolean).join(" ")}
      data-variant={variant}
      data-size={size}
      {...rest}
    >
      {children}
    </button>
  );
}
  • ButtonHTMLAttributes<HTMLButtonElement> を型に含めているので、onClick や aria-label など <button> の属性をそのまま渡せます。受け取った残りの属性は ...rest で <button> に渡します。
  • 呼び出し側から className を渡されたときは、ステップ 1 と同じ filter(Boolean).join(" ") で .button と結合します。

      border-color: var(--color-accent);
      color: var(--color-accent);
    }
  }

  &[data-variant="ghost"] {
    background: none;
    border-color: transparent;
    color: var(--color-fg);

    &:hover {
      background: var(--color-border);
    }
  }
}

&[data-variant="primary"] は、.button[data-variant="primary"] に展開されます。 色はすべて CSS カスタムプロパティで指定しているので、テーマを切り替えると secondary と ghost の色も追従します。

もう 1 つの方式: styles[variant] でクラス名を出し分ける

バリアントごとに .primary / .secondary のようなクラスを用意し、className={[styles.button, styles[variant], styles[size]].join(" ")} と出し分ける方式もあります。 &[data-variant="#{$v}"] という書き方は @each とマップを組み合わせて生成できるので、属性方式でも styles[variant] 方式でも Sass 側の書きやすさに大きな差はありません（今回は 3 種類なのでどちらもベタ書きしています）。 違いは呼び出し側の見え方です。styles[variant] 方式は呼び出し側の className も加えると常に複数のクラスを結合することになり、開発者ツールにもハッシュ付きのクラス名が並んでどれがバリアント由来か分かりにくくなります。 このレッスンでは、次に作る LikeButton のように className を付けて再利用する場面があります。 そこで、クラスの結合が 1 パターンで済み、開発者ツールで data-variant="primary" と状態がそのまま読める属性方式を選びました。 欠点は、見た目の切り替えに使っている data-variant / data-size が DOM にそのまま出るため、CSS の実装詳細が漏れているように見える点です。
