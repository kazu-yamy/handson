App Router の基礎とファイルベースルーティング

  • ⏱ 所要時間: 45分
  • 📊 難易度: 入門
  • 👤 対象: 01 を終え、Next.js で複数ページのアプリを作り始めたい人
  • 📋 前提: React のコンポーネントと JSX の基本が分かること
  • 🔗 前提となる項目: 01: 環境構築とプロジェクト作成

🎯 このレッスンで学ぶこと

  • src/app/ のフォルダ構成と URL の対応（ファイルベースルーティング）を理解する
  • page.tsx と layout.tsx でページと共通レイアウトを作り、Link でページ間を移動する
  • ネストしたレイアウトと動的ルート [slug] で、一覧と詳細のページを作る
  • not-found.tsx と loading.tsx で、404 と読み込み中の表示を用意する
  • ルートグループ (group) とプライベートフォルダ _folder の役割を説明できる

概要

App Router では、src/app/ 配下のフォルダ構成がそのまま URL になります。これを「ファイルベースルーティング」と呼びます。 このレッスンでは、01 で作ったトップページに About・Blog・Contact のページを追加し、共通ヘッダー、ブログ用のサイドバー付きレイアウト、記事ごとの詳細ページまでを作ります。

ℹ️

出発点

01 で作ったプロジェクトをそのまま使って続けます。ディレクトリ名は 01-setup のままで構いません。 教材中のコマンド出力は完成コードのディレクトリ名 02-app-router で表示していますが、手元では 01-setup@0.1.0 のように表示されます。

ℹ️

使用バージョン

Node.js 24.21.0 / npm 11.19.0 / Next.js 16.3.6 / React 19.2.8 / sass 1.105.0 で動作を確認しています（執筆時点: 2026年9月）。

App Router のファイル規約

このレッスンで使うファイル名とフォルダ名の規約を先に一覧しておきます。各ステップで 1 つずつ実際に作っていきます。

ファイル / フォルダ役割このレッスンでの例
page.tsxそのフォルダの URL で表示される画面。これがあるフォルダだけが URL として公開されるabout/page.tsx → /about
layout.tsx同じ階層以下の全ページを包む共通レイアウト。ページを移動しても再レンダリングされずに残るblog/layout.tsx（サイドバー）
loading.tsx同じ階層以下のページを読み込んでいる間に表示する画面blog/loading.tsx
not-found.tsxnotFound() を呼んだときや、存在しない URL にアクセスしたときの画面app/not-found.tsx
[slug]/動的ルート。URL の一部を params として受け取るblog/[slug]/page.tsx → /blog/app-router-basics
(group)/ルートグループ。フォルダを整理するためのもので、URL には現れない(marketing)/contact/page.tsx → /contact
_folder/プライベートフォルダ。ルーティングの対象から外れ、中に何を置いても URL にならない_components/、blog/_data/

手順

作業はプロジェクトのディレクトリで行います。開発サーバー（npm run dev）を起動したままにしておくと、保存するたびにブラウザで結果を確かめられます。

1

静的ルート /about を作り、Link でつなぐ

src/app/about/ フォルダを作り、その中に page.tsx を置きます。これだけで /about という URL のページになります。 ルーティングの設定ファイルを書く必要はありません。

2

共通ヘッダーを作り、ルートレイアウトに組み込む

全ページに表示するナビゲーション（Header）を作ります。このヘッダーはアプリのルートでしか使わない部品なので、構成規約に従って src/app/_components/Header/ に置きます。 先頭に _ が付いたフォルダはプライベートフォルダで、ルーティングの対象になりません。 また、構成規約では 1 コンポーネントを 1 フォルダにまとめます。本体（Header.tsx）、スタイル（Header.module.scss）、re-export 用の index.ts を同じフォルダに置きます。

TypeScript src/app/_components/Header/Header.tsx 
"use client";

import Link from "next/link";
import { usePathname } from "next/navigation";
import styles from "./Header.module.scss";

const NAV_ITEMS = [
  { href: "/", label: "Home" },
  { href: "/about", label: "About" },
  { href: "/blog", label: "Blog" },
] as const;

export function Header() {
  const pathname = usePathname();

  return (
    <header className={styles.header}>
      <nav className={styles.nav}>
        <ul className={styles.list}>
          {NAV_ITEMS.map((item) => {
            const isActive =
              item.href === "/" ? pathname === "/" : pathname.startsWith(item.href);

            return (
              <li key={item.href}>
                <Link
                  href={item.href}
                  className={isActive ? `${styles.link} ${styles.linkActive}` : styles.link}
                  aria-current={isActive ? "page" : undefined}
                >
                  {item.label}
                </Link>
              </li>
            );
          })}
        </ul>
      </nav>
    </header>
  );
}

App Router のコンポーネントは、既定ではサーバー側が描画する「サーバーコンポーネント」です。 現在の URL を取得する usePathname は、ブラウザ側でしか動かないフックです。そこでファイルの先頭に "use client" を書き、このコンポーネントを「クライアントコンポーネント」にしています。 取得したパスと各リンクの href を比べ、現在いるページのリンクを強調します。/ だけは完全一致、それ以外は前方一致で判定しているため、/blog/app-router-basics を開いているときも「Blog」が強調されます。

💡

"use client" を付ける範囲は最小限に

layout.tsx 自体に "use client" を付けると、その配下もクライアント側で動くコンポーネントとして扱われ、サーバーコンポーネントの利点が失われます。 ここでは usePathname が必要な Header だけを切り出して、クライアントコンポーネントにしました。layout.tsx はサーバーコンポーネントのまま <Header /> を呼び出しています。

3

ネストしたレイアウトで /blog を作る

ブログの記事データを用意します。本来はデータベースや API から取得するところですが、このレッスンでは配列で代用します。 データ用のファイルもプライベートフォルダ _data/ に置くので、URL にはなりません。

TypeScript src/app/blog/_data/posts.ts 
export type Post = {
  slug: string;
  title: string;
  body: string;
};

// サイドバー（layout.tsx）用の一覧はここから直接参照する（遅延なし）。
// loading.tsx の動作を見せるための遅延は getPosts / getPost にのみ入れる。
export const POSTS: Post[] = [
  {
    slug: "app-router-basics",
    title: "App Router の基礎",
    body: "src/app/ 配下のフォルダ構成がそのまま URL になります。page.tsx がそのルートの画面です。",
  },
  {
    slug: "nested-layouts",
    title: "ネストしたレイアウト",
    body: "layout.tsx は同じ階層以下の全ページに適用されます。ルートレイアウトと組み合わせて共通 UI を組み立てます。",
  },
  {
    slug: "dynamic-routes",
    title: "動的ルート",
    body: "[slug] のようにフォルダ名を角括弧で囲むと、URL の一部を受け取れる動的ルートになります。",
  },
];

function delay(ms: number) {
  return new Promise((resolve) => setTimeout(resolve, ms));
}

export async function getPosts(): Promise<Post[]> {
  await delay(1000);
  return POSTS;
}

export async function getPost(slug: string): Promise<Post | undefined> {
  await delay(1000);
  return POSTS.find((post) => post.slug === slug);
}

getPosts と getPost には、ステップ 5 で読み込み中の表示を体験するため、わざと 1 秒の遅延を入れています。 一方、POSTS 配列はレイアウトのサイドバーから遅延なしで直接参照します（理由はステップ 5 のコールアウトで説明します）。

次に、/blog 以下の全ページに共通するレイアウトを blog/layout.tsx に書きます。 layout.tsx は入れ子になり、/blog 配下のページは「ルートレイアウト（ヘッダー）→ ブログのレイアウト（サイドバー）→ ページ」の順に包まれます。 children の位置に各ページの内容が入ります。

💡

LayoutProps / PageProps 型に赤線が出る場合

LayoutProps<"/blog"> のような型ヘルパーは、next dev や next build の実行時に Next.js が自動生成します。生成先は .next/types/routes.d.ts です。 新しいフォルダを作った直後は生成が追いつかず、エディタに Type '"/blog"' does not satisfy the constraint '"/"' のような赤線が出ることがあります。ビルドや実行には影響しません。 開発サーバーが動いていれば、しばらくすると消えます。

4

動的ルート [slug] で記事の詳細ページを作る

記事ごとの URL（/blog/app-router-basics など）を 1 つのファイルで扱うため、フォルダ名を角括弧で囲んだ blog/[slug]/ を作ります。 角括弧の中の名前（slug）が、URL から受け取る値の名前になります。 ターミナルでフォルダを作るときは、角括弧がシェルに解釈されないよう mkdir -p "src/app/blog/[slug]" のように引用符で囲んでください。

TypeScript src/app/blog/[slug]/page.tsx 
import { notFound } from "next/navigation";
import { POSTS, getPost } from "../_data/posts";
import styles from "./page.module.scss";

export function generateStaticParams() {
  return POSTS.map((post) => ({ slug: post.slug }));
}

export default async function BlogPostPage({
  params,
}: PageProps<"/blog/[slug]">) {
  const { slug } = await params;
  const post = await getPost(slug);

  if (!post) {
    notFound();
  }

  return (
    <article>
      <h1 className={styles.title}>{post.title}</h1>
      <p className={styles.body}>{post.body}</p>
    </article>
  );
}
SCSS src/app/blog/[slug]/page.module.scss 
.title {
  font-size: 1.5rem;
  font-weight: 700;
  margin-bottom: 1rem;
}

.body {
  color: #333;
  line-height: 1.7;
}

このファイルのポイントは次の 3 つです。

  • params は Promise: Next.js 16 では、URL から受け取った値は Promise<{ slug: string }> として渡されます。const { slug } = await params; のように await してから使います。型は手書きせず、PageProps<"/blog/[slug]"> を使うと、ルートの文字列とファイルの配置がずれたときに型エラーで気付けます。
  • generateStaticParams: ビルド時に生成しておく slug の一覧を返す関数です。ここでは POSTS の 3 件を返しているので、3 つの記事ページが事前に HTML として生成されます（最後の「本番ビルドでルート一覧を確認する」で確かめます）。
  • notFound(): 該当する記事がないときに呼ぶと、処理をそこで打ち切って 404 用の画面を表示します。notFound() の後ろでは post が undefined でないことを TypeScript が理解するため、post.title をそのまま書けます。

✅ 確認ポイント

サイドバーの記事タイトルをクリックして、その記事の見出しと本文が表示されれば成功です。サイドバーはそのまま残り、右側だけが切り替わることにも注目してください。

💡

layout.tsx は loading.tsx の対象外

loading.tsx が包むのは、同じ階層の page.tsx とその配下だけです。同じ階層の layout.tsx は包まれません。 もしサイドバーを遅延ありの getPosts() で作ると、loading.tsx が表示される前にレイアウト自体の描画で 1 秒待たされてしまいます。 そのため、サイドバーは遅延なしの POSTS を直接参照し、遅延はページ側の getPosts / getPost にだけ入れています。

⚠️

notFound() でも HTTP ステータスが 200 のままになる

/blog/nonexistent のように存在しない記事を開くと、画面には 404 ページが表示されますが、HTTP ステータスコードは 200 が返ります。 祖先のフォルダに loading.tsx があるルートは、レスポンスを少しずつ送る「ストリーミング」で返されます。ストリーミングの場合、Next.js は 200 を返す仕様です（公式ドキュメントの not-found.js の API リファレンスに記載があります）。 npm run dev でも、npm run build 後の npm run start でも同じ結果になります。

そのため、ステータスコードだけで 404 になったかを判定しないでください。HTTP ステータスが 200 になるのは npm run dev でも本番ビルド後の npm run start でも共通ですが、確認方法は異なります。npm run dev ではページのソースに <meta name="next-error" content="not-found"/> が含まれているかで判定し、npm run start ではこの meta タグが出力されないため、検索エンジン向けの <meta name="robots" content="noindex"/> が含まれているかで判定します。

✅ 確認ポイント

ヘッダーの「Home」から「Blog」に移動すると、ヘッダーとサイドバーが表示され、右側に「記事を読み込み中...」が約 1 秒表示されてから記事一覧に切り替わります。ブラウザで http://localhost:3000/blog/nonexistent を開くと「404 - Not Found」が表示されます。ステータスコードは上の注意のとおり 200 です。

$ curl -s -o /dev/null -w '%{http_code}\n' localhost:3000/blog/nonexistent200

ルートグループ (marketing) で /contact を作る

フォルダ名を丸括弧で囲むと「ルートグループ」になり、フォルダの整理には使えますが URL には現れません。 src/app/(marketing)/contact/page.tsx を作ると、URL は /marketing/contact ではなく /contact になります。 ターミナルでフォルダを作るときは、括弧がシェルに解釈されないよう mkdir -p "src/app/(marketing)/contact" のように引用符で囲んでください。

TypeScript src/app/(marketing)/contact/page.tsx 
import styles from "./page.module.scss";

export default function ContactPage() {
  return (
    <main className={styles.main}>
      <h1 className={styles.title}>Contact</h1>
      <p>
        このページは <code>src/app/(marketing)/contact/page.tsx</code> にありますが、
        URL は <code>/(marketing)</code> を含まない <code>/contact</code> になります。
      </p>
    </main>
  );
}
SCSS src/app/(marketing)/contact/page.module.scss 
.main {
