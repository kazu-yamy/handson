変数とアウトプット

  • ⏱ 所要時間: 45分
  • 📊 難易度: 入門
  • 👤 対象: Terraform の基本操作（init / plan / apply）を一通り体験した人
  • 📋 前提: 01 で作った 01-basics ディレクトリ（main.tf と .gitignore）が手元にあること。クラウドのアカウントは不要（ローカルにファイルを作るだけ）
  • 🔗 前提となる項目: 01: Terraform の基本操作

🎯 このレッスンで学ぶこと

  • variable ブロックで入力変数を宣言し、var.<名前> で参照する
  • default・環境変数 TF_VAR_*・terraform.tfvars・*.auto.tfvars・-var / -var-file の優先順位を実際に確かめる
  • type と validation で受け取る値を検査し、sensitive で表示を伏せる（伏せるだけで、値は平文で残ることも知る）
  • locals で式に名前を付けて設定を整理する
  • output で結果を返し、terraform output（-raw / -json）で取り出す
  • 変数ファイルのうち、どれを Git にコミットするかを決める

概要

01 の main.tf には、あいさつ文の Hello やペットの名前の単語数 2 が直接書かれていました。値を変えるたびに main.tf を書き換えるのは不便です。 この項目では、設定の外から値を受け取る入力変数（variable）と、結果を外へ返す出力値（output）を使えるようにします。あわせて、設定の中で使う値に名前を付けるローカル値（locals）も扱います。

01 と同じく、使うのは手元にファイルを作る hashicorp/local と、ランダムな名前を作る hashicorp/random だけです。クラウドのアカウントや料金の心配はありません。

ℹ️

使用バージョン

Terraform v1.16.2（darwin_arm64）/ hashicorp/local v2.9.1 / hashicorp/random v3.9.1 で動作を確認しています。バージョンは執筆時点（2026年10月）のものです。 掲載している出力は色なし（-no-color 相当）で取得したものです。出力を grep や head に渡すコマンドだけは、色の制御文字で一致しなくならないよう -no-color を付けています。

2

入力変数を宣言して使う

あいさつ文の Hello を、外から変えられるようにします。新しく variables.tf を作り、入力変数 greeting を宣言します。 Terraform はディレクトリ内の .tf ファイルをすべて読み込むので、ファイル名は自由です。変数の宣言は variables.tf にまとめるのが慣例です。

HCL variables.tf 
variable "greeting" {
  type        = string
  description = "ファイルに書くあいさつ文"
  default     = "Hello"
}
  • type: 受け取る値の型（ここでは文字列 string）
  • description: 変数の説明。値の入力を求められたときなどに表示されます（ステップ 4 で確かめます）
  • default: 値が渡されなかったときに使う既定値

main.tf では、var.greeting の形で変数を参照します。content の Hello を置き換えます。

Diff main.tf 
 resource "local_file" "hello" {   filename = "${path.module}/output/hello.txt"-  content  = "Hello, ${random_pet.greeter.id}!\n"+  content  = "${var.greeting}, ${random_pet.greeter.id}!\n" }

3

値の渡し方と優先順位を確かめる

変数の値は -var 以外にも、ファイルや環境変数で渡せます。同じ greeting を複数の方法で同時に渡し、どれが勝つかを確かめます。 plan の全文は長いので、新しい content の行（+ で始まり、ペットの名前を含む行）だけを grep で取り出します。

⚠️

grep のパターンを自分のペットの名前に変える

このステップと、ステップ 6 の grep のパターンには、執筆時のペットの名前 wired-stag が入っています。そのまま実行すると何も表示されないので、自分の環境の名前（cat output/hello.txt で確かめられます）に書き換えてから実行してください。

まず、何も渡さない状態です。default の Hello が使われます。

Terminal 
$ terraform plan -no-color | grep -E '^ +\+ .*wired-stag'          + Hello, wired-stag!

環境変数でも値を渡せます。名前は TF_VAR_ に変数名を続けたもの（ここでは TF_VAR_greeting）です。まだ変数ファイルが無い状態で試すと、default の Hello の代わりに環境変数の値が使われます。

Terminal 
$ TF_VAR_greeting='from env' terraform plan -no-color | grep -E '^ +\+ .*wired-stag'          + from env, wired-stag!

① terraform.tfvars: 作業ディレクトリに terraform.tfvars を作ります。変数名 = 値 の形で書きます。

HCL terraform.tfvars 
greeting = "from terraform.tfvars"
Terminal 
$ terraform plan -no-color | grep -E '^ +\+ .*wired-stag'          + from terraform.tfvars, wired-stag!

オプションを何も付けていないのに、terraform.tfvars の値が使われました。この名前のファイルは自動で読み込まれます。

② 環境変数 TF_VAR_greeting: 先ほどの環境変数を、terraform.tfvars を残したまま渡します。

Terminal 
$ TF_VAR_greeting='from env' terraform plan -no-color | grep -E '^ +\+ .*wired-stag'          + from terraform.tfvars, wired-stag!

結果は terraform.tfvars の値のままです。環境変数は terraform.tfvars より弱いことがわかります。

③ -var-file: 任意の名前の変数ファイルを作り、-var-file で指定します。

HCL custom.tfvars 
greeting = "from custom.tfvars"
Terminal 
$ TF_VAR_greeting='from env' terraform plan -no-color -var-file=custom.tfvars | grep -E '^ +\+ .*wired-stag'          + from custom.tfvars, wired-stag!

④ -var: さらに -var も付けます。

Terminal 
$ TF_VAR_greeting='from env' terraform plan -no-color -var-file=custom.tfvars -var 'greeting=from -var' | grep -E '^ +\+ .*wired-stag'          + from -var, wired-stag!

-var-file と -var の書く順番を入れ替えると、結果も入れ替わります。

Terminal 
$ terraform plan -no-color -var 'greeting=from -var' -var-file=custom.tfvars | grep -E '^ +\+ .*wired-stag'          + from custom.tfvars, wired-stag!$ terraform plan -no-color -var-file=custom.tfvars -var 'greeting=from -var' | grep -E '^ +\+ .*wired-stag'          + from -var, wired-stag!

コマンドラインの -var と -var-file は、どちらが強いというより、後に書いた方が勝ちます。

⑤ *.auto.tfvars: 名前が .auto.tfvars で終わるファイルも自動で読み込まれます。my.auto.tfvars を作ります（terraform.tfvars と custom.tfvars は残したままです）。

HCL my.auto.tfvars 
greeting = "from my.auto.tfvars"
Terminal 
$ terraform plan -no-color | grep -E '^ +\+ .*wired-stag'          + from my.auto.tfvars, wired-stag!$ TF_VAR_greeting='from env' terraform plan -no-color | grep -E '^ +\+ .*wired-stag'          + from my.auto.tfvars, wired-stag!$ terraform plan -no-color -var-file=custom.tfvars | grep -E '^ +\+ .*wired-stag'          + from custom.tfvars, wired-stag!

my.auto.tfvars は terraform.tfvars にも環境変数にも勝ちますが、-var-file には負けました。 ここまでの結果を、弱い順に並べると次のとおりです。

順位渡し方確かめた組み合わせと結果
1（最も弱い）variable の default何も渡さないときだけ使われる
2環境変数 TF_VAR_<名前>default には勝つが、terraform.tfvars にも *.auto.tfvars にも負ける
3terraform.tfvars環境変数に勝ち、*.auto.tfvars に負ける
4*.auto.tfvarsterraform.tfvars に勝ち、-var-file に負ける
5（最も強い）-var / -var-fileファイルや環境変数より強い。両方あるときはコマンドラインで後に書いた方が勝つ

この順番は、公式ドキュメントの Input Variables の「Assign values to variables」 に載っている優先順位（強い順に書かれています）と一致します。 terraform.tfvars.json や、*.auto.tfvars が複数あるときの読み込み順も、このページに書かれています。

5

型と validation で値を検査し、sensitive で表示を伏せる

文字列以外の型の変数と、機微な値の変数を追加します。variables.tf を次の内容にします（pet_length・shout・api_token の 3 つを追加）。これが variables.tf の完成形です。

HCL variables.tf 
variable "greeting" {
  type        = string
  description = "ファイルに書くあいさつ文"
  default     = "Hello"
}

variable "owner" {
  type        = string
  description = "ファイルの作成者名（default なし。必ず値を渡す）"
}

variable "pet_length" {
  type        = number
  description = "random_pet の名前を構成する単語の数（1〜5）"
  default     = 2

  validation {
    condition     = var.pet_length >= 1 && var.pet_length <= 5
    error_message = "pet_length は 1 以上 5 以下で指定してください。"
  }
}

variable "shout" {
  type        = bool
  description = "true にするとあいさつ文を大文字にする"
  default     = false
}

variable "api_token" {
  type        = string
  description = "ダミーの API トークン（機微な値の例）"
  sensitive   = true
  default     = "dummy-token-12345"
}
  • pet_length: 数値（number）の変数です。validation ブロックで「1 以上 5 以下」という条件を付けています。condition が false になる値を渡すと、error_message を表示して止まります
  • shout: 真偽値（bool）の変数です。ステップ 6 で使います
  • api_token: sensitive = true を付けた、機微な値の例です。default の dummy-token-12345 は練習用のダミーです。本物のトークンやパスワードを default に書いてはいけません

つまずきポイント

💡

-var を付けたのに、次の plan で差分が出る

-var で渡した値はその 1 回限りで、どこにも保存されません。次の plan / apply で付け忘れると、default（や terraform.tfvars など）の値で計画が作られ、元に戻す差分が出ます。毎回使う値は terraform.tfvars に書きましょう。

💡

Error: No value for required variable で止まる

default の無い変数の値が渡されていません。-input=false を付けていると、入力を求めずにこのエラーで止まります。terraform.tfvars・-var・環境変数 TF_VAR_<名前> のどれかで値を渡してください。

💡

Error: Value for undeclared variable で止まる

-var で渡した変数名が、variable ブロックで宣言されていません。変数名の打ち間違いか、variables.tf への宣言の書き忘れを確かめてください。

💡

Error: Output refers to sensitive values で止まる

sensitive = true の変数から作った値を出力値にするときは、その output ブロックにも sensitive = true が必要です。エラー文の案内どおりに追加してください。

💡

ステップ 3 の grep で何も表示されない

入力変数で設定の外から値を受け取り、出力値で結果を外へ返せるようになりました。値の渡し方には優先順位があること、type と validation で受け取る値を検査できること、sensitive は表示を伏せるだけで state には平文で残ることも確かめました。 次の項目では、設定をモジュールにまとめて再利用します。今回作った入力変数と出力値は、そのままモジュールの「入口」と「出口」になります。
