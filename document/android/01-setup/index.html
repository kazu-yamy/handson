Android アプリがビルドされる流れ

Android アプリのビルドは、ビルドツールの Gradle が担当します。Gradle そのものは Android 専用ではありません。Android のビルド手順は、Gradle のプラグインである AGP（Android Gradle Plugin）が提供します。 Android Studio のビルドボタンも、内部では Gradle を呼び出しています。そのため、ターミナルから ./gradlew を実行しても同じビルドができます。

Text ./gradlew assembleDebug の流れ 
./gradlew assembleDebug
  ├─ Gradle Wrapper   … gradle-wrapper.properties の版の Gradle を用意して起動
  ├─ AGP              … app/build.gradle.kts の android { } を読み、ビルド手順を組み立てる
  ├─ Kotlin コンパイル … src/main/java/ の .kt をコンパイル（Compose コンパイラプラグイン付き）
  ├─ リソース処理・dex 変換
  └─ APK の作成と署名  → app/build/outputs/apk/debug/app-debug.apk
要素役割この項目での設定場所
Gradle（Wrapper）ビルドツール本体。gradlew が決まった版の Gradle を取得して実行するgradle/wrapper/gradle-wrapper.properties
AGPAndroid 向けのビルド手順（リソース処理、dex 変換、APK 作成など）を Gradle に追加するgradle/libs.versions.toml の [plugins]
Kotlin / Compose コンパイラKotlin のソースをコンパイルする。Compose の @Composable 関数は Compose コンパイラプラグインが変換する同上（kotlin-compose）
Android SDKコンパイル対象の Android API（compileSdk）や、エミュレータ、adb などのツール一式Android Studio の SDK Manager

Version Catalog と Compose BOM

Version Catalog は、プロジェクトで使うライブラリとプラグインのバージョンを 1 つのファイル（gradle/libs.versions.toml）に集める Gradle の仕組みです。 ビルドスクリプトにはバージョンを直接書かず、libs.androidx.core.ktx のように、カタログが生成するアクセサで参照します。

セクション書く内容参照の例
[versions]バージョン番号に名前を付けるlibs.versions.kotlin.get()
[libraries]ライブラリ（group・name・バージョン参照）implementation(libs.androidx.core.ktx)
[plugins]Gradle プラグイン（id・バージョン参照）alias(libs.plugins.android.application)

Compose BOM（Bill of Materials）は、互いに組み合わせて動作する Compose ライブラリのバージョンの一覧です。 BOM を platform(...) で依存に加えると、androidx.compose.ui:ui や material3 などは BOM が決めたバージョンで解決されます。 そのため、カタログの [libraries] では、Compose のライブラリにバージョンを書きません。BOM のバージョン（composeBom）を上げれば、Compose 一式がまとめて更新されます。

ℹ️

AGP 9 では Kotlin のプラグインを適用しない

AGP 9.0 から、Kotlin のコンパイル機能が AGP に組み込まれ（built-in Kotlin）、既定で有効になりました。そのため plugins { } に org.jetbrains.kotlin.android（kotlin-android）は書きません。Compose を使うために必要な Compose コンパイラプラグイン（org.jetbrains.kotlin.plugin.compose、カタログの kotlin-compose）だけを適用します。AGP 8 以前の解説記事にある alias(libs.plugins.kotlin.android) は、このプロジェクトでは使いません。

起動時に表示される画面 MainActivity.kt です（作成直後の状態。ステップ 5 で書き換えます）。

Kotlin app/src/main/java/com/handson/android01/MainActivity.kt

        super.onCreate(savedInstanceState)
        enableEdgeToEdge()

            HandsonAndroid01Theme {
                Scaffold(modifier = Modifier.fillMaxSize()) { innerPadding ->
                    Greeting(
                        name = "Android",
                        modifier = Modifier.padding(innerPadding)

            }
        }

}

@Composable
fun Greeting(name: String, modifier: Modifier = Modifier) {

        text = "Hello $name!",

    )

@Preview(showBackground = true)
@Composable
fun GreetingPreview() {

    }
}
  • ComponentActivity: 画面の土台となる Activity です。AndroidManifest.xml で起動時の Activity として登録されています。
  • enableEdgeToEdge(): ステータスバーやナビゲーションバーの裏側まで画面を広げて描画します。
  • setContent { ... }: この中に Compose で UI を書きます。
  • Scaffold: 画面の基本レイアウトです。innerPadding はシステムバーと重ならないための余白で、Modifier.padding(innerPadding) で中身に渡しています。
  • @Composable: UI を組み立てる関数（Composable 関数）であることを示します。@Preview は、Android Studio のプレビューに表示する関数に付けます。

            if (darkTheme) dynamicDarkColorScheme(context) else dynamicLightColorScheme(context)
        }

        darkTheme -> DarkColorScheme
        else -> LightColorScheme
    }

    MaterialTheme(
        colorScheme = colorScheme,
        typography = Typography,
        content = content
    )
}

dynamicColor が true で、かつ Android 12（Build.VERSION_CODES.S）以上の端末では、壁紙から作られる配色（ダイナミックカラー）を使います。それより古い端末では、Color.kt の色で作った LightColorScheme / DarkColorScheme を使います。

エミュレータで実行する

最後に、エミュレータでアプリを動かします。エミュレータで動かす仮想端末を AVD（Android Virtual Device）と呼びます。

Android Studio では、メニューの View > Tool Windows > Device Manager を開き、「+」→ Create Virtual Device から、端末に Pixel 7、システムイメージに API 36 の Google APIs（Apple シリコンの Mac では arm64-v8a）を選んで AVD を作ります。システムイメージが未ダウンロードの場合は、その画面からダウンロードできます。AVD ができたら、ツールバーの target device メニューで AVD を選び、Run ▶ を押すと、エミュレータが起動してアプリがインストール・起動されます。

ターミナルでも同じことができます。まずシステムイメージを入れ、AVD を作ります。sdkmanager と avdmanager は $ANDROID_HOME/cmdline-tools/latest/bin/ にあります（下では PATH に入れた前提で書いています）。

Terminal

Apple シリコンの Mac では arm64-v8a、Intel の Mac では x86_64 のシステムイメージを選びます。エミュレータは CPU の仮想化機能（macOS では Hypervisor.framework）を使います。執筆環境では sysctl kern.hv_support が 1（利用可）で、問題なく起動しました。仮想化が使えない環境では、エミュレータの起動に失敗することがあります。

つまずきポイント

⚠️

Gradle の実行に使う JDK のバージョン

AGP 9.4 の実行には JDK 17 以上が必要です。Android Studio からビルドする場合は、同梱の JDK（JBR）が使われます。ターミナルから ./gradlew を実行する場合は、java -version（または JAVA_HOME）が指す JDK で動きます。この JDK が 17 以上であることを確認してください。

⚠️

BuildConfig が見つからない（Unresolved reference）

AGP 8.0 以降は BuildConfig の生成が既定で無効です（AGP 9 も同じ）。app/build.gradle.kts の buildFeatures に buildConfig = true があるか確認してください（ステップ 5）。

⚠️

AGP 8 以前の手順をそのまま使わない

AGP 9 では Kotlin のコンパイルが AGP に組み込まれたため、org.jetbrains.kotlin.android プラグインは適用しません。古い記事の alias(libs.plugins.kotlin.android) や kotlinOptions { } をそのまま写さないでください。Compose を使うために必要なのは org.jetbrains.kotlin.plugin.compose だけです。

💡

Compose ライブラリにバージョンを書かない

androidx.compose.* のライブラリは Compose BOM がバージョンを決めます。カタログに個別のバージョンを書くと、BOM の組み合わせから外れることがあります。Compose を更新するときは、[versions] の composeBom だけを変えます。Material3 のバージョン（この項目では 1.4.0）も BOM が決めています。

💡

カタログを編集した後は同期する

libs.versions.toml を変更した直後は、Android Studio のエディタが新しいアクセサ（libs.kotlinx.coroutines.android など）を認識しません。Sync Now で同期してください。ターミナルの ./gradlew は、実行のたびにカタログを読み込みます。

まとめ

Android Studio の Empty Activity でプロジェクトを作り、Gradle でビルド・lint・テストを実行し、エミュレータで動かすところまでを体験しました。 ライブラリとプラグインのバージョンは Version Catalog（gradle/libs.versions.toml）に集め、Compose のライブラリは Compose BOM でまとめてそろえます。これが、以降の項目でも使う依存管理の形です。 次の項目では、Android 開発に必要な Kotlin の文法を学びます。
