1

変数・関数・文字列テンプレート・when 式

まず、Kotlin の最小限の書き方を確かめます。Basics.kt を作り、次の内容を書きます。

Kotlin app/src/main/java/com/handson/android01/kotlin/Basics.kt 
package com.handson.android01.kotlin

// Step 1: 変数・関数・文字列テンプレート・when 式

// 再代入できない（Java の final 相当）。型は右辺から推論される（String）
val appName = "HandsonAndroid02"

// 再代入できる。型は推論されるが、ここでは Int のまま
var counter = 0

// デフォルト引数: 省略すると既定値が使われる
fun greet(name: String, greeting: String = "こんにちは", punctuation: String = "！"): String =
    "$greeting、$name$punctuation"

// 単一式関数: 戻り値の型を省略でき、= の右辺がそのまま戻り値になる
fun add(a: Int, b: Int): Int = a + b

// when は式として値を返せる。上から順に評価され、最初に一致した分岐が使われる
fun describeNumber(n: Int): String = when {
    n < 0 -> "負の数"
    n == 0 -> "ゼロ"
    n % 2 == 0 -> "正の偶数"
    else -> "正の奇数"
}

// 値そのものと比較する when（複数の値を , で並べられる）
fun dayType(day: String): String = when (day) {
    "土", "日" -> "休日"
    else -> "平日"
}

// 文字列テンプレート: $変数名、または ${式}
fun formatSum(a: Int, b: Int): String = "${a} + ${b} = ${add(a, b)}"

fun incrementCounter(): Int {
    counter++
    return counter
}
  • val は再代入できない変数（Java の final 相当）、var は再代入できる変数です。val appName = "HandsonAndroid02" のように右辺があれば型を書かなくても推論されます（appName は String、counter は Int）。
  • greet の greeting: String = "こんにちは" はデフォルト引数です。呼び出し側で省略すると既定値が使われます。
  • fun add(a: Int, b: Int): Int = a + b は単一式関数です。{ return ... } の代わりに = の右辺が戻り値になります。
  • when は値を返す式です。条件だけを並べる形（describeNumber）と、値と比較する形（dayType）があります。"土", "日" のように , で複数の値をまとめられます。
  • "$greeting、$name$punctuation" や "${add(a, b)}" は文字列テンプレートです。$変数名 で変数を、${式} で式の結果を埋め込みます。
  • 関数も変数も、クラスの外（ファイル直下）に書いています。これをトップレベル関数・トップレベルプロパティと呼びます。

次に、テストを BasicsTest.kt に書きます。

2

null 安全

Kotlin では、String 型の変数に null を入れられません。null を入れたい場合は String? のように型に ? を付けます。こうすると、null の可能性がある値をそのまま使うコードはコンパイルエラーになります。Java でよく起きる NullPointerException を、コンパイル時に防ぐ仕組みです。

Android では、値が無い可能性のある入力が頻繁に登場します。たとえば、画面に渡される Intent.extras（Bundle）は、キーが無いと null を返します。API から受け取る JSON の省略可能なフィールドや、データを読み込む前の画面の状態も null になりえます。ここでは Bundle の代わりに Map を使って、同じ状況を作ります。

NullSafety.kt を作ります。

Kotlin app/src/main/java/com/handson/android01/kotlin/NullSafety.kt 
package com.handson.android01.kotlin

// Step 2: null 安全

// 型に ? を付けると null を入れられる。String は null を入れられない
fun findNickname(users: Map<String, String?>, id: String): String? = users[id]

// ?. 安全呼び出し: レシーバーが null なら式全体が null になる
fun nicknameLength(nickname: String?): Int? = nickname?.length

// ?: エルビス演算子: 左辺が null のときだけ右辺を使う
fun displayName(nickname: String?): String = nickname ?: "名無し"

// !! 非 null アサーション: null なら NullPointerException を投げる
fun forceLength(nickname: String?): Int = nickname!!.length

// let: null でないときだけブロックを実行する（it は非 null の値）
fun greetIfPresent(nickname: String?): String? = nickname?.let { "こんにちは、$it" }

// スマートキャスト: null チェックの後は String として扱える（!! は不要）
fun lengthOrZero(text: String?): Int {
    if (text != null) {
        return text.length
    }
    return 0
}

// Android では Intent.extras（Bundle）のように、値が無いかもしれない入力が多い。
// Bundle の代わりに Map で模擬する
fun readTitle(extras: Map<String, Any?>?): String {
    val title = extras?.get("title") as? String
    return title ?: "untitled"
}

class Profile {
    // lateinit: 後から代入する前提の var。代入前に読むと例外になる。
    // プリミティブ型（Int など）と null 許容型（String?）には付けられない
    lateinit var name: String

    // by lazy: 初めて読んだときに一度だけ計算される val
    val summary: String by lazy { "profile:$name" }
}
書き方意味この例
T?null を入れられる型findNickname の戻り値 String?
a?.b安全呼び出し。a が null なら式全体が nullnickname?.length
a ?: bエルビス演算子。a が null のときだけ b を使うnickname ?: "名無し"
a!!非 null アサーション。null なら NullPointerExceptionnickname!!.length
a?.let { }null でないときだけブロックを実行するgreetIfPresent
スマートキャストif (text != null) の後は String として扱えるlengthOrZero
as?安全キャスト。型が違えば nullreadTitle

Profile クラスでは、初期化を後回しにする 2 つの方法を比べます。

  • lateinit var: 「後で必ず代入する」と約束した var です。型は非 null（String）のまま書けます。代入する前に読むと例外になります。Int などのプリミティブ型と、String? のような null 許容型には付けられません。
  • by lazy { }: 最初に読んだときに一度だけブロックを実行し、その結果を覚えておく val です。

テストを NullSafetyTest.kt に書きます。!! と lateinit で投げられる例外のメッセージを確かめるため、println で出力しています。

Kotlin app/src/test/java/com/handson/android01/kotlin/NullSafetyTest.kt 
package com.handson.android01.kotlin

import org.junit.Assert.assertEquals
import org.junit.Assert.assertNull
import org.junit.Assert.assertThrows
import org.junit.Test

class NullSafetyTest {
    private val users: Map<String, String?> = mapOf("u1" to "taro", "u2" to null)

    @Test
    fun findNickname_returnsNullableValue() {
        assertEquals("taro", findNickname(users, "u1"))
        assertNull(findNickname(users, "u2"))
        assertNull(findNickname(users, "unknown"))
    }

    @Test
    fun safeCall_returnsNullWhenReceiverIsNull() {
        assertEquals(4, nicknameLength("taro"))
        assertNull(nicknameLength(null))
    }

    @Test
    fun elvis_providesFallback() {
        assertEquals("taro", displayName("taro"))
        assertEquals("名無し", displayName(null))
    }

    @Test
    fun forceUnwrap_throwsNullPointerException_whenNull() {
        assertEquals(4, forceLength("taro"))
        val e = assertThrows(NullPointerException::class.java) { forceLength(null) }
        println("NPE message: ${e.message}")
    }

    @Test
    fun let_runsOnlyWhenNotNull() {
        assertEquals("こんにちは、taro", greetIfPresent("taro"))
        assertNull(greetIfPresent(null))
    }

    @Test
    fun smartCast_afterNullCheck() {
        assertEquals(4, lengthOrZero("taro"))
        assertEquals(0, lengthOrZero(null))
    }

    @Test
    fun readTitle_handlesMissingExtras() {
        assertEquals("Lesson", readTitle(mapOf("title" to "Lesson")))
        assertEquals("untitled", readTitle(null))
        assertEquals("untitled", readTitle(mapOf("title" to 42)))
    }

    @Test
    fun lateinit_throwsUntilAssigned() {
        val profile = Profile()
        val e = assertThrows(UninitializedPropertyAccessException::class.java) { profile.name }
        println("lateinit message: ${e.message}")
        profile.name = "taro"
        assertEquals("taro", profile.name)
    }

    @Test
    fun byLazy_computesOnce() {
        val profile = Profile()
        profile.name = "taro"
        assertEquals("profile:taro", profile.summary)
        profile.name = "hanako"
        // 初回読み取りの値がキャッシュされる
        assertEquals("profile:taro", profile.summary)
    }
}

データクラスと sealed interface

アプリが扱うデータ（Todo など）と、画面の状態（読み込み中・成功・エラー）を型で表します。Models.kt を作ります。

Kotlin app/src/main/java/com/handson/android01/kotlin/Models.kt 
package com.handson.android01.kotlin

// Step 3: データクラス・sealed interface・enum class

// data class: equals / hashCode / toString / copy / 分解宣言が自動で生成される
data class Todo(
    val id: Int,
    val title: String,
    val done: Boolean = false,
)

// enum class: 決まった値の集合。when で網羅的に扱える
enum class Priority { LOW, MEDIUM, HIGH }

// sealed interface: 実装クラスを同じモジュール・同じパッケージ内に限定できる（Kotlin 1.5 以降）。
// when で全ての子型を書けば、else なしでも網羅性がコンパイル時に検査される
sealed interface UiState {
    data object Loading : UiState
    data class Success(val data: List<Todo>) : UiState
    data class Error(val message: String) : UiState
}

fun stateLabel(state: UiState): String = when (state) {
    is UiState.Loading -> "読み込み中"
    is UiState.Success -> "${state.data.size} 件"
    is UiState.Error -> "エラー: ${state.message}"
}

fun priorityLabel(priority: Priority): String = when (priority) {
    Priority.LOW -> "低"
    Priority.MEDIUM -> "中"
    Priority.HIGH -> "高"
}
  • data class: コンストラクタの引数（プロパティ）から、equals / hashCode / toString / copy / 分解宣言用の関数が自動で作られます。val だけで書けば不変（作った後に中身が変わらない）なクラスになります。
  • done: Boolean = false: コンストラクタにもデフォルト引数を書けます。Todo(1, "買い物") と書けば done は false です。
  • enum class: 決まった値の集合です。Priority.entries で全ての値を一覧できます。
  • sealed interface: 実装できる型を、同じモジュール・同じパッケージの中に限定できます（Kotlin 1.5 以降）。コンパイラが子型をすべて把握できるので、when で全ての子型を書けば else は不要です。
  • data object Loading: 状態を持たない子型は object（インスタンスが 1 つだけのクラス）にします。data を付けると toString が Loading のように読みやすくなります。
  • is UiState.Success -> "${state.data.size} 件": is で型を判定した分岐の中では、state が UiState.Success にスマートキャストされ、data を参照できます。

この UiState の形は、06（ViewModel と StateFlow）で画面の状態を表すときにも使います。

テストを ModelsTest.kt に書きます。

Kotlin app/src/test/java/com/handson/android01/kotlin/ModelsTest.kt 
package com.handson.android01.kotlin

import org.junit.Assert.assertEquals
import org.junit.Assert.assertNotEquals
import org.junit.Assert.assertTrue
import org.junit.Test

class ModelsTest {
    private val todo = Todo(id = 1, title = "Kotlin を学ぶ")

    @Test
    fun dataClass_hasDefaultValue() {
        assertEquals(false, todo.done)
    }

    @Test
    fun dataClass_copyChangesOnlySpecifiedField() {
        val done = todo.copy(done = true)
        assertEquals(true, done.done)
        assertEquals(todo.title, done.title)
        // copy は新しいインスタンスを返し、元の値は変わらない
        assertEquals(false, todo.done)
    }

    @Test
    fun dataClass_equalsComparesFields() {
        assertEquals(Todo(1, "Kotlin を学ぶ"), todo)
        assertNotEquals(Todo(2, "Kotlin を学ぶ"), todo)
    }

    @Test
    fun dataClass_destructuring() {
        val (id, title, done) = todo
        assertEquals(1, id)
        assertEquals("Kotlin を学ぶ", title)
        assertEquals(false, done)
    }

    @Test
    fun dataClass_toStringShowsFields() {
        assertTrue(todo.toString().startsWith("Todo(id=1, title=Kotlin を学ぶ, done=false)"))
    }

    @Test
    fun sealedWhen_coversAllStates() {
        assertEquals("読み込み中", stateLabel(UiState.Loading))
        assertEquals("2 件", stateLabel(UiState.Success(listOf(todo, todo.copy(id = 2)))))
        assertEquals("エラー: 通信失敗", stateLabel(UiState.Error("通信失敗")))
    }

    @Test
    fun enum_whenReturnsLabel() {
        assertEquals("低", priorityLabel(Priority.LOW))
        assertEquals("中", priorityLabel(Priority.MEDIUM))
        assertEquals("高", priorityLabel(Priority.HIGH))
        assertEquals(listOf("LOW", "MEDIUM", "HIGH"), Priority.entries.map { it.name })
    }
}
  • todo.copy(done = true) は、指定したプロパティだけを変えた新しいインスタンスを返します。元の todo は変わりません。

コレクションとラムダ

Todo のリストを、ラムダを使って加工します。Collections.kt を作ります。

Kotlin app/src/main/java/com/handson/android01/kotlin/Collections.kt 
package com.handson.android01.kotlin

// Step 4: コレクションとラムダ

// List は読み取り専用（要素の追加・削除はできない）
fun sampleTodos(): List<Todo> = listOf(
    Todo(1, "買い物", done = true),
    Todo(2, "掃除"),
    Todo(3, "Kotlin を学ぶ", done = true),
    Todo(4, "散歩"),
)

// MutableList は可変（追加・削除ができる）
fun collectTitles(todos: List<Todo>): MutableList<String> {
    val result = mutableListOf<String>()
    for (todo in todos) {
        result.add(todo.title)
    }
    return result
}

// it: ラムダの引数が 1 つのときの暗黙の名前
fun titlesOfDone(todos: List<Todo>): List<String> =
    todos.filter { it.done }.map { it.title }

// 明示的なラムダ引数: 引数が複数あるときは名前を付ける
fun sortedByIdDescending(todos: List<Todo>): List<Todo> =
    todos.sortedBy { todo -> -todo.id }

// groupBy: キーごとに要素をまとめた Map を作る
fun groupByDone(todos: List<Todo>): Map<Boolean, List<Todo>> =
    todos.groupBy { it.done }

// firstOrNull: 条件に合う最初の要素。無ければ null
fun findTodo(todos: List<Todo>, id: Int): Todo? =
    todos.firstOrNull { it.id == id }

// 末尾ラムダ: 最後の引数がラムダなら、括弧の外に書ける
fun countWhere(todos: List<Todo>, predicate: (Todo) -> Boolean): Int =
    todos.count(predicate)
  • listOf(...) が返すリストは、要素の追加・削除ができません（サイズ固定）。add や remove は List 型にありません。
  • mutableListOf() が返す MutableList は、要素の追加・削除ができます。
  • { it.done } はラムダ（その場で書く無名の関数）です。引数が 1 つのときは、it という暗黙の名前で参照できます。{ todo -> -todo.id } のように -> の左に名前を付けることもできます。
  • filter（条件に合う要素だけ残す）・map（要素を変換する）・sortedBy（キーで並べ替える）・groupBy（キーごとにまとめた Map を作る）・firstOrNull（条件に合う最初の要素。無ければ null）は、いずれも元のリストを変えずに新しい結果を返します。
  • predicate: (Todo) -> Boolean は関数型です。「Todo を受け取って Boolean を返す関数」を引数に取ります。

拡張関数とスコープ関数

既存の型に関数を追加する拡張関数と、オブジェクトに対する処理をまとめるスコープ関数を書きます。Extensions.kt を作ります。

Kotlin app/src/main/java/com/handson/android01/kotlin/Extensions.kt 
package com.handson.android01.kotlin

// Step 5: 拡張関数とスコープ関数

// 拡張関数: 既存の型に、クラスを継承せずに関数を足す。レシーバーは this で参照する
fun String.toTitleCase(): String =
    split(" ").joinToString(" ") { word -> word.replaceFirstChar { it.uppercaseChar() } }

// List<Todo> に対する拡張関数。Todo のリストを加工する
fun List<Todo>.doneCount(): Int = count { it.done }

// 表示用の 1 行にまとめる（MainActivity の画面で使う）
fun List<Todo>.summaryLine(): String = "${size} 件中 ${doneCount()} 件完了"

// 組み立て用の可変クラス（Todo は data class で不変にしたので、初期化の例として別に用意）
class TodoDraft {
    var title: String = ""
    var done: Boolean = false
}

// apply: レシーバーを初期化し、レシーバー自身を返す（オブジェクトの設定）
fun draftWithApply(title: String): TodoDraft = TodoDraft().apply {
    this.title = title
    done = false
}

// also: 副作用（ログ・追加処理）を入れ、レシーバー自身を返す
fun addAndRecord(list: MutableList<String>, title: String): MutableList<String> =
    list.also { it.add(title) }

// run: レシーバーを使って結果の値を計算する（this でレシーバーを参照）
fun summarizeWithRun(todos: List<Todo>): String = todos.run {
    "${size} 件中 ${doneCount()} 件完了"
}

// with: レシーバーを引数で渡し、ブロックの結果を返す（拡張関数ではなく通常の関数）
fun summarizeWithWith(todos: List<Todo>): String = with(todos) {
    "${size} 件中 ${doneCount()} 件完了"
}
  • fun String.toTitleCase() は String の拡張関数です。"hello kotlin world".toTitleCase() のように、String のメソッドと同じ形で呼べます。関数の中では、レシーバー（呼び出し元の値）を this で参照できます。this は省略できるので、split(" ") は this.split(" ") と同じです。
  • fun List<Todo>.doneCount() のように、型引数を指定した型にも拡張関数を定義できます。List<String> には doneCount は現れません。
  • 拡張関数は、クラスを継承したり書き換えたりはしません。実体は「レシーバーを第 1 引数に取る static 関数」で、Java の StringUtils.toTitleCase(s) のようなユーティリティを、呼び出しやすい形で書けるようにしたものです。

スコープ関数は、レシーバーの参照方法（this か it）と、戻り値（レシーバー自身かラムダの結果か）で使い分けます。

関数レシーバーの参照戻り値主な用途この項目での例
applythis（省略可）レシーバー自身オブジェクトの初期化・設定draftWithApply
alsoitレシーバー自身副作用（ログ・追加処理）addAndRecord
runthis（省略可）ラムダの結果レシーバーを使って値を計算summarizeWithRun
withthis（省略可）ラムダの結果既存オブジェクトに対する処理（拡張関数ではない）summarizeWithWith
letitラムダの結果null でないときだけ処理（ステップ 2）greetIfPresent

Coroutines.kt を作ります。通信の代わりに delay で待ちます。

Kotlin app/src/main/java/com/handson/android01/kotlin/Coroutines.kt 
package com.handson.android01.kotlin

import kotlinx.coroutines.Dispatchers
import kotlinx.coroutines.async
import kotlinx.coroutines.coroutineScope
import kotlinx.coroutines.delay
import kotlinx.coroutines.withContext

// Step 6: コルーチンの入口

// suspend fun: 途中で中断・再開できる関数。delay は待ち時間の間スレッドを塞がない
suspend fun fetchTodos(): List<Todo> {
    delay(1000) // 通信の代わりに 1 秒待つ
    return sampleTodos()
}

// withContext(Dispatchers.IO): ブロッキングになりうる処理を IO 用のスレッドで実行する
suspend fun fetchTodosOnIo(): List<Todo> = withContext(Dispatchers.IO) {
    delay(1000)
    sampleTodos()
}

// async / await: 2 つの処理を並列に走らせ、両方の結果を待つ
suspend fun fetchTodosAndCount(): Pair<List<Todo>, Int> = coroutineScope {
    val todos = async { fetchTodos() }
    val count = async {
        delay(1000)
        4
    }
    todos.await() to count.await()
}
  • suspend fun: 途中で中断・再開できる関数です。suspend 関数は、コルーチンの中か、別の suspend 関数の中からだけ呼べます。
  • delay(1000): 1 秒待ちます。待っている間、スレッドを塞ぎません（Java の Thread.sleep とは違います）。
  • withContext(Dispatchers.IO): ブロックを IO 用のスレッドで実行し、結果を返します。
  • coroutineScope + async / await: 2 つの処理を並行して開始し、両方の結果を待ちます。todos.await() to count.await() の to は、2 つの値から Pair を作る関数です。

テストを CoroutinesTest.kt に書きます。suspend 関数を呼ぶため、テストの本体を runTest { } で囲みます。

Kotlin app/src/test/java/com/handson/android01/kotlin/CoroutinesTest.kt 
package com.handson.android01.kotlin

import kotlinx.coroutines.delay
import kotlinx.coroutines.launch
import kotlinx.coroutines.test.advanceTimeBy
import kotlinx.coroutines.test.currentTime
import kotlinx.coroutines.test.runCurrent
import kotlinx.coroutines.test.runTest
import org.junit.Assert.assertEquals
import org.junit.Assert.assertFalse
import org.junit.Assert.assertTrue
import org.junit.Test

class CoroutinesTest {
    @Test
    fun delay_doesNotConsumeRealTime() = runTest {
        val startedAt = System.currentTimeMillis()
        val todos = fetchTodos()
        val elapsedRealMs = System.currentTimeMillis() - startedAt

        assertEquals(4, todos.size)
        // 仮想時間では 1000ms 進んでいる
        assertEquals(1000L, currentTime)
        // 実時間はほとんど消費していない
        assertTrue("実時間 ${elapsedRealMs}ms", elapsedRealMs < 1000)
    }

    @Test
    fun advanceTimeBy_controlsVirtualClock() = runTest {
        var finished = false
        launch {
            delay(500)
            finished = true
        }
        advanceTimeBy(499)
        assertFalse(finished)
        advanceTimeBy(1)
        runCurrent()
        assertTrue(finished)
        assertEquals(500L, currentTime)
    }

    @Test
    fun withContext_ioDispatcher_returnsResult() = runTest {
        assertEquals(4, fetchTodosOnIo().size)
    }

    @Test
    fun async_runsInParallel() = runTest {
        val (todos, count) = fetchTodosAndCount()
        assertEquals(4, todos.size)
        assertEquals(4, count)
        // 直列なら 2000ms かかるが、並列なので 1000ms
        assertEquals(1000L, currentTime)
    }
}
  • runTest の中の delay は、実際には待たずに仮想時間を進めます。currentTime は仮想時間（ミリ秒）です。delay_doesNotConsumeRealTime では、仮想時間が 1000ms 進む一方で、実時間は 1000ms 未満であることを確かめています。
  • 仮想時間になるのは、テストディスパッチャ上の delay だけです。withContext(Dispatchers.IO) に切り替えた先は実時間で待つため、fetchTodosOnIo の処理は実測で約 1 秒かかります（この実行では 1.053 秒）。だから本番コードでは、ディスパッチャを引数で注入できる形にします。
  • advanceTimeBy_controlsVirtualClock では、launch で開始した処理を仮想時間で少しずつ進めます。advanceTimeBy(499) の時点では delay(500) の後ろは実行されません。advanceTimeBy(1) で 500ms に達した後、runCurrent() を呼ぶと、その時点で実行可能な処理が実行されて finished が true になります。
  • async_runsInParallel では、1 秒かかる処理を 2 つ並行に実行しています。直列なら 2000ms かかるところが、仮想時間 1000ms で終わります。

演習

以下のチェックリストを使って、このレッスンの内容を振り返りましょう。

つまずきポイント

⚠️

./gradlew test --tests ... はエラーになる

ルートの test タスクは、複数のテストタスクを束ねたものなので --tests を受け付けず、Unknown command-line option '--tests' で失敗します。テストクラスを絞り込むときは、モジュールとビルドバリアントを指定した ./gradlew :app:testDebugUnitTest --tests '...' を使います。全テストを実行するだけなら ./gradlew test で構いません。

⚠️

!! を多用しない

!! で投げられる NullPointerException のメッセージは null です（ステップ 2）。どの値が null だったかが分からないので、原因の調査に時間がかかります。?.・?:・スマートキャストで、null のときの扱いをコードに書いてください。

⚠️

lateinit と null 許容型は別物

lateinit var name: String は「読む前に必ず代入する」という約束で、守らないと UninitializedPropertyAccessException になります。var name: String? は最初から null を許し、読む側で null を処理します。代入されないことがありうる値には、lateinit ではなく null 許容型を使います。Int などのプリミティブ型や String? には lateinit を付けられません。

⚠️

List 型でも中身が変更不可とは限らない

List の読み取り専用は型の上だけの約束です。ステップ 4 のテストのように as MutableList でキャストできてしまい、変更できるかどうかは中身の実装で決まります。キャストで List を書き換えず、変更が必要なら toMutableList() でコピーを作るか、最初から MutableList として扱います。

💡

== と === の違い

Kotlin の == は equals による値の比較で、Java の ==（参照の比較）とは意味が違います。同じインスタンスかどうかを比べるのは === です（ステップ 5 の also_addsAndReturnsSameList で使っています）。data class は == でプロパティの値が比較されます（ステップ 3 の assertEquals で確かめます）。

💡

スコープ関数は戻り値で選ぶ

迷ったら、まず「レシーバー自身を返したいか（apply / also）、ラムダの結果を返したいか（run / let / with）」で絞ります。次に、ブロックの中でレシーバーを this（省略可）で使うか、it で使うかで選びます。スコープ関数を入れ子にすると this や it が何を指すか分かりにくくなるので、深く重ねないようにします。

💡

テストでは runBlocking ではなく runTest を使う

runBlocking でもテストから suspend 関数を呼べますが、delay を実時間で待ちます。delay(1000) を含むテストは 1 秒かかります。runTest は仮想時間で進めるため、テストディスパッチャ上の delay は一瞬で終わり、advanceTimeBy で時間の進み方も制御できます。ただし仮想時間になるのはテストディスパッチャ上の delay だけです。withContext(Dispatchers.IO) の先は実時間で待ちます。

ℹ️

Java のコードを呼ぶときの platform type

注釈のない Java の戻り値は platform type（String!）になります。Kotlin はこの型で null チェックを強制しません。@Nullable / @NotNull などが付いていれば、通常の null 許容型・非 null 型として見えます。この項目のコードでは Java の API を呼んでいないため、この挙動は実際には確かめていません。

ℹ️

Android Studio の「Convert Java to Kotlin」

Android Studio には、Java のファイルを Kotlin に変換する機能があります。変換後のコードでは、!! や Any? の箇所が増える場合があります。変換結果はそのまま使わず、null 許容型を見直してください。この項目では変換を試していません。

まとめ

val / var と when 式から始めて、null 安全、データクラスと sealed interface、コレクションとラムダを書きました。続いて拡張関数とスコープ関数、suspend 関数を、いずれもテストで動作を確かめながら書きました。 最後に、作った Todo と拡張関数を Compose の画面から呼び出し、表示を変えました。 次の項目では、Composable 関数とプレビューを使った UI の組み立て方を学びます。
