概要

07 までのアプリは、MainActivity が Todo の一覧（TodoListPage）を直接表示する 1 画面だけでした。 この項目では、一覧の行のタイトルを押すと開く「詳細」画面を足し、2 つの画面を行き来できるようにします。画面遷移には、Jetpack の Navigation 3 を使います。

前提知識として、04 の State hoisting（状態は下へ、イベントは上へ）を使います。07 の viewModel()・collectAsStateWithLifecycle()・SavedStateHandle も使います。

Navigation 3 の考え方

Navigation 3 で画面遷移を組み立てる部品は、次の 3 つです。

  • キー: 画面を表す値です。NavKey を実装した object や data class で作ります。NavKey はメソッドを持たない、印を付けるだけのインターフェースです。引数付きの画面は、引数を data class のプロパティとして持たせます。
  • バックスタック: キーを並べたリストです。このリストは、アプリが自分で持ちます。進むときはリストにキーを追加し（add）、戻るときは末尾を取り除きます（removeLastOrNull）。
  • NavDisplay と entryProvider: entryProvider は「キーの型ごとに、どの画面を出すか」の対応表です。NavDisplay は、バックスタックの末尾のキーを entryProvider で画面に変えて表示します。

画面を切り替える操作は、すべて「リストを書き換える」ことになります。リストが変わると、NavDisplay が末尾のキーに合わせて画面を出し直します。Navigation 3 は、従来の Navigation Compose（androidx.navigation:navigation-compose）とは別のライブラリです。この項目では Navigation Compose は使いません。

import androidx.navigation3.runtime.NavKey

// 画面を表す「キー」。Navigation 3 では、バックスタックの中身はこのキーが並んだただのリスト。

画面遷移の本体を作ります。ui/navigation/TodoApp.kt を新しく作ります。

Kotlin app/src/main/java/com/handson/android01/ui/navigation/TodoApp.kt 
package com.handson.android01.ui.navigation

import androidx.compose.runtime.Composable
import androidx.compose.runtime.mutableStateListOf
import androidx.compose.runtime.remember
import androidx.compose.ui.Modifier
import androidx.lifecycle.viewmodel.compose.viewModel
import androidx.navigation3.runtime.NavKey
import androidx.navigation3.runtime.entryProvider
import androidx.navigation3.ui.NavDisplay
import com.handson.android01.ui.screens.TodoDetailPage
import com.handson.android01.ui.screens.TodoListPage
import com.handson.android01.ui.screens.TodoListViewModel

// アプリ全体の画面遷移。バックスタックは「キーを並べただけのリスト」で、自分で持つ。
// 進む = リストに追加、戻る = 末尾を取り除く。NavDisplay は、末尾のキーに対応する画面を表示する
@Composable
fun TodoApp(
    modifier: Modifier = Modifier,
    // NavDisplay の外（Activity が持ち主の ViewModelStoreOwner）で作るので、一覧と詳細で同じインスタンスを使える
    viewModel: TodoListViewModel = viewModel(),
) {
    val backStack = remember { mutableStateListOf<NavKey>(TodoList) }

    NavDisplay(
        backStack = backStack,
        modifier = modifier,
        // システムの戻る操作（ジェスチャー・戻るボタン）で呼ばれる。末尾を取り除くと、1 つ前の画面が表示される
        onBack = { backStack.removeLastOrNull() },
        // entryProvider: キーから「画面（NavEntry）」を作る対応表。entry<キーの型> { key -> 画面 } と書く
        entryProvider = entryProvider {
            entry<TodoList> {
                TodoListPage(
                    viewModel = viewModel,
                    onOpenDetail = { id -> backStack.add(TodoDetail(id)) },
                )
            }
            entry<TodoDetail> { key ->
                TodoDetailPage(
                    todoId = key.id,
                    viewModel = viewModel,
                    onBack = { backStack.removeLastOrNull() },
                )
            }
        },
    )
}
  • remember { mutableStateListOf<NavKey>(TodoList) }: バックスタックです。最初は一覧のキーだけが入っています。Compose が変更を検知できるリストなので、add すると NavDisplay が表示を変えます。回転で消える弱点があり、ステップ 3 で直します。
  • entryProvider { entry<TodoList> { ... } entry<TodoDetail> { key -> ... } }: キーの型ごとに出す画面を書きます。entry<TodoDetail> のラムダは、キーそのもの（key）を受け取ります。key.id が詳細画面の引数です。
  • onBack: システムの戻る操作（戻るボタン・ジェスチャー）で呼ばれます。末尾を取り除くと、1 つ前の画面が表示されます。上部バーの戻るボタンにも、同じ処理を渡しています。
  • viewModel: TodoListViewModel = viewModel(): NavDisplay の外で 1 つ作り、一覧と詳細の両方に渡します。理由はステップ 2 で説明します。

引数付きのキーと詳細での操作

詳細画面で、完了の切り替えと削除をできるようにします。削除したら一覧へ戻ります。どの Todo を表示するかは、ステップ 1 でキー TodoDetail(id) の id として渡せています。ここでは、詳細の操作が一覧に反映されることを確かめます。

データの置き場所: 一覧の ViewModel を共有する

詳細画面のデータは、一覧と同じ TodoListViewModel から読みます。TodoApp が NavDisplay の外で viewModel() を呼ぶので、ViewModel の持ち主は Activity です。その同じインスタンスを、一覧の entry と詳細の entry に引数で渡しています。この形にした理由は次のとおりです。

  • 同期の仕組みが要らない: 一覧と詳細は同じ Todo の一覧を見ます。持ち主が 1 つなら、詳細で変えた完了状態が、戻った一覧にそのまま出ます。
  • 保存の仕組みが既にある: TodoListViewModel は、07 で SavedStateHandle に一覧を保存しています。別の置き場を足すと、プロセスの再生成から復元する仕組みを二重に持つことになります。
  • 07 のコードを変えずに済む: ViewModel と、そのテスト（TodoListViewModelRecreationTest など）はそのまま使えます。
  • 詳細専用の ViewModel は作らない: 詳細だけが持つ状態は「どの Todo か」（キーの id）だけです。uiState.todos.find { it.id == todoId } を、詳細の画面状態とみなします。

ViewModel は、手書きで引数に渡しています。依存性の注入（DI）は、後の項目（Hilt）で扱います。

⚠️

Unknown screen ... で落ちる

⚠️

NavDisplay backstack cannot be empty で落ちる

⚠️

回転すると一覧に戻ってしまう

バックスタックを remember で持っています。rememberNavBackStack に替え、キーに @Serializable を付けます。

⚠️

ホームボタンを押すと Serializer for class '...' is not found で落ちる

キーに @Serializable が付いていません。build.gradle.kts に kotlin.serialization プラグインがあることも確かめます。

⚠️

詳細で削除した後も「この Todo は見つかりません」が表示されたまま、一覧へ戻らない

deleteTodo の後に onBack() を呼んでいません。削除と戻る操作は、同じイベントの中で続けて呼びます。一覧へは戻るのに、戻る途中で「見つかりません」が一瞬表示される場合は、TodoDetailPage の lastFound（最後に見つかった Todo を表示する処理）が抜けています。

まとめ

画面を表すキー（TodoList・TodoDetail(id)）を作り、キーのリストをバックスタックとして自分で持ちました。進む・戻るはリストの add と removeLastOrNull で、NavDisplay が末尾のキーの画面を entryProvider から選んで表示します。 詳細画面は一覧と同じ ViewModel を見るので、詳細での完了切替と削除がそのまま一覧に反映されます。 最後に、バックスタックを rememberNavBackStack と @Serializable で保存しました。回転とプロセスの再生成の後も詳細が戻ることは、UI テストと am kill で確かめました。
