概要

08 までのアプリは、ViewModel が 1 秒待ってから、アプリの中で作ったデモデータ（demoTodos(20)）を一覧に入れていました（07 の疑似読み込み）。 この項目では、これをインターネット上の Web API からの取得に置き換えます。HTTP 通信には Ktor Client、JSON の変換には kotlinx.serialization を使います。

前提知識として、07 の viewModelScope と SavedStateHandle を使います。既存のテストのつなぎ替えでは、07 のテスト用ディスパッチャー（runTest・StandardTestDispatcher・UnconfinedTestDispatcher）が出てきます。08 で導入した serialization プラグイン（@Serializable）も使います。

取得する API

取得先は JSONPlaceholder（https://jsonplaceholder.typicode.com）の /todos です。JSONPlaceholder は、外部の練習用の公開 API です。_limit=20 を付けて、先頭の 20 件だけを取得します（付けないと 200 件が返ります）。次のレスポンスは、筆者が 2026年10月4日 05:18（日本時間）に取得したものの先頭部分です。

エンジンに Android エンジンを選んだ理由

Ktor Client は、実際に通信する部分を「エンジン」として差し替えられます。Ktor 3.6.0 のドキュメント（Client engines）は、Android 向けに OkHttp エンジンと Android エンジンを挙げています。この教材は、サードパーティのライブラリを使わず、公式のパッケージだけで構成する方針です。そこで、サードパーティの HTTP ライブラリ（OkHttp は Square 製）に依存しない Android エンジン（ktor-client-android）を使います。通信はプラットフォームの HttpURLConnection が行うので、端末のネットワークセキュリティ設定（cleartext の禁止など）がそのまま効きます。Android エンジンは HTTP/2 と WebSockets に対応しませんが、この項目の用途（HTTPS の GET で JSON を取得する）には不要です。エンジンは HttpClient(エンジン) の引数で替えられるので、後で替えてもコードはほとんど変わりません。

コードは Ktor と kotlinx.serialization の公式の API だけを使います。ただし、Ktor の artifact の推移的依存として、okio などのライブラリは入ります。ktor-serialization-kotlinx-json が YAML のライブラリを経由して引き込むもので、コードからは直接使いません。

INTERNET を書き忘れると、通信できない

ビルド時に作られるマージ後のマニフェスト（依存のマニフェストを合わせたもの）で、INTERNET はこの 1 行の 1 件だけでした。ktor-client-android を含め、どのライブラリも INTERNET を宣言していません。自分で宣言するライブラリもあり、その場合は書き忘れても動いてしまいます。この項目の構成では、書き忘れるとすぐに気づけます。

筆者は、マージされた権限を取り除く次の指定で、権限が無い状態を完成状態のコードで再現しました。

XML AndroidManifest.xml（実験用。試した後は元に戻す） 
<uses-permission android:name="android.permission.INTERNET" tools:node="remove" />

起動すると、アプリは落ちずに、一覧の代わりに「予期しないエラーが発生しました」と表示されました（ステップ 2 で作る失敗表示）。ViewModel の catch に一時的にログ出力を入れて見た logcat の抜粋です（実験後は元へ戻しました）。

例外は Ktor の呼び出しの中で投げられるので、呼び出し側の try/catch で捕まります。SecurityException は IOException のサブクラスではないので、「ネットワークに接続できません」ではなく「予期しないエラー」の文言になります。

API の JSON の 1 件分を表す型を作ります。data/TodoDto.kt を新しく作ります（data フォルダも新規）。

Kotlin app/src/main/java/com/handson/android01/data/TodoDto.kt 
package com.handson.android01.data

import com.handson.android01.kotlin.Todo
import kotlinx.serialization.Serializable

// API が返す JSON の 1 件分の形（https://jsonplaceholder.typicode.com/todos の要素）。
// アプリ内で使う Todo とは別の型にして、API の都合（userId など）をアプリの中に持ち込まない。
// @Serializable: Kotlin のシリアライズプラグインが、JSON との変換コードをコンパイル時に生成する
@Serializable
data class TodoDto(
    val userId: Int,
    val id: Int,
    val title: String,
    val completed: Boolean,
)

// API の形からアプリの Todo への変換
fun TodoDto.toTodo(): Todo = Todo(id = id, title = title, done = completed)
  • @Serializable を付けると、Kotlin の serialization プラグイン（08 で導入済み）が、JSON との変換コードをコンパイル時に作ります。
  • TodoDto は API の JSON の形（userId・completed）をそのまま持ちます。アプリの Todo は、画面の都合（done・Parcelable）を持ちます。型を分けておくと、API の都合がアプリの中に広がりません。
  • 2 つの型の変換は、toTodo() の 1 か所だけにします。

取得処理をまとめるクラスを作ります。data/TodoApi.kt を新しく作ります。

Kotlin app/src/main/java/com/handson/android01/data/TodoApi.kt 
package com.handson.android01.data

import com.handson.android01.kotlin.Todo
import io.ktor.client.HttpClient
import io.ktor.client.call.body
import io.ktor.client.engine.HttpClientEngine
import io.ktor.client.plugins.contentnegotiation.ContentNegotiation
import io.ktor.client.request.get
import io.ktor.client.request.parameter
import io.ktor.serialization.kotlinx.json.json
import kotlinx.serialization.json.Json

// 練習用の公開 API（jsonplaceholder）から Todo を取得する。
// HttpClient は引数で受け取る（テストでは、通信しない MockEngine 入りの HttpClient を渡すため）
class TodoApi(
    private val client: HttpClient,
    private val baseUrl: String = "https://jsonplaceholder.typicode.com",
) {
    // 取得して、アプリの Todo に変換して返す。失敗時は例外を投げる（呼び出し側で捕まえる）。
    // suspend 関数だが、通信は Ktor のエンジン（Android）がバックグラウンドのスレッド（Dispatchers.IO）で行うので、メインスレッドから呼んでも画面は固まらない
    suspend fun fetchTodos(limit: Int = 20): List<Todo> {
        val dtos: List<TodoDto> = client.get("$baseUrl/todos") { parameter("_limit", limit) }.body()
        return dtos.map { it.toTodo() }
    }
}

// アプリでも、テストでも同じ設定の HttpClient を作る。違うのはエンジンだけ（アプリ = Android、テスト = MockEngine）
fun createTodoHttpClient(engine: HttpClientEngine): HttpClient = HttpClient(engine) {
    // 2xx 以外のステータスを例外にする。既定は false で、404 や 500 でもそのまま本文のデコードに進んでしまう
    expectSuccess = true
    install(ContentNegotiation) {
        json(
            Json {
                // API の JSON にあって TodoDto に無い項目（今回は無いが、API が項目を足したとき）を無視する
                ignoreUnknownKeys = true
            },
        )
    }
}
  • TodoApi は HttpClient を引数で受け取ります。テストでは、通信しない MockEngine 入りの HttpClient に差し替えます（ステップ 2）。baseUrl も引数にして、テストでリクエスト先を確かめやすくしています。
  • client.get(...).body() は、レスポンスの本文を、受け取る変数の型（List<TodoDto>）にデコードします。デコードは ContentNegotiation プラグインに登録した json(...) が行います。
  • createTodoHttpClient(engine) は、HttpClient の設定を 1 か所にまとめた関数です。アプリは Android エンジン、テストは MockEngine と、エンジンだけを替えます。テストも本番と同じ JSON の設定を通ります。
  • expectSuccess = true は、2xx 以外のステータスを例外にする設定です。既定の false のままだと、404 や 500 でも例外にならず、本文のデコードに進みます。HTTP エラーなのに「JSON の形が違う」という別の失敗に見えてしまいます。実際にどう見えるかは、次の項目（10）でテストを使って確かめます。
  • ignoreUnknownKeys = true は、JSON にあって TodoDto に無い項目を無視する設定です。今の API の 4 項目はすべて TodoDto にあるので、外しても動きます。ただし、外したままだと、API が項目を 1 つ足しただけでデコードに失敗するようになります。

// テスト用の偽のサーバー。MockEngine が、ネットワークに出ずにレスポンスを返す。
// status と todos は、テストの途中で書き換えられる（失敗 → 再試行で成功、を作るため）。
// dispatcher を渡すと、エンジンの処理がそのディスパッチャーで動く。テスト用のディスパッチャーを渡せば、delayMillis が仮想時間になる
class FakeTodoServer(
    var todos: List<Todo>,
    var status: HttpStatusCode = HttpStatusCode.OK,
    private val delayMillis: Long = 0L,
    dispatcher: CoroutineDispatcher? = null,
) {
    private val engine = MockEngine(
        MockEngineConfig().apply {
            this.dispatcher = dispatcher
            addHandler {
                delay(delayMillis)
                val body = Json.encodeToString(todos.map { TodoDto(userId = 1, id = it.id, title = it.title, completed = it.done) })
                // Content-Type を付けないと、ContentNegotiation が JSON として読んでくれない
                respond(body, status, headersOf(HttpHeaders.ContentType, ContentType.Application.Json.toString()))
            }
        },
    )

    val api = TodoApi(createTodoHttpClient(engine))

    val requestCount: Int get() = engine.requestHistory.size
}
  • MockEngine は、ネットワークに出ずに、ハンドラーで決めたレスポンスを返すエンジンです。createTodoHttpClient(engine) に渡すので、本番と同じ設定（JSON・expectSuccess・タイムアウト）を通ります。
  • respond には Content-Type: application/json を付けます。付けないと、ContentNegotiation が JSON として読みません。
  • dispatcher にテスト用のディスパッチャーを渡すと、ハンドラーの delay(delayMillis) が仮想時間になります。07 の「待ち時間を仮想時間で進める」テストが、そのまま書けます。
  • status と todos は var で、テストの途中で書き換えられます。requestCount は、偽のサーバーが受けたリクエストの回数です。どちらも、次の項目（10）で失敗と再試行をテストするときに使います。

この項目で扱わなかったこと

MockEngine を使った新しいテストは、次の項目（10）で扱います。TodoApi の成功・HTTP エラー・壊れた JSON・タイムアウト、ViewModel の失敗と再試行、失敗表示の UI テストです。expectSuccess を外したときの見え方も、10 でテストを使って確かめます。

つまずきポイント

⚠️

一覧が出ずに「予期しないエラーが発生しました」と表示される

マージ後のマニフェストに INTERNET 権限が無いと、SecurityException になり、この文言が出ます。AndroidManifest.xml に <uses-permission android:name="android.permission.INTERNET" /> があるか確かめます。

⚠️

Serializer for type argument 'TodoDto' is not found で取得に失敗する

TodoDto に @Serializable が付いていません。コンパイルでは気づけないので、DTO を足したら必ず付けます。

⚠️

Encountered an unknown key で取得に失敗する

JSON に、DTO に無い項目があります。Json { ignoreUnknownKeys = true } にします。

⚠️

Cleartext HTTP traffic to ... not permitted で取得に失敗する

URL が http:// になっています。https:// に直します。

⚠️

Activity を起動する UI テストに、API の実データ（Delectus Aut Autem）が出て失敗する

FakeTodoApiRule が無いか、RuleChain の内側に置いています。RuleChain.outerRule(FakeTodoApiRule()).around(composeTestRule) のように、Activity を起動するルールより外側に置きます。

⚠️

ViewModel の単体テストで、応答が届く前にアサートしてしまう

FakeTodoServer に dispatcher を渡していません。渡さないと、MockEngine は別のスレッドで動き、待ち時間も実時間になります。setMain したものと同じテスト用ディスパッチャーを渡します。

⚠️

まとめ

Ktor Client（Android エンジン）と ContentNegotiation で、Web API から JSON を取得しました。JSON は @Serializable な TodoDto にデコードしてから、アプリの Todo に変換しました。 ViewModel では、例外の種類から画面の文言を作りました。CancellationException は投げ直し、失敗の状態は SavedStateHandle に保存しません。失敗中はエラーの文言と「再試行」を出します。 HttpClient は外から渡す形なので、MockEngine 入りのものと差し替えられます。この仕組みで、既存のテストを偽のサーバーへつなぎ替え、ネットワークへ出ない形にしました。機内モードで失敗表示と再試行を確かめ、release の APK でも、keep ルールを足さずに動くことを確かめました。

次の項目（10: MockEngine でネットワークのテスト）では、この偽のサーバーを使って、API・ViewModel の失敗と再試行・失敗表示のテストを、ネットワークに出ない形で書きます。
