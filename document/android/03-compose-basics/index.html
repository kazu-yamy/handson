概要

02 では、テンプレートの Greeting の中で Text を並べて Todo を表示しました。 この項目では、Jetpack Compose の基本である Composable 関数を 1 つずつ部品として切り出します。部品を組み合わせて、TopAppBar・カード・ボタンのある Todo 一覧画面を作ります。 部品ごとに @Preview を用意し、最後に Compose UI テストで表示内容を確かめます。

宣言的 UI とは

従来の View システムでは、XML でレイアウトを定義し、findViewById などで取り出した View に対して setText のように「どう変えるか」を命令して画面を更新していました。 Compose では、「データがこの値なら UI はこうなる」を Kotlin の関数で宣言します。データが変わると、Compose がその関数を呼び直して UI を作り直します。これを再コンポーズ（recomposition）と呼びます。 画面の更新手順を自分で書く代わりに、「入力から UI を作る関数」を書くのが宣言的 UI の考え方です。

Composable 関数の 3 つの慣習

この項目で作る部品は、すべて次の 3 つに従います。ステップ 1 で実際に書いて確かめます。

慣習内容
@Composable を付けるCompose コンパイラが UI を宣言する関数として扱います。関数名は名詞の PascalCase（Greeting、TodoRow）にします
値を返さないView オブジェクトなどを返さず、戻り値は Unit です。関数の中で Text などを呼ぶこと自体が UI の宣言になります
modifier を最初の省略可能引数にするmodifier: Modifier = Modifier を、必須の引数の後・ほかの省略可能引数の前に置きます。呼び出し側が外から余白や大きさを足せるようにするためです

この項目の画面は状態を持ちません。同じデータを渡せば、いつも同じ UI が描かれます。チェックボックスを押して完了を切り替えるといった、状態を変える操作は 04 の remember / mutableStateOf で扱います。

Composable 関数の基本と @Preview

最初の Composable 関数として、名前を受け取って挨拶を表示する Greeting を部品に切り出します。ui/components/Greeting.kt を作ります。

Kotlin app/src/main/java/com/handson/android01/ui/components/Greeting.kt 
package com.handson.android01.ui.components

import androidx.compose.material3.Text
import androidx.compose.runtime.Composable
import androidx.compose.ui.Modifier
import androidx.compose.ui.tooling.preview.Preview
import com.handson.android01.ui.theme.HandsonAndroid01Theme

// Composable 関数: UI を「宣言」する関数。値（View オブジェクトなど）を返さず、Unit を返す。
// 命名は PascalCase（先頭大文字）にする。Compose コンパイラがこの関数を Composable として扱う
@Composable
fun Greeting(name: String, modifier: Modifier = Modifier) {
    // modifier は最初の省略可能な引数にする（Compose の慣習）。呼び出し側が外から見た目を足せるようにする
    Text(
        text = "Hello, $name!",
        modifier = modifier,
    )
}

// Preview は引数を取らない Composable にする（@PreviewParameter を除く。ステップ 5 で扱う）
@Preview(showBackground = true)
@Composable
private fun GreetingPreview() {
    HandsonAndroid01Theme {
        Greeting(name = "Android")
    }
}
  • @Composable: この関数が UI を宣言する Composable 関数であることを示します。Composable 関数は、ほかの Composable 関数（または setContent などの Composable を受け取る場所）からしか呼べません。
  • fun Greeting(...) に戻り値の型はありません（Unit）。Text(...) を呼ぶことが「ここに文字を表示する」という宣言になります。
  • modifier: Modifier = Modifier: 必須の name の後、最初の省略可能な引数です。受け取った modifier は、関数の一番外側の要素（ここでは Text）に渡します。
  • @Preview(showBackground = true): Android Studio の Preview パネルに描く関数に付けます。showBackground = true で白い背景が付きます。Preview の中でも本番と同じ見た目になるよう、テーマ（HandsonAndroid01Theme）で囲みます。
  • private fun GreetingPreview(): Preview 用の関数は引数を取らず、private にします。理由はステップ 5 で説明します。

import androidx.compose.ui.test.assertIsDisplayed
import androidx.compose.ui.test.junit4.v2.createComposeRule
import androidx.compose.ui.test.onNodeWithText
import androidx.test.ext.junit.runners.AndroidJUnit4
import com.handson.android01.ui.theme.HandsonAndroid01Theme
import org.junit.Rule
import org.junit.Test
import org.junit.runner.RunWith

@RunWith(AndroidJUnit4::class)
class GreetingTest {

    // createComposeRule(): Activity を起動せず、テスト対象の Composable だけを setContent で描画する
    @get:Rule
    val composeTestRule = createComposeRule()

    @Test
    fun greeting_showsName() {
        composeTestRule.setContent {
            HandsonAndroid01Theme {
                Greeting(name = "Compose")
            }
        }

        composeTestRule.onNodeWithText("Hello, Compose!").assertIsDisplayed()
    }

    @Test
    fun greeting_showsDifferentNameWhenCalledWithAnotherArgument() {
        composeTestRule.setContent {
            HandsonAndroid01Theme {
                Greeting(name = "Kotlin")
            }
        }

        composeTestRule.onNodeWithText("Hello, Kotlin!").assertIsDisplayed()
    }
}
  • createComposeRule(): Activity を起動せずに、テスト対象の Composable だけを描画するためのルールです。import は androidx.compose.ui.test.junit4.v2 のものを使います（下のコールアウトを参照）。
  • composeTestRule.setContent { ... }: テストの中で描画する UI を指定します。
  • onNodeWithText("Hello, Compose!"): 表示されている文字が完全一致するノード（UI の要素）を探します。assertIsDisplayed() で画面に表示されていることを確かめます。

Column / Row / Box と Modifier

Compose では、要素の並べ方をレイアウト用の Composable で指定します。この項目では次の 3 つを使います。

Composable並べ方この項目で使う場所
Column子要素を上から下に並べる（02 の Greeting で使用）ステップ 3 の画面全体・カードの中
Row子要素を左から右に並べるTodoRow（チェックボックス・タイトル・状態）
Box子要素を重ねて置くCountBadge（アイコンの上に件数のバッジ）

まず、Todo 1 件を 1 行で表示する TodoRow を作ります。02 で作った Todo と拡張関数 toTitleCase() を使います。

Kotlin app/src/main/java/com/handson/android01/ui/components/TodoRow.kt 
package com.handson.android01.ui.components

import androidx.compose.foundation.layout.Arrangement
import androidx.compose.foundation.layout.Row
import androidx.compose.foundation.layout.fillMaxWidth
import androidx.compose.foundation.layout.padding
import androidx.compose.material3.Checkbox
import androidx.compose.material3.MaterialTheme
import androidx.compose.material3.Text
import androidx.compose.runtime.Composable
import androidx.compose.ui.Alignment
import androidx.compose.ui.Modifier
import androidx.compose.ui.platform.testTag
import androidx.compose.ui.tooling.preview.Preview
import androidx.compose.ui.unit.dp
import com.handson.android01.kotlin.Todo
import com.handson.android01.kotlin.toTitleCase
import com.handson.android01.ui.theme.HandsonAndroid01Theme

@Composable
fun TodoRow(todo: Todo, modifier: Modifier = Modifier) {
    // Row: 子要素を左から右に並べる。verticalAlignment で高さ方向の揃え位置を決める
    Row(
        // testTag は padding より前に書く。後ろに書くと、タグの付いたノードが余白の内側だけになる
        modifier = modifier
            .fillMaxWidth()
            .testTag("todo_row")
            .padding(horizontal = 16.dp, vertical = 8.dp),
        horizontalArrangement = Arrangement.spacedBy(8.dp),
        verticalAlignment = Alignment.CenterVertically,
    ) {
        // onCheckedChange = null にすると表示専用になる（タップしても状態が変わらない）
        Checkbox(checked = todo.done, onCheckedChange = null)
        // weight(1f): 残りの横幅をすべて使う。weight を持つ子が複数あれば比率で分ける
        Text(
            text = todo.title.toTitleCase(),
            modifier = Modifier.weight(1f),
            style = MaterialTheme.typography.bodyLarge,
        )
        Text(
            text = if (todo.done) "完了" else "未完了",
            style = MaterialTheme.typography.labelMedium,
        )
    }
}

@Preview(showBackground = true)
@Composable
private fun TodoRowPreview() {
    HandsonAndroid01Theme {
        TodoRow(todo = Todo(1, "learn kotlin basics", done = true))
    }
}
  • Row(horizontalArrangement = Arrangement.spacedBy(8.dp), verticalAlignment = Alignment.CenterVertically): 子要素の間を 8dp ずつ空け、高さ方向は中央に揃えます。
  • modifier.fillMaxWidth().testTag("todo_row").padding(...): Modifier はメソッドチェーンで重ねます。fillMaxWidth() で親の幅いっぱいに広げ、padding で内側に余白を付けます。testTag は UI テストからこの行を探すための目印です。
  • Checkbox(checked = todo.done, onCheckedChange = null): onCheckedChange に null を渡すと、表示専用のチェックボックスになります。
  • Modifier.weight(1f): Row の中だけで使える指定で、ほかの子が使った残りの横幅をすべて使います。タイトルが伸び、状態の文字は右端に寄ります。

Modifier は書いた順に左から適用されます。順序を入れ替えると結果が変わることを、2 つの Preview を並べて確かめます。ModifierOrderPreviews.kt を作ります。

Kotlin app/src/main/java/com/handson/android01/ui/components/ModifierOrderPreviews.kt 
package com.handson.android01.ui.components

import androidx.compose.foundation.background
import androidx.compose.foundation.layout.Box
import androidx.compose.foundation.layout.padding
import androidx.compose.material3.Text
import androidx.compose.runtime.Composable
import androidx.compose.ui.Modifier
import androidx.compose.ui.graphics.Color
import androidx.compose.ui.tooling.preview.Preview
import androidx.compose.ui.unit.dp

// Modifier は左から順に外側から包んでいく。順序を変えると見た目が変わる
// 1 つ目: padding が先 → 余白の外側に背景色が付かない（背景は文字のまわりだけ）
@Preview(name = "padding → background", showBackground = true)
@Composable
private fun PaddingThenBackgroundPreview() {
    Box(
        modifier = Modifier
            .padding(24.dp)
            .background(Color(0xFFFFE082)),
    ) {
        Text("A")
    }
}

// 2 つ目: background が先 → 余白の部分まで背景色が付く
@Preview(name = "background → padding", showBackground = true)
@Composable
private fun BackgroundThenPaddingPreview() {
    Box(
        modifier = Modifier
            .background(Color(0xFFFFE082))
            .padding(24.dp),
    ) {
        Text("A")
    }
}

どちらも padding(24.dp) と background(...) を 1 つずつ使っていて、違うのは順序だけです。padding が先だと、余白を空けた内側にだけ背景色が付きます。background が先だと、余白を含めた全体に背景色が付きます。@Preview の name は、1 つのファイルにある複数の Preview を見分けるための名前です。

次に、Box で要素を重ねる例として、アイコンの右上に件数のバッジを載せる CountBadge を作ります。

Kotlin app/src/main/java/com/handson/android01/ui/components/CountBadge.kt 
package com.handson.android01.ui.components

import androidx.compose.foundation.background
import androidx.compose.foundation.layout.Box
import androidx.compose.foundation.layout.size
import androidx.compose.foundation.shape.CircleShape
import androidx.compose.material.icons.Icons
import androidx.compose.material.icons.filled.Check
import androidx.compose.material3.Icon
import androidx.compose.material3.MaterialTheme
import androidx.compose.material3.Text
import androidx.compose.runtime.Composable
import androidx.compose.ui.Alignment
import androidx.compose.ui.Modifier
import androidx.compose.ui.tooling.preview.Preview
import androidx.compose.ui.unit.dp
import com.handson.android01.ui.theme.HandsonAndroid01Theme

// Box: 子要素を重ねて置く。後に書いた子ほど手前に描かれる
// contentAlignment と Modifier.align で、重ねた子の位置を指定する
@Composable
fun CountBadge(count: Int, modifier: Modifier = Modifier) {
    Box(modifier = modifier.size(48.dp)) {
        Icon(
            imageVector = Icons.Default.Check,
            contentDescription = null,
            modifier = Modifier
                .align(Alignment.Center)
                .size(32.dp),
        )
        Box(
            modifier = Modifier
                .align(Alignment.TopEnd)
                .size(20.dp)
                .background(MaterialTheme.colorScheme.error, CircleShape),
            contentAlignment = Alignment.Center,
        ) {
            Text(
                text = count.toString(),
                color = MaterialTheme.colorScheme.onError,
                style = MaterialTheme.typography.labelSmall,
            )
        }
    }
}

@Preview(showBackground = true)
@Composable
private fun CountBadgePreview() {
    HandsonAndroid01Theme {
        CountBadge(count = 2)
    }

private val DarkColorScheme = darkColorScheme(
    primary = Purple80,
    secondary = PurpleGrey80,
    tertiary = Pink80
)

private val LightColorScheme = lightColorScheme(
    primary = Purple40,
    secondary = PurpleGrey40,

@Composable
fun HandsonAndroid01Theme(
    darkTheme: Boolean = isSystemInDarkTheme(),
    // Dynamic color is available on Android 12+
    dynamicColor: Boolean = true,
    content: @Composable () -> Unit
) {
    val colorScheme = when {
        dynamicColor && Build.VERSION.SDK_INT >= Build.VERSION_CODES.S -> {
            val context = LocalContext.current
            if (darkTheme) dynamicDarkColorScheme(context) else dynamicLightColorScheme(context)
        }

        darkTheme -> DarkColorScheme
        else -> LightColorScheme
    }

    MaterialTheme(
        colorScheme = colorScheme,
        typography = Typography,
        content = content
    )
}
  • HandsonAndroid01Theme 自体も Composable 関数です。最後の引数 content に Composable のラムダを受け取り、MaterialTheme で囲んで描きます。HandsonAndroid01Theme { ... } と書けるのは、02 で学んだ末尾ラムダの書き方です。
  • darkTheme: Boolean = isSystemInDarkTheme(): 端末がダークテーマかどうかを既定値にしています。
  • dynamicColor: Boolean = true: Android 12（API 31、Build.VERSION_CODES.S）以上では、壁紙から作られる色（dynamicLightColorScheme / dynamicDarkColorScheme）を使います。このプロジェクトの minSdk は 26 なので、API 26〜30 の端末では固定の LightColorScheme / DarkColorScheme になります。
  • typography = Typography: Type.kt で定義した文字のスタイルです。テンプレートの Type.kt は bodyLarge だけを上書きしていて、titleLarge や labelMedium などは Material3 の既定値のままです。

@PreviewParameter + PreviewParameterProvidervalues の要素ごとに Preview を 1 つずつ描きます。ここではデモデータ・空のリスト・12 件のリストの 3 通りです。引数を取る Preview 関数は、この指定のときだけ使えます
fontScale = 1.5f端末の文字サイズを 1.5 倍にした状態で描きます。大きな文字で崩れないかを確かめます
device = Devices.TABLET定義済みの端末（ここではタブレット）の画面サイズで描きます
uiMode = Configuration.UI_MODE_NIGHT_YESステップ 4 と同じく、ダークテーマで描きます
@PreviewLightDarkマルチプレビューアノテーションの 1 つで、ライトとダークの 2 つを一度に作ります
@PreviewFontScale複数の文字サイズの Preview をまとめて作ります
@PreviewScreenSizes複数の画面サイズの Preview をまとめて作ります

マルチプレビューアノテーションは、@Preview を複数組み合わせたアノテーションです。1 つ付けるだけで、決まった条件の Preview が複数できます。@PreviewLightDark / @PreviewFontScale / @PreviewScreenSizes は、この項目で使う ui-tooling-preview 1.12.1 に含まれています。

Preview 関数をすべて private にしているのは、Preview は Android Studio で描くためだけの関数で、アプリのコードから呼ばれては困るからです。これは慣習で、公開のままでもビルドは通ります。ただし private にしてもコードからは消えません。このプロジェクトの release ビルドは isMinifyEnabled = false（テンプレートの設定）なので、R8 による縮小が行われず、Preview 関数も APK に含まれます。

演習

以下のチェックリストを使って、このレッスンの内容を振り返りましょう。

つまずきポイント

⚠️

Modifier は順序で結果が変わる

Modifier は書いた順に適用されます。padding と background の順序で背景色の範囲が変わります（ステップ 2 の ModifierOrderPreviews.kt）。また、testTag を padding の後ろに書くとタグの範囲が余白の内側だけになります（幅のテストが 268dp で失敗）。どの範囲に効かせたいかを考えて並べます。

⚠️

TopAppBar には @OptIn(ExperimentalMaterial3Api::class) が必要

Material3 1.4.0 の TopAppBar は実験的 API です。@OptIn を付けないと This material API is experimental and is likely to change or to be removed in the future. でビルドが失敗します。@OptIn は、TopAppBar を呼んでいる関数（ここでは TodoListScreen）に付けます。

⚠️

Icons.Default.* には material-icons-core が必要

material3 を追加しただけでは Icons を参照できず、Unresolved reference 'Icons' になります。androidx.compose.material:material-icons-core を依存に追加します。バージョンは BOM が決めるので、Version Catalog には version を書きません。

⚠️

@Preview は引数を取る関数に付けられない

@Preview を付ける関数は、引数を取らないようにします（@PreviewParameter を付けた引数を除く）。データを変えて描きたいときは、ステップ 5 のように PreviewParameterProvider を用意し、引数に @PreviewParameter を付けます。

⚠️

UI テストはエミュレータが起動していないと実行されない

エミュレータが起動していない状態で connectedDebugAndroidTest を実行すると、テストは No connected devices! で失敗します。テストが本当にエミュレータで実行されたか分からないときは、adb devices でエミュレータが接続されていることを確かめてから、--rerun を付けて実行し直します。

💡

Preview 関数は private にする

Preview 関数はアプリのコードから呼ぶものではないので private にします。慣習として private にします（本番コードに Preview が含まれないようにする意図）。private にしても関数はコードに残り、R8 で縮小しない設定（このプロジェクトの isMinifyEnabled = false）では release の APK にも含まれます。

💡

Checkbox の onCheckedChange = null は表示専用

onCheckedChange に null を渡すと、タップしてもチェックの状態は変わりません。この項目の画面は状態を持たないため、表示専用にしています。タップで切り替えられるようにするのは 04 です。

💡

createComposeRule と createAndroidComposeRule の使い分け

createComposeRule() は Activity を起動せず、setContent で渡した部品や画面だけを描きます。データを差し替えて部品を単体で確かめるのに向いています。createAndroidComposeRule<MainActivity>() は実際の Activity を起動し、アプリ本来の画面を確かめます。どちらも、v2 の付かない旧パッケージ（androidx.compose.ui.test.junit4）のものは非推奨です。

ℹ️

再コンポーズと、状態を持たない画面

Composable 関数は、受け取る値や読んでいる状態が変わると呼び直されます（再コンポーズ）。この項目の画面は状態を持たないので、同じ todos を渡せばいつも同じ UI が描かれます。「追加」を押したときの処理も onAddClick として親から受け取り、状態の変更は親に任せています。状態を持たせて再コンポーズを実際に起こすのは 04 で扱います。
