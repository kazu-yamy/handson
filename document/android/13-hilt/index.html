🎯 このレッスンで学ぶこと

  • Hilt を Gradle に入れ、@HiltAndroidApp と @AndroidEntryPoint でアプリと Activity を Hilt につなげられる
  • 手書きの AppContainer にあった部品の作り方を、@Module / @Provides と @Inject constructor / @Singleton で書き直せる

概要

09 から、アプリ全体で使う部品（DB・API・Repository）は AppContainer という object で手書きして組み立ててきました。ViewModel は、引数なしの 2 次コンストラクタから AppContainer の Repository を受け取っています。テストでは、AppContainer の差し替え口（todoRepositoryOverride など）を FakeTodoApiRule が偽物に替えていました。

この項目では、この組み立てを Hilt に任せます。Hilt は依存性注入（DI）のライブラリです。部品の作り方を注釈で書いておくと、組み立てるコードを Hilt がビルドのときに生成します。Hilt の本体は com.google.dagger のライブラリで、生成されるコードも Dagger のコード生成（dagger.internal.codegen）が作ります。

手書きの DI と Hilt の違い

12 まで（AppContainer）この項目（Hilt）
部品の作り方を書く場所AppContainer の lazy他人の型（Room・Ktor・DataStore）は module の @Provides。自分の型は @Inject constructor
アプリで 1 つにするobject の lazy@Singleton
Context の受け渡しTodoApplication.onCreate で AppContainer.init(this)@ApplicationContext を付けた引数に Hilt が渡す

UI テストの差し替えFakeTodoApiRule が AppContainer の差し替え口を書き換える偽の module（FakeDataModule）を @TestInstallIn で本物の module と入れ替える
組み立てのコード自分で書くHilt がビルドのときに生成する。部品が足りなければビルドが失敗する

Hilt がビルドのときに生成するものは、たとえば次のとおりです（ステップ 1・2・4 で実物の場所を確かめます）。

  • @Provides ごと、@Inject constructor ごとの Factory（DataModule_ProvideTodoApiFactory・TodoRepository_Factory）。中身は、引数を受け取って作り方の関数やコンストラクタを呼ぶだけのコードです。
  • @AndroidEntryPoint の Activity の基底クラス（Hilt_MainActivity）と、@HiltAndroidApp のアプリの基底クラス（Hilt_TodoApplication）。
  • アプリ全体の部品の置き場所（コンポーネント）の定義（TodoApplication_HiltComponents）と、@HiltViewModel の ViewModel を登録するコード（TodoListViewModel_HiltModules）。

部品の作り方を module に書く

AppContainer の lazy に書いていた部品の作り方を、Hilt に教えます。このステップの終わりでも、アプリはまだ AppContainer の部品を使います。Hilt のほうの作り方は、ステップ 4 で使い始めます。

他人の型の作り方を module に書く

app/src/main/java/com/handson/android01/di/DataModule.kt を作ります。

Kotlin app/src/main/java/com/handson/android01/di/DataModule.kt 
package com.handson.android01.di

import android.content.Context
import androidx.datastore.core.DataStore
import androidx.datastore.preferences.core.Preferences
import androidx.datastore.preferences.preferencesDataStore
import androidx.room3.Room
import androidx.sqlite.driver.AndroidSQLiteDriver
import com.handson.android01.data.AppDatabase
import com.handson.android01.data.TodoApi
import com.handson.android01.data.TodoDao
import com.handson.android01.data.createTodoHttpClient
import dagger.Module
import dagger.Provides
import dagger.hilt.InstallIn
import dagger.hilt.android.qualifiers.ApplicationContext
import dagger.hilt.components.SingletonComponent
import io.ktor.client.engine.android.Android
import kotlinx.coroutines.Dispatchers
import javax.inject.Singleton

// DataStore は、ファイル（datastore/settings.preferences_pb）ごとに、アプリで 1 つだけ作る。
// preferencesDataStore のプロパティ委譲は、トップレベルに 1 回だけ書く（クラスの中に書くと、インスタンスのたびに別の DataStore が作られる）。
// AppContainer も使うので private にしない（internal）
internal val Context.settingsDataStore: DataStore<Preferences> by preferencesDataStore(name = "settings")

// 自分で `@Inject constructor` を書けない、または組み立てが要る型（Room・Ktor・DataStore は他人の型。TodoApi は HttpClient を組み立てて渡す）の作り方を Hilt に教える module。
// SingletonComponent に入れるので、ここで作る部品はアプリ全体で使える。AppContainer の lazy と 1 対 1 で対応する
@Module
@InstallIn(SingletonComponent::class)
object DataModule {

    // @Singleton は「コンポーネントに 1 つ」＝アプリで 1 つ。DB は何度も作らず、使い回す。
    // Context は Hilt が用意している（@ApplicationContext を付けると Application の Context が渡される）
    @Provides
    @Singleton
    fun provideDatabase(@ApplicationContext context: Context): AppDatabase =
        Room.databaseBuilder<AppDatabase>(context, "todos.db")
            // クエリを実行するスレッド。ここでは IO 用のスレッドプールを指定する
            .setQueryCoroutineContext(Dispatchers.IO)
            // SQLite を動かすドライバー。省略しても既定でこのドライバーが使われるが、何を使っているか分かるように明示する
            .setDriver(AndroidSQLiteDriver())
            .build()

    // DAO は DB が持っているので、scope は付けない（呼ばれるたびに database.todoDao() を返すだけ）。
    // 引数の AppDatabase は、上の provideDatabase の結果を Hilt が渡す
    @Provides
    fun provideTodoDao(database: AppDatabase): TodoDao = database.todoDao()

    // HttpClient は接続を使い回すので、アプリで 1 つにする
    @Provides
    @Singleton
    fun provideTodoApi(): TodoApi = TodoApi(createTodoHttpClient(Android.create()))

    // 12 のトップレベルの委譲を返すだけ。「ファイルごとに 1 つ」の保証は、委譲のほうが持っている
    @Provides
    @Singleton
    fun provideSettingsDataStore(@ApplicationContext context: Context): DataStore<Preferences> = context.settingsDataStore
}
  • @Module の付いた object が、作り方を並べる場所（module）です。@InstallIn(SingletonComponent::class) で、アプリ全体のコンポーネントに入れます。
  • @Provides の付いた関数が、1 つの型の作り方です。何を提供するかは戻り値の型で決まります。provideTodoDao は TodoDao を返すので、TodoDao を欲しがる引数に渡されます。
  • 関数の引数も Hilt が用意します。provideTodoDao(database: AppDatabase) の database には、provideDatabase の結果が渡されます。
  • @Singleton は「コンポーネントに 1 つ」です。アプリ全体のコンポーネントなので、アプリで 1 つになります。DB・TodoApi（中の HttpClient）・DataStore は使い回すので付けます。TodoDao は DB が持っているので付けません。
  • Context は、@ApplicationContext を付けた引数で受け取ります。Application の Context が渡されます。この注釈が無いと、Context は渡されません（Context を返す @Provides は無いため）。
  • 12 で AppContainer.kt のトップレベルに書いた preferencesDataStore の委譲は、このファイルに移しました。AppContainer からも使うので、このステップでは internal にしています。
